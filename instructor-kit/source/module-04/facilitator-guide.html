Session 4: Filtering, Sorting and Limiting

How to teach the fourth session of MySQL Foundations. Learners filter rows precisely (comparisons, AND/OR with parentheses, IN, BETWEEN, LIKE and the rules for NULL), sort and page results so they come out the same every time, and close Modules 1 and 2 with Checkpoint 1, a scored 30-minute task: build, fill and read a small database from nothing.

How to Use This Guide

  • Two lessons in shorter blocks (65 and 55 minutes) because the 30 minutes before the wrap-up are Checkpoint 1, a scored open-notes task on Modules 1 and 2 (Lessons 1.1 to 2.3).
  • Every SQL block below was run to produce the output under it, on MySQL 9.7.2, on the Module 3 data (Lesson 3.1's setup script = labs/_states/flat.sql). Ask for a row count before every query: counting first is how silent filter mistakes get caught.

Lesson Plans

3.1

WHERE Clauses, Operators & Filtering

65 min
Objectives (from the lesson page)
  • Filter rows by numbers, text and dates with the comparison operators (=, !=, <, >, <=, >=)
  • Combine conditions with AND, OR and NOT, and use parentheses to say exactly what you mean
  • Match lists, ranges and text patterns with IN, BETWEEN and LIKE
  • Find missing values with IS NULL and explain why = NULL finds nothing
  • Spot the silent filtering mistakes (missing NULL rows, AND/OR mix-ups) and fix error 1054
  • Save a set of reusable searches in a .sql script
Timing in the room
10mFrame: a test on every row; true, false, unknown
25mLive demo: comparisons to precedence, two mistakes
20mGuided lab: staff_requests_starter.sql in pairs
10mStart the lesson project: saved_searches.sql, Steps 1 to 3
Mental model to say

Draw the lesson's diagram: each row of books → the test → kept (true) or dropped (false, or unknown). "WHERE is a test MySQL runs on every row. The third answer, unknown, appears whenever a NULL is involved, and unknown is dropped like false."

Then the counting habit: "Before you run a filter, say how many rows you expect. Three of today's mistakes give no error at all; the count is how you catch them."

Then precedence as arithmetic: "Multiplication before addition; AND before OR. When you mix them, type the parentheses."

Live demo (you type, they follow)

Inside bookstore with the Module 3 data. Ask for the row count before each query.

  1. WHERE as a test on every row (2m). "Five of ten pass. The ORDER BY makes the result read the same everywhere: Lesson 3.2." 
    SELECT title, price
FROM books
WHERE price < 10
ORDER BY price, title;
    +------------------------+-------+
| title                  | price |
+------------------------+-------+
| Pride and Prejudice    |  7.99 |
| The Catcher in the Rye |  8.99 |
| The Great Gatsby       |  8.99 |
| Brave New World        |  9.49 |
| 1984                   |  9.99 |
+------------------------+-------+
  2. See the test itself (2m). "A condition is a value: 1, 0 or NULL. Put it in the SELECT list to debug a WHERE." 
    SELECT title, price, price < 10 AS passes
FROM books
ORDER BY id
LIMIT 4;
    +-----------------------+-------+--------+
| title                 | price | passes |
+-----------------------+-------+--------+
| Dune                  | 14.99 |      0 |
| 1984                  |  9.99 |      1 |
| To Kill a Mockingbird | 11.99 |      0 |
| The Great Gatsby      |  8.99 |      1 |
+-----------------------+-------+--------+
  3. Text ignores case (1m). "The collation is _ci: case-insensitive." 
    SELECT title
FROM books
WHERE author = 'j.r.r. tolkien'
ORDER BY title;
    +-------------------+
| title             |
+-------------------+
| Lord of the Rings |
| The Hobbit        |
+-------------------+
  4. Not equal, and two missing customers (2m). "Eight customers, two in New York. Count the rows." 
    SELECT first_name, city
FROM customers
WHERE city != 'New York'
ORDER BY first_name;

| first_name | city        |
+------------+-------------+
| Bob        | Chicago     |
| Carol      | Los Angeles |
| Dave       | Houston     |
| Grace      | Chicago     |
+------------+-------------+
    Four. Eve and Hank are gone: an unknown city is not "different from New York". Leave the question open until Step 12.
  5. AND narrows (1m). "Cheap AND long." 
    SELECT title, price, pages
FROM books
WHERE price < 10 AND pages > 300
ORDER BY price;

  6. OR widens (1m). "Cheap OR short. Gatsby passes both: does it appear twice?" 
    SELECT title, price, pages
FROM books
WHERE price < 9 OR pages < 200
ORDER BY title;

| title                  | price | pages |
+------------------------+-------+-------+
| Fahrenheit 451         | 10.49 |   158 |

| The Catcher in the Rye |  8.99 |   234 |
| The Great Gatsby       |  8.99 |   180 |
+------------------------+-------+-------+
  7. IN: a list (1m). "Three ORs on one column, said once." 
    SELECT title, author
FROM books
WHERE author IN ('George Orwell', 'Aldous Huxley', 'Ray Bradbury')
ORDER BY author;
    +-----------------+---------------+
| title           | author        |
+-----------------+---------------+
| Brave New World | Aldous Huxley |
| 1984            | George Orwell |
| Fahrenheit 451  | Ray Bradbury  |
+-----------------+---------------+
  8. BETWEEN includes both ends (1m). "Are 9.49 and 10.99 in?" 
    SELECT title, price
FROM books
WHERE price BETWEEN 9.49 AND 10.99
ORDER BY price;
    +-----------------+-------+
| title           | price |
+-----------------+-------+
| Brave New World |  9.49 |
| 1984            |  9.99 |
| Fahrenheit 451  | 10.49 |
| The Hobbit      | 10.99 |
+-----------------+-------+
  9. A month of timestamps (2m). "created_at has a time. Half-open: on or after the first, before the first of next month." 
    SELECT first_name, created_at
FROM customers
WHERE created_at >= '2026-01-01'
  AND created_at <  '2026-02-01'

  10. LIKE: contains (2m). "% is any number of characters. Lowercase 'the' finds The too." 
    SELECT title

    NULL = NULL   AS equals,
    NULL != 'x'   AS not_equals,

| equals | not_equals | is_null |

+--------+------------+---------+

    SELECT title, author, price
FROM books
WHERE author = 'J.R.R. Tolkien' OR author = 'George Orwell' AND price < 12
ORDER BY price;

| title             | author         | price |
+-------------------+----------------+-------+
| 1984              | George Orwell  |  9.99 |
| The Hobbit        | J.R.R. Tolkien | 10.99 |
| Lord of the Rings | J.R.R. Tolkien | 15.99 |
+-------------------+----------------+-------+
    Lord of the Rings at 15.99 is in it: MySQL read A OR (B AND C).
  14. Parentheses say what you meant (1m). 
    SELECT title, author, price
FROM books
WHERE (author = 'J.R.R. Tolkien' OR author = 'George Orwell')
  AND price < 12
ORDER BY price;
    +------------+----------------+-------+
| title      | author         | price |
+------------+----------------+-------+
| 1984       | George Orwell  |  9.99 |
| The Hobbit | J.R.R. Tolkien | 10.99 |
+------------+----------------+-------+
  15. Two mistakes (2m). "Text without quotes; and = NULL." 
    SELECT title FROM books WHERE author = Tolkien;
SELECT first_name, city
FROM customers
WHERE city = NULL;
    ERROR 1054 (42S22): Unknown column 'Tolkien' in 'where clause'
Empty set
    The second is silent: no error, no rows. IS NULL.
Three mistakes to expect, and how to coach each
  • = NULL or != that drops the NULL rows. Coach: "What happens to Eve and Hank in this test?" Show the condition as a column.
  • AND/OR without parentheses. Coach: "Read it the way MySQL does: AND first. Where would you put the brackets?"
  • Text without quotes (1054) and wildcards with = (silent). Coach: "Quotes for text; % only means something to LIKE."

Checks for understanding

Ask these out loud:

  • NULL = NULL: true, false or unknown? Answer: unknown (NULL).
  • BETWEEN 9.49 AND 10.99: are the ends in? Answer: yes, both.
  • Why a half-open range for created_at? Answer: BETWEEN '...-01' AND '...-31' stops at midnight of the 31st and misses that day.
  • 'The%' or 'The %'? Answer: the space keeps out words like Theory.

3.2

Sorting & Limiting Results

55 min
Objectives (from the lesson page)
  • Sort results with ORDER BY on one or more columns or expressions, each ascending or descending
  • Predict where NULL values land in a sort and move them to the end
  • Take the top N rows with LIMIT, and add a tie-breaker so the result is always the same
  • Split a result into pages with LIMIT ... OFFSET, and explain when keyset pagination is better
  • Read and fix the errors MySQL raises for misplaced or malformed ORDER BY and LIMIT clauses

Mental model to say

"A table is a set of rows, not a list. Without ORDER BY you get whatever is cheapest for the server, which usually looks right until one day it is not." Then the phone book: sorted by last name, and by first name only among people with the same last name.

Then the run order on the board: FROM → WHERE → SELECT → ORDER BY → LIMIT. "That is why an alias works in ORDER BY, and why LIMIT cuts the sorted result." And the rule: every ORDER BY that feeds a LIMIT ends with a unique column.

Three mistakes to expect, and how to coach each
  • ORDER BY a, b DESC expecting both descending. Coach: "DESC belongs to the column before it."
  • A top N with ties at the cut. Coach: "Could two rows have the same value here? Then add a unique column."
  • Clauses out of order or a formula in LIMIT (1064). Coach with the clause order on the board; compute the offset first.

Closing

Exit ticket (3 questions, no notes, 4 minutes)

After the checkpoint, keep it short: three questions on the slide, sticky notes on the way out.

  1. Why does WHERE city != 'Chicago' skip Eve and Hank, and how do you include them? Answer: Their city is NULL, so the comparison is unknown, not true, and only true rows are kept. Add OR city IS NULL.
  2. Write the WHERE clause for: books from $9 to $11, both ends included, that are not by Tolkien. Answer: WHERE price BETWEEN 9 AND 11 AND author != 'J.R.R. Tolkien' (on the course data: Brave New World, 1984, Fahrenheit 451).
  3. Why should every ORDER BY that feeds a LIMIT end with a unique column? Answer: If rows tie at the cut-off, the server may return either one, and the choice can change between runs: page 1 and page 2 can repeat or skip a row. A unique column (id, title here) makes the order repeatable.
