Lesson

4.3

Joins

By the end you can
  • Combine matching rows from two or more tables with INNER JOIN ... ON, using table aliases
  • Keep unmatched rows with LEFT JOIN, and find rows with no match using the anti-join pattern
  • Explain what RIGHT JOIN and CROSS JOIN return, and when (rarely) to use them
  • Join a table to itself to read a hierarchy such as employees and managers
  • Combine joins with GROUP BY without the two silent traps: COUNT(*) on outer joins and row fan-out
Key ideas
  • JOIN ... ON (INNER) returns one row per matching pair; a row without a partner disappears.
  • LEFT JOIN keeps every row of the left table (the one before JOIN) and fills the right side with NULL when nothing matches.
  • Anti-join: LEFT JOIN right ... WHERE right.id IS NULL finds the rows with no match (or NOT EXISTS).
  • On a LEFT JOIN, conditions on the right table go in ON; in WHERE they turn it into an inner join.
  • A JOIN without ON is a cross join (every combination): check the ON when a join returns too many rows.
  • Self-join: one table, two aliases, two roles (employee and manager).
  • What does one row of this join stand for? Ask before COUNT or SUM: use COUNT(right.id), COUNT(DISTINCT ...), COALESCE.
  • Qualify columns that exist in both tables (1052); after an alias, use only the alias (1054).
Worked example: guests and RSVPs

A guest list and the RSVPs, small enough to check by eye. Four guests; Ana replied twice, Cleo once, Ben and Dev never.

DROP DATABASE IF EXISTS kit_rsvp;
CREATE DATABASE kit_rsvp;
USE kit_rsvp;
CREATE TABLE guests (id INT PRIMARY KEY, name VARCHAR(30) NOT NULL);
CREATE TABLE rsvps (
    id       INT PRIMARY KEY,
    guest_id INT NOT NULL,
    answer   VARCHAR(5) NOT NULL,
    CONSTRAINT fk_rsvps_guest FOREIGN KEY (guest_id) REFERENCES guests(id)
);
INSERT INTO guests VALUES (1, 'Ana'), (2, 'Ben'), (3, 'Cleo'), (4, 'Dev');
INSERT INTO rsvps VALUES (1, 1, 'yes'), (2, 3, 'no'), (3, 1, 'yes');
Database changed

JOIN keeps only the pairs (guest + reply): Ben and Dev are not in it, and Ana appears once per reply.

SELECT g.name, r.answer
FROM guests AS g
JOIN rsvps AS r ON r.guest_id = g.id
ORDER BY g.id, r.id;
+------+--------+
| name | answer |
+------+--------+
| Ana  | yes    |
| Ana  | yes    |
| Cleo | no     |
+------+--------+

LEFT JOIN keeps every guest; where there is no reply it writes NULL:

SELECT g.name, r.answer
FROM guests AS g
LEFT JOIN rsvps AS r ON r.guest_id = g.id
ORDER BY g.id, r.id;
+------+--------+
| name | answer |
+------+--------+
| Ana  | yes    |
| Ana  | yes    |
| Ben  | NULL   |
| Cleo | no     |
| Dev  | NULL   |
+------+--------+

The anti-join keeps only the guests with no reply (the right side's id is NULL):

SELECT g.name
FROM guests AS g
LEFT JOIN rsvps AS r ON r.guest_id = g.id
WHERE r.id IS NULL;
+------+
| name |
+------+
| Ben  |
| Dev  |
+------+

And the counting trap: COUNT(*) counts Ben's and Dev's padded rows; COUNT(r.id) does not:

SELECT g.name, COUNT(*) AS rows_counted, COUNT(r.id) AS replies
FROM guests AS g
LEFT JOIN rsvps AS r ON r.guest_id = g.id
GROUP BY g.id, g.name
ORDER BY g.id;
+------+--------------+---------+
| name | rows_counted | replies |
+------+--------------+---------+
| Ana  |            2 |       2 |
| Ben  |            1 |       0 |
| Cleo |            1 |       1 |
| Dev  |            1 |       0 |
+------+--------------+---------+

FROM orders

A) It returns 12 rows, using the order's id
B) ERROR 1052 (23000): Column 'id' in field list is ambiguous
C) ERROR 1054 (42S22): Unknown column 'id' in 'field list'

Q5
Carol (3) has no orders; Dave (4) has two. What does this print?
SELECT c.first_name, COUNT(o.id) AS orders
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
WHERE c.id IN (3, 4)
GROUP BY c.id, c.first_name
ORDER BY c.id;
Q6
This was meant to list every author with their in-stock books. Isaac Asimov (no books) and the authors of the two out-of-stock books are missing. Why?
SELECT a.name, b.title
FROM authors AS a
LEFT JOIN books AS b ON b.author_id = a.id
WHERE b.in_stock = TRUE
ORDER BY a.id, b.title;
A) LEFT JOIN cannot be combined with WHERE
B) in_stock is a BOOLEAN, so TRUE must be written as 1
C) The ORDER BY removes the NULL rows
D) The WHERE runs after the join: for the padded rows b.in_stock is NULL, so the LEFT JOIN behaves like an inner join

Part 1 Assessment: How It Works

The rules
  • 60 minutes, open book: the lesson pages, your notes, this workbook and your own scripts are allowed. Other people and AI assistants are not.
  • The file is the brief: labs/module-07/part1-assessment/part1_assessment_starter.sql. It builds the Riverside Cooking School database (kit_riverside): instructors, classes and students. You build the enrollments table (Part A) and answer eight questions (Part B), writing every answer in the file under its TODO.
  • Run it often: save, then SOURCE labs/module-07/part1-assessment/part1_assessment_starter.sql. Every run rebuilds the school from scratch, so you cannot break anything.
  • Joins or subqueries: either is fine where both work. Every query that returns several rows has an ORDER BY. Do not type a number the database can compute.
  • Hand in at the end: the file, renamed part1_assessment_<yourname>.sql, through the channel on the board. It must run from start to finish.
Before you start
  • ☐ My laptop is charged or plugged in; mysql -u root -p works from my course folder
  • ☐ The starter runs as handed out: three tables built, TODO lines, no ERROR
  • ☐ The lesson pages I may want are open in tabs (2.2 types and constraints, 4.2 foreign keys, 3.3 GROUP BY, 4.3 joins)
  • ☐ I know the plan: Part A in about 20 minutes, Part B in about 35, a final run in the last 5
If you get stuck
  • Read the FIRST error line: number, then reason. The lesson's Common Mistakes sections list most of them.
  • If A1 will not work after 15 minutes, make a minimal table (student_id INT, class_id INT, enrolled_on DATE, rating INT), turn on the A2 INSERT and move on: Part B needs the rows more than the rules.
  • Skip a Part B question and come back: each one is scored on its own.

Glossary

TermMeaning
joinPairs the rows of two tables that satisfy a condition (ON) and returns each pair as one wider row
INNER JOIN (JOIN)Only the rows with a match on both sides
LEFT JOINEvery row of the left table; NULL in the right table's columns where nothing matched
anti-joinLEFT JOIN ... WHERE right.id IS NULL: the left rows with no match
CROSS JOINEvery combination of rows (also what a JOIN without ON does)
self-joinA table joined to itself under two aliases (employee and manager)
table aliasA short name for a table in one query (books AS b)
fan-outRows multiplied by a join (one row per order line, not per order): count with care
ambiguous column (1052)A column name that exists in two joined tables, used without its table
