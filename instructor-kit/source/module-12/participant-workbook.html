7.4

User Management & Permissions

By the end you can
  • Create accounts as 'user'@'host' and explain how MySQL 9.7 stores their passwords (caching_sha2_password)
  • Grant and revoke privileges at the global, database, table and column level, and read SHOW GRANTS
  • Log in as a restricted user and recognize the access-denied errors (1142, 1143, 1044, 3118)
  • Group privileges into roles, assign them, and make them active with SET DEFAULT ROLE
  • Design least-privilege accounts for an application, a report and staff, and script them
Key ideas
  • Least privilege: every account gets the minimum it needs; nobody shares root, applications never use it.
  • An account is 'user'@'host'. The same name with another host is another account.
  • New accounts have only USAGE (may connect). GRANT what ON where TO whom adds; REVOKE ... FROM removes, at the same level.
  • Levels: *.* global, db.* database, db.table, columns SELECT (a, b), routines EXECUTE ON PROCEDURE.
  • Test both directions as the account: 1142 (table), 1143 (column), 1044 (database at login), 3118 (locked).
  • Roles bundle privileges; they work only once active: SET DEFAULT ROLE ALL TO ....
  • ACCOUNT LOCK disables an account and keeps its grants; DROP USER removes both.
  • caching_sha2_password is the default; mysql_native_password is gone in 9.x (1524): update the driver.
Worked example: a column-level grant and an audit

An intern may see each book's id, title and price, and nothing else: a column-level grant. Then an audit of what the account really has, read from information_schema (handy when SHOW GRANTS gets long), and the cleanup.

CREATE USER 'kit_intern'@'localhost' IDENTIFIED BY 'CHANGE-ME-intern-1';
GRANT SELECT (id, title, price) ON bookstore.books TO 'kit_intern'@'localhost';
SHOW GRANTS FOR 'kit_intern'@'localhost';
+------------------------------------------------------------------------------------------+
| Grants for kit_intern@localhost                                                          |
+------------------------------------------------------------------------------------------+
| GRANT USAGE ON *.* TO `kit_intern`@`localhost`                                           |
| GRANT SELECT (`id`, `price`, `title`) ON `bookstore`.`books` TO `kit_intern`@`localhost` |
+------------------------------------------------------------------------------------------+
SELECT GRANTEE, TABLE_NAME, COLUMN_NAME, PRIVILEGE_TYPE
FROM information_schema.COLUMN_PRIVILEGES
WHERE GRANTEE = '''kit_intern''@''localhost'''
ORDER BY COLUMN_NAME;
+--------------------------+------------+-------------+----------------+
| GRANTEE                  | TABLE_NAME | COLUMN_NAME | PRIVILEGE_TYPE |
+--------------------------+------------+-------------+----------------+
| 'kit_intern'@'localhost' | books      | id          | SELECT         |
| 'kit_intern'@'localhost' | books      | price       | SELECT         |
| 'kit_intern'@'localhost' | books      | title       | SELECT         |
+--------------------------+------------+-------------+----------------+
DROP USER 'kit_intern'@'localhost';

Logged in as kit_intern, SELECT title, price FROM books would work and SELECT * FROM books would fail with 1142 (not every column is granted).

8.1

Importing & Exporting Data

By the end you can
  • Back up a database with mysqldump, choose the right options for MySQL 9.7, and restore the file into a test database
  • Explain what secure_file_priv and local_infile control, and find their values on your server
  • Export query results to a CSV file with SELECT ... INTO OUTFILE, including a header row
  • Import a CSV file through a staging table with LOAD DATA INFILE, converting dates and empty values on the way in
  • Recognize and fix the errors file operations raise (1290, 1086, 3948, 2068, 3546)
Key ideas
  • Whole databases: mysqldump at the terminal writes SQL; the mysql client restores it. Rows: INTO OUTFILE and LOAD DATA at mysql>.
  • On 9.7: --single-transaction --routines --events --set-gtid-purged=OFF; without the last one a same-server restore fails with 3546.
  • A backup counts after a test restore into another database, with the counts compared and written down.
  • A dump holds no accounts: keep your CREATE USER and GRANT scripts.
  • Server-side files live in the secure_file_priv folder (1290 elsewhere, 1086 if the file exists) and need FILE.
  • LOCAL sends a file from your computer; local_infile must be on at both ends, and errors become warnings: read them.
  • Staging tables: load as text, convert with @variables, NULLIF, STR_TO_DATE, check with a LEFT JOIN, copy in one transaction.
Worked example: a header row for a CSV

INTO OUTFILE writes no column names. Glue a header row on with UNION ALL, and sort with a helper column so the header always comes first. On screen it looks like this; add the INTO OUTFILE clause at the end to write the file.

SELECT title, price
FROM (
    SELECT 0 AS part, 'title' AS title, 'price' AS price
    UNION ALL
    SELECT 1, title, price FROM books WHERE price > 12
) AS t
ORDER BY part, title;
+-------------------+-------+
| title             | price |
+-------------------+-------+
| title             | price |
| Dune              | 14.99 |
| Lord of the Rings | 15.99 |
+-------------------+-------+

The header made every column text, so the prices print left-aligned: spreadsheets do not mind.

Glossary

TermMeaning
accountA user name and the host it may connect from: 'user'@'host'
privilegePermission for one kind of statement (SELECT, INSERT, ...) at one level
least privilegeEvery account gets the minimum it needs, nothing more
USAGENo privileges: the account may connect, nothing else
roleA named bundle of privileges granted to accounts; active only after SET DEFAULT ROLE or SET ROLE
ACCOUNT LOCKDisables a login without deleting the account or its grants (3118 at login)
mysqldumpA terminal program that writes a database as SQL statements (a logical backup)
test restoreLoading a backup into another database and comparing it with the original
GTIDGlobal transaction IDs used by replication; on in 9.7, hence --set-gtid-purged=OFF
secure_file_privThe only folder the server reads files from and writes files to
INTO OUTFILEWrites a query's rows to a file on the server
LOAD DATA [LOCAL] INFILEReads a file's rows into a table (LOCAL: the file is on your computer)
staging tableA table that receives raw imported rows for checking before the real tables
