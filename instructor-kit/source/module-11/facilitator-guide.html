The questions and their answers
  1. W1 (6.3) A book-club sheet has a cell that reads Dune, 1984. Which normal form does that break, and what is the fix? Answer: 1NF: one value per cell. Fix: one row per book in a child table (member_id, book_id).
  2. W2 (6.3) "The key, the whole key, and nothing but the key." Which part of the phrase is 2NF, and which is 3NF? Answer: "The whole key" is 2NF (no column depends on only part of a composite key); "nothing but the key" is 3NF (no column depends on another non-key column).
  3. W3 (7.1) Which program reads the line DELIMITER //: the server, the client or the procedure? Answer: The mysql client. It changes where the client cuts statements; the server never sees the word DELIMITER.
  4. W4 (7.1) You want SELECT title, sale_price(price) FROM books to work. Do you write a stored procedure or a stored function? Answer: A stored function: it returns one value and can sit inside an expression. A procedure runs with CALL.

W5 (7.1) Predict, then run (it creates a small function in bookstore, which the 7.2 demo does not need):

RETURNS DECIMAL(8, 2) DETERMINISTIC
RETURN ROUND(p_price * 0.8, 2);
SELECT title, price, sale_price(price) AS on_sale
FROM books
WHERE id IN (1, 2)
ORDER BY id;

| title | price | on_sale |
+-------+-------+---------+
| Dune  | 14.99 |   11.99 |
| 1984  |  9.99 |    7.99 |

Lesson Plans

7.2

Transactions

60 min
Objectives (from the lesson page)
  • Group changes with START TRANSACTION, COMMIT and ROLLBACK, and explain autocommit and implicit commits
  • Undo part of a transaction with SAVEPOINT and ROLLBACK TO SAVEPOINT
  • Predict what a second connection sees and when it has to wait, under MySQL's default REPEATABLE READ isolation
  • Lock rows on purpose with SELECT ... FOR UPDATE, and read lock errors 1205 and 1213
  • Write a stored procedure whose error handler rolls back the whole transaction and passes the error on
Timing in the room
10mFrame: all or nothing; ACID; autocommit and implicit commits
25mLive demo: COMMIT, ROLLBACK, two silent traps, two windows, a procedure with a handler
15mGuided lab: loyalty_points_starter.sql in pairs
10mStart the lesson project: checkout.sql, setup and Step 1
Mental model to say

Start with the gift card: "Move 30 dollars of store credit from Alice to Bob: subtract from Alice, add to Bob. If the server stops between the two, 30 dollars vanish. A transaction makes the pair one unit: the database keeps both changes or neither."

Then the board line: START TRANSACTION → your statements → COMMIT (keep all) or ROLLBACK (discard all). "Every UPDATE you ran in this course was already a transaction: autocommit wraps each statement in its own and commits it at once. START TRANSACTION switches that off until you decide."

Then ACID in one breath, pointing at the bookstore: atomicity (an order never exists without its items), consistency (the CHECK holds after every commit), isolation (a report never counts a half-placed order), durability (after COMMIT it survives a power cut). And the warning list on the board: CREATE, ALTER, DROP, TRUNCATE and account statements commit by themselves.

Live demo (you type, they follow)

This is the lesson's own sequence, from a fresh bookstore.sql. Learners type along in their own window; for the two-window step they open a second terminal. Ask for a prediction before every statement that prints something.

    (2, 'Bob Smith', 50.00),

  5. Silent trap 1: a schema change inside a transaction (3m). "I zero Bob's balance, create a little audit table, change my mind and roll back." Predict Bob's balance. 
    START TRANSACTION;
UPDATE accounts SET balance = 0 WHERE id = 2;

ROLLBACK;

    +----+---------+
| id | balance |
+----+---------+
|  2 |    0.00 |
+----+---------+
    The CREATE TABLE committed the open transaction before it ran, so ROLLBACK had nothing to undo. Repair it (no output): UPDATE accounts SET balance = 80.00 WHERE id = 2; DROP TABLE demo_audit;
  6. Silent trap 2: COMMIT after an error (3m). "Carol has 0.00 and sends Bob 40 by hand." Run it as one block, so the COMMIT runs after the error. 
    START TRANSACTION;
UPDATE accounts SET balance = balance + 40 WHERE id = 2;
UPDATE accounts SET balance = balance - 40 WHERE id = 3;
COMMIT;
SELECT * FROM accounts ORDER BY id;
    ERROR 3819 (HY000): Check constraint 'chk_balance' is violated.
+----+----------------+---------+
| id | name           | balance |
+----+----------------+---------+
|  1 | Alice Johnson  |  120.00 |
|  2 | Bob Smith      |  120.00 |
|  3 | Carol Williams |    0.00 |
+----+----------------+---------+
    In MySQL a failed statement undoes only itself; the transaction stays open with Bob's +40 in it, and COMMIT saved it: 40 dollars from nothing (PostgreSQL would refuse the COMMIT). Repair: UPDATE accounts SET balance = balance - 40 WHERE id = 2;. The fix in code is a handler; at the prompt, ROLLBACK after any error.
  7. Two windows (5m). "Real databases serve many connections at once." Open a second terminal on the projector, side by side, label them A and B on the board. The table continues from the steps above (Alice 120, Bob 80, Carol 0); it comes from two real client sessions:
    WindowStatementWhat it shows (real output)
    ASTART TRANSACTION; UPDATE accounts SET balance = balance - 20 WHERE id = 1; SELECT id, balance FROM accounts WHERE id = 1;100.00: A sees its own change
    BSELECT id, balance FROM accounts WHERE id = 1;120.00 at once: the committed value, no waiting
    BUPDATE accounts SET balance = balance + 1 WHERE id = 1;waits, then ERROR 1205 (HY000): Lock wait timeout exceeded; try restarting transaction (5 s on the test server; 50 s on a default server)

    BSELECT id, balance FROM accounts WHERE id = 1;100.00: now B sees it
    Say: "readers never wait and never see unfinished work; writers wait for writers." If you commit in A while B is still waiting, B's UPDATE simply finishes: show that once if the room is with you. FOR UPDATE (a read that locks) and deadlocks (1213) stay on the slides.
  8. A procedure that cleans up after itself (3m). "At the prompt you decide; in a procedure the code must decide. The handler is two lines: ROLLBACK, then RESIGNAL." Paste this one (it is the lesson's; do not type 28 lines live) and walk through the handler, the SIGNALs and FOR UPDATE. 
    DROP PROCEDURE IF EXISTS transfer;
DELIMITER //
CREATE PROCEDURE transfer(IN p_from INT, IN p_to INT, IN p_amount DECIMAL(10, 2))
BEGIN
    DECLARE v_balance DECIMAL(10, 2);
    DECLARE EXIT HANDLER FOR SQLEXCEPTION
    BEGIN
        ROLLBACK;   -- undo everything this call did
        RESIGNAL;   -- and pass the original error to the caller
    END;
    IF p_amount IS NULL OR p_amount <= 0 THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Amount must be positive';
    END IF;
    START TRANSACTION;
    SELECT balance INTO v_balance FROM accounts WHERE id = p_from FOR UPDATE;
    IF v_balance IS NULL THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'No such source account';
    END IF;
    IF v_balance < p_amount THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Insufficient funds';
    END IF;
    UPDATE accounts SET balance = balance - p_amount WHERE id = p_from;
    UPDATE accounts SET balance = balance + p_amount WHERE id = p_to;
    IF ROW_COUNT() = 0 THEN
        SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'No such destination account';
    END IF;
    COMMIT;
END //
DELIMITER ;

Three mistakes to expect, and how to coach each
  • Committing after an error. "I got 3819, then typed COMMIT, and Bob still got his 40." Coach: "In MySQL a failed statement undoes only itself. After any error inside a transaction, ROLLBACK, or let a handler do it." (Self-check Q3 and the lab's debug file.)
  • Expecting a lock to block reads. "Why could B read the row A was changing?" Coach with the two columns on the board: readers get the last committed version and never wait; only writers (and FOR UPDATE) wait for the lock.
  • A transaction left open in a forgotten window. Someone's UPDATE hangs for 50 seconds. Coach: "Which window has an open transaction? COMMIT or ROLLBACK it." Closing a window rolls back, which also releases the locks.

Checks for understanding

Ask these out loud during the demo and the lab:

  • After START TRANSACTION; UPDATE ...; who can see the change? Answer: only your own session, until COMMIT.
  • Which of these ends a transaction by itself: SAVEPOINT, CREATE TABLE, SELECT? Answer: CREATE TABLE (an implicit commit).
  • B's plain SELECT did not wait for A's lock. Why did B's UPDATE wait? Answer: writers need the row lock; readers read the committed snapshot.
  • Why RESIGNAL after ROLLBACK in a handler? Answer: so the caller still learns the original error.

Workbook self-check, items Q1 to Q6 (learners do them at the end of the block or at home).

Answers: Q1 B) The server rolls it back when the connection ends; Q2 Two rows: id 1 qty 4, id 2 qty 8; Q3 C) ALTER TABLE books ADD COLUMN rating INT;; Q4 D) Nothing yet: B waits for A's row lock, and fails with ERROR 1205 if A holds it past the timeout; Q5 A) So the caller still receives the original error after the half-done changes are undone; Q6 D) Run the whole transaction again from the start. Full set with explanations in the Answer Key.

7.3

JSON Columns

60 min
Objectives (from the lesson page)
  • Add a JSON column and explain how MySQL validates and stores what you put in it
  • Read values with ->, ->> and JSON_EXTRACT, and filter rows on them
  • Change parts of a document with JSON_SET, JSON_INSERT, JSON_REMOVE and JSON_ARRAY_APPEND
  • Turn rows into JSON with JSON_OBJECT and JSON_ARRAYAGG, and JSON back into rows with JSON_TABLE
  • Index a JSON path through a generated column, and decide when data belongs in real columns instead
Timing in the room
10mFrame: columns for what every row has, JSON for the flexible leftovers; paths, -> and ->>
25mLive demo: the lesson's attributes column from setup to an indexed path, and two silent mistakes
15mGuided lab: reader_prefs_starter.sql in pairs
10mStart the lesson project: catalog_feed.sql, the setup and Step 1
Mental model to say

Use the two columns on the board: "Every book has a title, a price, an author: columns. Only some books have a series, some won awards, some are illustrated, and marketing invents a new detail every month. A column per detail would be mostly NULL; a JSON column holds one small document per row for the flexible leftovers."

Then the path: "You reach inside a document with a path. $ is the whole document, $.format a key, $.awards[0] the first element." And the two arrows, written large: -> gives JSON (a string keeps its quotes), ->> gives plain text for people, comparisons and sorting.

Then the rule that decides everything: "If every row has it, you join on it, sum it or protect it with a constraint, it is a column. JSON is for optional, varied, mostly-for-display details. Design the tables first; JSON gets the leftovers."

Live demo (you type, they follow)

The lesson's own sequence, from a fresh bookstore.sql (learners reloaded it at the break). Ask for a prediction before each step that prints something.

  1. Add the column and fill it (3m). "Details that only some books have: a format, a series, awards. One JSON document per row, next to the ordinary columns." Learners reloaded bookstore.sql at the break; these are the lesson's four statements. 
    ALTER TABLE books ADD COLUMN attributes JSON;

  3. MySQL checks every document (1m). "JavaScript lets you write a bare key. JSON does not." 
    UPDATE books SET attributes = '{format: "ebook"}' WHERE id = 2;
    ERROR 3140 (22032): Invalid JSON text: "Missing a name for object member." at position 1 in value for column 'books.attributes'.
    Fix: double quotes around every key, or let JSON_OBJECT('format', 'ebook') write it for you.
  4. Two arrows (3m). "Every path starts at $. The single arrow gives JSON, quotes and all; the double arrow gives plain text." Predict which column has quotes. 
    SELECT
    title,
    JSON_EXTRACT(attributes, '$.format') AS extracted,
    attributes->'$.format'               AS arrow,
    attributes->>'$.format'              AS double_arrow
FROM books
WHERE id IN (1, 6)
ORDER BY id;
    +------------+-------------+-------------+--------------+
| title      | extracted   | arrow       | double_arrow |
+------------+-------------+-------------+--------------+
| Dune       | "paperback" | "paperback" | paperback    |
| The Hobbit | "hardcover" | "hardcover" | hardcover    |
+------------+-------------+-------------+--------------+
  5. Arrays and missing keys (2m). "[0] is the first element. 1984 has an empty array; the Hobbit has no awards key at all. A missing key is NULL, not an error." 
    SELECT
    title,
    attributes->>'$.awards[0]'          AS first_award,
    JSON_LENGTH(attributes->'$.awards') AS award_count,
    attributes->>'$.series'             AS series
FROM books
WHERE id IN (1, 2, 6)
ORDER BY id;
    +------------+-------------+-------------+-----------------+
| title      | first_award | award_count | series          |
+------------+-------------+-------------+-----------------+
| Dune       | Hugo        |           2 | Dune Chronicles |
| 1984       | NULL        |           0 | NULL            |
| The Hobbit | NULL        |        NULL | Middle-earth    |
+------------+-------------+-------------+-----------------+
  6. Is it in the array? (1m). "MEMBER OF asks: is this value one of the array's elements?" 
    SELECT title
FROM books
WHERE 'Hugo' MEMBER OF (attributes->'$.awards');
    +-------+
| title |

  7. Change part of a document (2m). "JSON_SET returns a changed copy; UPDATE stores it." Mention the family: SET adds or replaces, INSERT only adds, REPLACE only replaces, REMOVE, ARRAY_APPEND. 
    UPDATE books
SET attributes = JSON_SET(attributes, '$.edition', '75th anniversary')
WHERE id = 6;
SELECT attributes->>'$.edition' AS edition, attributes->>'$.format' AS format
FROM books WHERE id = 6;

  8. JSON from rows (2m). "An app wants JSON? MySQL can build it." Point out that numbers stay numbers and the keys come out sorted again. 
    SELECT JSON_OBJECT('id', id, 'title', title, 'price', price) AS item
FROM books
WHERE id <= 3
ORDER BY id;
    +-------------------------------------------------------------+
| item                                                        |
+-------------------------------------------------------------+
| {"id": 1, "price": 14.99, "title": "Dune"}                  |
| {"id": 2, "price": 9.99, "title": "1984"}                   |
| {"id": 3, "price": 11.99, "title": "To Kill a Mockingbird"} |
+-------------------------------------------------------------+
  9. JSON back to rows (3m). "Arrays are awkward to report on. JSON_TABLE makes one row per element." Read it aloud: for every book, take $.awards, one row per element, call the element award. 
    SELECT b.title, aw.award
FROM books AS b,
     JSON_TABLE(
         b.attributes,
         '$.awards[*]'
         COLUMNS (award VARCHAR(40) PATH '$')
     ) AS aw
ORDER BY b.title, aw.award;
    +-------+--------+
| title | award  |
+-------+--------+
| Dune  | Hugo   |
| Dune  | Nebula |
+-------+--------+
  10. Index a path (3m). "You cannot index the JSON column itself (error 3152), but you can index a generated column that pulls one value out." 
    ALTER TABLE books
    ADD COLUMN format VARCHAR(20)
        GENERATED ALWAYS AS (attributes->>'$.format') VIRTUAL,
    ADD INDEX idx_books_format (format);
SELECT title, format FROM books WHERE format = 'hardcover' ORDER BY title;
    +-------------------+-----------+
| title             | format    |
+-------------------+-----------+
| Lord of the Rings | hardcover |
| The Hobbit        | hardcover |
+-------------------+-----------+

    EXPLAIN SELECT title FROM books WHERE attributes->>'$.format' = 'hardcover'\G

    SELECT title
FROM books
WHERE attributes->>'$.Format' = 'hardcover';
SELECT CONCAT(title, ' (', attributes->'$.format', ')') AS label
FROM books
WHERE id = 1;
    Empty set
+--------------------+
| label              |
+--------------------+
| Dune ("paperback") |
+--------------------+
    Keys are case-sensitive and a missing key is NULL, so the typo finds nothing and warns nobody. The quotes would end up on the web page: use ->> whenever a value leaves JSON.
Three mistakes to expect, and how to coach each
  • JSON written like JavaScript ({format: "ebook"}, single quotes inside): error 3140. Coach: "keys and text in double quotes; the whole document inside SQL's single quotes", or JSON_OBJECT writes it for you.
  • The single arrow where text was meant: quotes in labels, comparisons with '"paperback"'. Coach: "Is the value leaving JSON (display, CONCAT, WHERE with text)? Then two arrows."
  • A typo in a key, and no error: $.Format returns NULL everywhere. Coach: copy key names from the data (SELECT attributes FROM books LIMIT 1), keep one spelling, and protect important keys with a CHECK or a generated column.

Checks for understanding

Closing

Exit ticket (3 questions, no notes, 4 minutes)

Put the three questions on the slide. Learners answer in the workbook's Exit Ticket box or on a sticky note. Sort them before Session 12: question 1's "not yet" pile gets the first minute of the Session 12 warm-up.

  1. Inside a transaction, an UPDATE fails with error 3819 and you then type COMMIT. What is saved? Answer: every change made before the failed statement: a failed statement undoes only itself. ROLLBACK after an error.
  2. Write the handler that makes a procedure undo its transaction on any error and still report the error. Answer: DECLARE EXIT HANDLER FOR SQLEXCEPTION BEGIN ROLLBACK; RESIGNAL; END;
  3. Name one bookstore fact that belongs in JSON and one that must stay a column, with a reason each. Answer (example): a book's series (only some books have one, display only) in JSON; its price in a column (every book has one, totals use it).
