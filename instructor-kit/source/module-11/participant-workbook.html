7.2

Transactions

By the end you can
  • Group changes with START TRANSACTION, COMMIT and ROLLBACK, and explain autocommit and implicit commits
  • Undo part of a transaction with SAVEPOINT and ROLLBACK TO SAVEPOINT
  • Predict what a second connection sees and when it has to wait, under MySQL's default REPEATABLE READ isolation
  • Lock rows on purpose with SELECT ... FOR UPDATE, and read lock errors 1205 and 1213
  • Write a stored procedure whose error handler rolls back the whole transaction and passes the error on
Key ideas
  • A transaction is all or nothing: START TRANSACTION, your statements, then COMMIT (keep) or ROLLBACK (discard).
  • Autocommit (on by default) commits every statement by itself. START TRANSACTION suspends it until COMMIT or ROLLBACK.
  • Implicit commits: CREATE, ALTER, DROP, TRUNCATE and account statements commit the open transaction before they run.
  • A failed statement undoes only itself: after an error inside a transaction, ROLLBACK (or let a handler do it).
  • Savepoints undo part of a transaction and keep it open: SAVEPOINT s; ... ROLLBACK TO SAVEPOINT s;
  • Isolation (REPEATABLE READ): plain reads see committed data from a snapshot and never wait; writers wait for row locks (1205 after the timeout).
  • FOR UPDATE locks the rows you are about to change; a deadlock (1213) rolls one transaction back: retry it whole.
  • In procedures: DECLARE EXIT HANDLER FOR SQLEXCEPTION BEGIN ROLLBACK; RESIGNAL; END;
Worked example: a gift card pays for a book

A gift card pays for a book: read the balance with a lock, charge the card, create the order and its line, all in one transaction. The lock (FOR UPDATE) keeps a second cashier from spending the same balance between the check and the charge.

CREATE TABLE gift_cards (
    code    VARCHAR(10) PRIMARY KEY,
    balance DECIMAL(8, 2) NOT NULL CHECK (balance >= 0)
);
INSERT INTO gift_cards VALUES ('GC-100', 25.00);
START TRANSACTION;
SELECT balance FROM gift_cards WHERE code = 'GC-100' FOR UPDATE;
UPDATE gift_cards SET balance = balance - 14.99 WHERE code = 'GC-100';
INSERT INTO orders (customer_id, order_date) VALUES (3, '2026-06-30');
INSERT INTO order_items (order_id, book_id, quantity, price_at_time)
VALUES (LAST_INSERT_ID(), 1, 1, 14.99);
COMMIT;
+---------+
| balance |
+---------+
|   25.00 |
+---------+

Both the charge and the order are there, or neither would be:

SELECT (SELECT balance FROM gift_cards WHERE code = 'GC-100') AS card_left,
       (SELECT COUNT(*) FROM orders WHERE customer_id = 3)         AS carol_orders;
+-----------+--------------+
| card_left | carol_orders |
+-----------+--------------+
|     10.01 |            1 |
+-----------+--------------+

In an app, the error branch would ROLLBACK; in a procedure, a handler does it (Lesson 7.2's transfer).

7.3

JSON Columns

By the end you can
  • Add a JSON column and explain how MySQL validates and stores what you put in it
  • Read values with ->, ->> and JSON_EXTRACT, and filter rows on them
  • Change parts of a document with JSON_SET, JSON_INSERT, JSON_REMOVE and JSON_ARRAY_APPEND
  • Turn rows into JSON with JSON_OBJECT and JSON_ARRAYAGG, and JSON back into rows with JSON_TABLE
  • Index a JSON path through a generated column, and decide when data belongs in real columns instead
Key ideas
  • A JSON column holds one validated document per row (error 3140 for invalid JSON), stored in a binary form with sorted keys.
  • Paths start at $: $.format, $.awards[0], $.awards[last], $.awards[*].
  • -> (= JSON_EXTRACT) returns JSON, with quotes; ->> returns plain text for display, comparison and sorting.
  • A missing key is NULL, not an error, so a misspelled key fails silently.
  • JSON_SET / INSERT / REPLACE / REMOVE / ARRAY_APPEND return a changed copy; UPDATE stores it.
  • JSON_OBJECT and JSON_ARRAYAGG build JSON from rows; JSON_TABLE turns JSON back into rows.
  • Index a path through a generated column; protect important keys with a CHECK.
  • Core data stays in columns and tables: what every row has, what you join on or calculate with.
Worked example: a JSON message becomes rows

A review widget sends one JSON message with several reviews. JSON_TABLE turns it into rows that join and group like any table.

SET @reviews = '{"source": "web", "reviews": [
    {"book_id": 1, "stars": 5}, {"book_id": 1, "stars": 4},
    {"book_id": 6, "stars": 5}, {"book_id": 2, "stars": 3}]}';
SELECT b.title, COUNT(*) AS reviews, AVG(r.stars) AS avg_stars
FROM JSON_TABLE(@reviews, '$.reviews[*]'
         COLUMNS (book_id INT PATH '$.book_id', stars INT PATH '$.stars')) AS r
JOIN books AS b ON b.id = r.book_id
GROUP BY b.id, b.title
ORDER BY avg_stars DESC, b.title;
+------------+---------+-----------+
| title      | reviews | avg_stars |
+------------+---------+-----------+
| The Hobbit |       1 |    5.0000 |
| Dune       |       2 |    4.5000 |
| 1984       |       1 |    3.0000 |
+------------+---------+-----------+

The stars come from the message, but the titles come from books: never trust names or prices sent by a browser.

Glossary

TermMeaning
transactionSeveral statements treated as one unit: all of them are kept (COMMIT) or none (ROLLBACK)
ACIDAtomicity, consistency, isolation, durability: the guarantees a transaction gives
autocommitThe default mode: each statement is its own transaction, committed at once
implicit commitA commit MySQL does by itself before DDL and account statements
savepointA named bookmark inside a transaction; ROLLBACK TO it undoes only the later part
isolation levelWhat a transaction sees of others' work; MySQL's default is REPEATABLE READ
row lockA writer's claim on a row; other writers wait (1205 after innodb_lock_wait_timeout)
deadlockTwo transactions waiting for each other; InnoDB rolls one back with 1213
EXIT HANDLERCode that runs when a statement in a routine fails, then leaves the routine
JSONA text format of objects, arrays, strings, numbers, true, false and null
pathWhere a value sits in a document: $, $.key, $.list[0], $.list[*]
-> / ->>Extract a value as JSON (with quotes) / as plain text
JSON_TABLETurns a JSON array into rows with typed columns
generated columnA column computed from other columns of the row; can be indexed
