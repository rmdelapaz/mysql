Start Here · Diagnostic

Not graded. Each reason also says where the skill comes back in this course. The sheet is the one on the workbook's Start Here page; MySQL's own answers to D1 to D5 are in the diagnostic lab's output below.

D1
You filter the city column to show only Chicago. How many rows are left?
A) 1
B) 2
C) 3
D) 6
Why: Orders 1002 and 1003. A filter keeps the rows that match a condition; in SQL that is WHERE city = 'Chicago'. Skill: filtering rows. Where it comes back: WHERE in Lesson 3.1 (and the lesson's first SELECT).
D2
You sort by price, largest first. Which item is on the top row?
A) Pride and Prejudice
B) The Hobbit
C) Dune
D) 1984
Why: 14.99 is the highest price (Dune appears twice with it). Sorting in SQL is ORDER BY price DESC. Skill: sorting. Where it comes back: ORDER BY in Lesson 3.2.
D3
How many rows have the city New York AND a qty of 2 or more?
A) 1
B) 2
C) 4
D) 5
Why: Only 1005 (Frank Miller) meets both conditions. With OR the answer would be 4 rows (1001, 1002, 1004, 1005): the most common slip, and the reason for the lab's TODO 3. Skill: AND versus OR. Where it comes back: WHERE with AND/OR in Lesson 3.1.
D4
You add a column total = qty × price. What is the total for order 1004?
A) 14.99
B) 17.99
C) 29.98
D) 44.97
Why: 3 × 14.99 = 44.97. In SQL a formula column is an expression in the SELECT list: qty * price AS total. Skill: a formula column. Where it comes back: expressions in SELECT (Lesson 1.1's taste, then 3.3).
D5
=COUNTA(city) counts the filled-in cells of the city column. What does it give?
A) 4
B) 5
C) 6
D) 0
Why: Six rows, but Eve's city is empty, so 5. SQL has the same idea: COUNT(city) skips empty (NULL) values, COUNT(*) counts rows. Skill: empty cells. Where it comes back: NULL in Lessons 2.2 and 3.3.
D6
You saved bookstore.sql in your Downloads folder. Your terminal is open in your home folder. Which path names the file?
A) bookstore.sql
B) Downloads/bookstore.sql
C) /bookstore.sql
D) home/Downloads.sql
Why: A relative path starts from the folder the terminal is in: from home, the file is inside Downloads. (Windows writes Downloads\bookstore.sql.) From Lesson 1.3 on you run .sql files this way: SOURCE Downloads/bookstore.sql. Skill: files and folders. Where it comes back: the Setup Guide and Lesson 1.3 (running .sql files).

1.1 · What Is a Database?: self-check

Q1
Which sentence describes MySQL correctly?
A) MySQL is a database: the file that holds your tables
B) MySQL is a database management system: server software that stores databases, enforces their rules and answers SQL
C) MySQL is a query language, a dialect of SQL
D) MySQL is a spreadsheet program that understands SQL
Why: A database is the organized data (for example the course's bookstore); the DBMS is the program that guards it and answers queries. MySQL, MariaDB and PostgreSQL are DBMSs.
A is wrong: The database is your data; MySQL is the software around it, and one MySQL server holds many databases.
C is wrong: SQL is the language; MySQL is a product that understands it (with its own small dialect).
D is wrong: A DBMS enforces types, keys and permissions that a spreadsheet does not.
Q2
A books table has the columns id, title, author_id, price. Which column is most likely a foreign key?
A) id
B) title
C) author_id
D) price
Why: author_id holds another table's primary key (authors.id) to say which author wrote the book: that is what a foreign key is.
A is wrong: id is this table's own primary key.
B is wrong: A title is ordinary data; two books can even share one.
D is wrong: A price is ordinary data, not a pointer to another row.
Q3
What does the last statement print?
CREATE TABLE pets (id INT PRIMARY KEY, name VARCHAR(20), kind VARCHAR(10));
INSERT INTO pets VALUES (1, 'Rex', 'dog'), (2, 'Tom', 'cat'), (3, 'Fido', 'dog');
UPDATE pets SET kind = 'cat' WHERE id = 3;
SELECT name FROM pets WHERE kind = 'cat' ORDER BY id;
Two rows: Tom and Fido
Why: The UPDATE changes only the row whose id is 3 (Fido) from dog to cat, so two cats come back, in id order. A WHERE clause picks the rows an UPDATE touches, exactly as it picks the rows a SELECT shows.
Q4
The pets table from Q3 is still there. What happens when this runs?
-- pets now holds ids 1, 2 and 3
INSERT INTO pets VALUES (2, 'Kit', 'cat');
A) ERROR 1062 (23000): Duplicate entry '2' for key 'pets.PRIMARY'
B) A new row is added: Kit gets id 4 automatically
C) ERROR 1366 (HY000): Incorrect integer value
D) Tom's row is replaced by Kit's
Why: id is the primary key and 2 already belongs to Tom. A primary key must be unique, so MySQL refuses the whole row (the lesson's Common Mistake 1). Leaving the id to AUTO_INCREMENT avoids it.
B is wrong: The id was given explicitly (and this table has no AUTO_INCREMENT): MySQL does not change your values.
C is wrong: 2 is a perfectly good integer; 1366 is for text in a number column.
D is wrong: An INSERT never overwrites an existing row.
Q5
A music app must remember, for millions of logged-in users, which song each is playing right now, and look it up in under a millisecond. Which kind of database fits best?
A) A relational database with a table per song
B) A graph database
C) A document store
D) A key-value store such as Redis
Why: One value (the current song) looked up by one key (the session or user id), very fast, usually in memory: the job key-value stores are built for. The app's accounts and payments would still live in a relational database.
A is wrong: It would work, but the data is a single key and value, and speed is the whole requirement.
B is wrong: A graph database answers questions about chains of connections.
C is wrong: Documents suit records whose fields vary; here every record is one key and one value.
Q6
Carol closes her account. Which statement removes her row but keeps the table and every other customer?
A) DROP TABLE customers;
B) DELETE FROM customers WHERE id = 3;
C) UPDATE customers SET email = NULL WHERE id = 3;
D) DELETE FROM customers;
Why: DELETE removes rows (the D in CRUD); its WHERE clause picks which ones.
A is wrong: DROP TABLE removes the table itself, structure and all rows.
C is wrong: UPDATE changes values in a row that stays (and here it would break the NOT NULL rule on email).
D is wrong: Without WHERE, DELETE removes every customer.

1.1 · What Is a Database?: predict, then run

P1
Predict the output, then run it.
CREATE TABLE notes (id INT PRIMARY KEY, title VARCHAR(30) NOT NULL);
INSERT INTO notes VALUES (1, 'Buy milk'), (2, 'Call Bob'), (3, 'Pay rent');
DELETE FROM notes WHERE id = 2;
SELECT * FROM notes;
+----+----------+
| id | title    |
+----+----------+
|  1 | Buy milk |
|  3 | Pay rent |
+----+----------+
Why: DELETE removes only the row whose id is 2; the other two stay with their ids. Ids are never renumbered after a delete.
P2
Predict the output, then run it.
CREATE TABLE members (id INT PRIMARY KEY, email VARCHAR(50) NOT NULL UNIQUE);
INSERT INTO members VALUES (1, 'ana@example.com');
INSERT INTO members VALUES (2, 'ana@example.com');
ERROR 1062 (23000): Duplicate entry 'ana@example.com' for key 'members.email'
Why: The first INSERT works. The second repeats an email in a UNIQUE column, so MySQL refuses it with 1062 and names the key (members.email). The table keeps one row.

1.2 · Installing MySQL: self-check

Q7
mysql --version in a terminal prints 9.7.2. What does that prove?
A) The MySQL server is running
B) Your password is correct
C) The mysql client program is installed and on your PATH
D) Your server is MySQL 9.7, not MariaDB
Why: mysql --version describes the client on your computer and works with no server running at all. Only SELECT VERSION();, sent after logging in, describes the server (the lesson's Exercise 1).
A is wrong: No connection is made; a stopped server gives the same answer.
B is wrong: No password is asked for.
D is wrong: A 9.7 client can talk to an 8.4 or a MariaDB server; ask the server.
Q8
mysql -u root -p answers ERROR 1045 (28000): Access denied for user .... What do you fix first?
A) The user name or the password
B) Start the server
C) Add mysql to your PATH
D) Reinstall MySQL with the native password plugin
Why: 1045 means the server is running and answered, but refused the credentials. Retype the password (it is case-sensitive); remember -p; on Ubuntu's own package root may only work through sudo mysql.
B is wrong: A stopped server cannot refuse you: it gives 2002 or 2003.
C is wrong: Without the client on the PATH you would get "command not found", not a MySQL error.
D is wrong: That plugin is removed in 9.x (error 1524), and the problem is the credentials.
Q9
On the course's MySQL 9.7 server, what does this print?
SELECT VERSION() LIKE '9.7.%' AS on_97;
1 (in a column named on_97)
Why: LIKE compares the version text with a pattern (% means anything), and a comparison gives 1 for true and 0 for false. VERSION() is 9.7.2 here, so the answer is 1; on 8.4 or MariaDB it would be 0.
Q10
You use Homebrew on a Mac. Which command installs the version this course uses?
A) brew install mysql
B) brew install mariadb
C) brew install mysql-client
D) brew install mysql@9.7
Why: The versioned formula mysql@9.7 stays on the 9.7 LTS series (it is keg-only: add its bin folder to the PATH).
A is wrong: The plain formula follows the newest innovation release (calendar numbers such as 26.x).
B is wrong: That is MariaDB, a different product.
C is wrong: That installs only the client, with no server.
Q11
Your MySQL container was started with -p 3307:3306. Which command connects to it from a mysql client installed on your laptop?
A) mysql -u root -p
B) mysql -h localhost -P 3306 -u root -p
C) mysql -h 127.0.0.1 -P 3307 -u root -p
D) mysql -h 127.0.0.1 -P 3306 -u root -p
Why: The container's port 3306 is published on the laptop's port 3307, and 127.0.0.1 forces a network connection (localhost would make the client look for a local socket file and ignore the port).
A is wrong: That looks for a local server on the default socket: error 2002.
B is wrong: localhost ignores -P on macOS and Linux, and 3306 is the wrong laptop port anyway.
D is wrong: Right host, wrong port: 3306 on the laptop is not where the container listens.
Q12
On a fresh MySQL 9.7 install (not Docker), what does this print?
SELECT plugin
FROM mysql.user
WHERE user = 'root' AND host = 'localhost';
caching_sha2_password
Why: caching_sha2_password is the default login method for every new account in 8.4 and 9.x. mysql_native_password no longer exists in 9.x, so you should never see it there.

Handout: labs/module-01/l1_2-installing-mysql/debug_old_advice.sql (deliberately broken)

As shipped, MySQL prints:

ERROR 1524 (HY000): Plugin 'mysql_native_password' is not loaded
ERROR 1193 (HY000): Unknown system variable 'default_authentication_plugin'
Empty set
  1. 1524: the mysql_native_password plugin is not loaded: removed in 9.x, disabled by default in 8.4. No account is created (the check query is empty). Modern replacement: leave out IDENTIFIED WITH ... (the default caching_sha2_password) and update the client or library.
  2. 1193: default_authentication_plugin no longer exists. Modern replacement: SELECT @@authentication_policy;.

On MariaDB the first statement fails with 1064 (MariaDB writes IDENTIFIED VIA); with corrected MariaDB syntax it would CREATE the account, so never "fix" it in class.

The Lesson Pages' Own Quick Quizzes

Lesson 1.1 · What Is a Database?
  1. B The database is the data; the DBMS is the software that manages it: The database is the organized data itself. The DBMS, such as MySQL, is the software that stores it, enforces its rules and answers queries about it.
  2. C A foreign key: A foreign key holds another table's primary key to record which row this one belongs to. Many orders can point at the same customer.
  3. A SELECT: R is Read, and reading rows is what SELECT does. INSERT, UPDATE and DELETE cover Create, Update and Delete.
  4. C id 1 is already used, and a primary key must be unique: id is the primary key and 1 already belongs to Alice. Primary key values must be unique, so MySQL refuses the duplicate entry.
  5. B An order_items table with one row per book per order, holding order_id, book_id and quantity: An order_items table holds one row per book in an order, with order_id and book_id foreign keys and a quantity. Each fact sits in its own row and can be counted and joined.
Lesson 1.2 · Installing MySQL
  1. C docker run ... mysql:9.7: The 9.7 tag pins the LTS series. latest, plain brew install mysql and distribution packages can each give you a different version.
  2. A The server is not running: 2002 and 2003 mean nothing answered. A stopped server is the usual reason; start it and try again.
  3. B It fails with error 1524, because the plugin is not loaded: mysql_native_password is removed in 9.x, so the statement fails with error 1524. Current phpMyAdmin and PHP support the default caching_sha2_password.
  4. A mysql -h 127.0.0.1 -P 3306 -u root -p: 127.0.0.1 forces a TCP connection to the published port. The name localhost makes the client look for a local socket file, which the container does not provide.
  5. C It is MariaDB: most SQL works, but some results and features differ from MySQL 9.7: XAMPP bundles MariaDB, a MySQL fork with its own version numbers. Basic SQL runs, but some features, messages and result orders differ from MySQL 9.7.

Opening: Reading the Room

There is no retrieval warm-up in Session 1. The opening's two checks have their answers above: the environment check output (what READY looks like) and the diagnostic D1 to D6. Learners who end the clinic still NOT READY leave with a numbered plan in their workbook's Start Here box.

Exit Ticket

  1. Server, client, database: the server (mysqld) stores the data, enforces the rules and answers SQL; a client (mysql, phpMyAdmin, Workbench) is what you type into and it sends your SQL to the server; a database is a named set of tables inside the server (preview_shop today, bookstore from Session 2).
  2. 2002 vs 1045: 2002 means nothing answered: check that the server is running (start command for your platform) and that you are asking the right place (Docker: -h 127.0.0.1 -P <port>). 1045 means the server answered and refused: check the user name and password (and -p).
  3. Keys: id is the primary key, customer_id the foreign key (it holds a customers.id). Storing the name in every order copies one fact many times; the copies drift apart (the order-sheet lab's three Alices).

Common Wrong Answers and What They Reveal

  • Q1 A ("MySQL is a database"). The everyday usage. Draw the three boxes again: one server, many databases inside.
  • Q4 B ("Kit gets id 4"). Expects MySQL to repair the input. A database refuses rather than guesses; that is the point of rules.
  • Q6 A or D (DROP TABLE / DELETE without WHERE). Mixes up removing rows with removing the table, or forgets that WHERE picks the rows. Both are destructive with no undo: worth a minute in the Session 2 warm-up.
  • Q7 D ("the client version proves the server version"). The most common misconception of the day. Exercise 1 of Lesson 1.2 is built on it.
  • Q8 B ("start the server" for 1045). Has not separated "no answer" from "answered and refused". Repeat the triage line.
  • Q11 B or D. Either localhost (socket, ignores the port) or the container's internal port. Draw the two ports: the laptop's 3307 leads to the container's 3306.
  • Exit ticket 1 with "client = phpMyAdmin only". Fine, but ask what they type into in the terminal: the mysql command is a client too.
