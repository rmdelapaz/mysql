Lessons

3.3

Aggregate Functions & GROUP BY

By the end you can
  • Summarize a table with COUNT, SUM, AVG, MIN and MAX, and predict how each one treats NULL
  • Produce one summary row per group with GROUP BY, sorted with ORDER BY
  • Keep or drop whole groups with HAVING, and explain when to use WHERE instead
  • Read and fix the errors MySQL raises for broken aggregate queries (1140, 1055, 1111)
  • Build a small inventory report as a reusable .sql script
Key ideas
  • An aggregate turns many rows into one value: COUNT, SUM, AVG, MIN, MAX.
  • COUNT(*) counts rows; COUNT(col) counts filled-in values; COUNT(DISTINCT col) counts different values.
  • Every aggregate skips NULL (except COUNT(*)). Over no rows, COUNT gives 0 and the others NULL.
  • AVG of a DECIMAL prints extra decimals: show money with ROUND(AVG(price), 2).
  • MIN and MAX give the value, not the row. To see the row, sort and LIMIT (or, after the break, a subquery).
  • GROUP BY makes piles; the aggregate runs once per pile. Every selected column is grouped or aggregated (1140, 1055).
  • WHERE picks rows before the piles; HAVING picks piles after. An aggregate in WHERE is 1111.
  • GROUP BY does not sort on MySQL 8.0 and later: always add ORDER BY.
Worked example: WHERE removes rows, HAVING removes piles

Three small summaries that show which clause does which job. First, one pile per author, kept only when the pile has more than one book, with the first and latest publication date of each kept pile:

SELECT author,
       COUNT(*)       AS books,
       MIN(published) AS first_book,
       MAX(published) AS latest_book
FROM books
GROUP BY author
HAVING COUNT(*) > 1;
+----------------+-------+------------+-------------+
| author         | books | first_book | latest_book |
+----------------+-------+------------+-------------+
| J.R.R. Tolkien |     2 | 1937-09-21 | 1954-07-29  |
+----------------+-------+------------+-------------+

Tolkien is the only author with two books. Now a condition on single rows: WHERE keeps the books over $10 BEFORE they are piled up, so the out-of-stock pile never forms (both out-of-stock books cost 8.99):

SELECT in_stock, COUNT(*) AS books_over_10
FROM books
WHERE price > 10
GROUP BY in_stock
ORDER BY in_stock DESC;
+----------+---------------+
| in_stock | books_over_10 |
+----------+---------------+
|        1 |             5 |
+----------+---------------+

And a condition on whole piles: every book goes into a pile, then HAVING drops the pile that is too small:

SELECT in_stock, COUNT(*) AS books
FROM books
GROUP BY in_stock
HAVING COUNT(*) > 5
ORDER BY in_stock DESC;
+----------+-------+
| in_stock | books |
+----------+-------+
|        1 |     8 |
+----------+-------+

Same table, two different missing rows, for two different reasons: WHERE removed rows, HAVING removed a pile.

3.4

Subqueries & Nested Queries

By the end you can
  • Compare every row with an aggregate using a scalar subquery ("above average", "equal to the maximum")
  • Filter with IN, NOT IN, ANY and ALL subqueries, and keep NULLs from emptying a NOT IN
  • Write correlated subqueries and EXISTS / NOT EXISTS checks that compare a row with related rows
  • Build derived tables in FROM and computed columns in SELECT
  • Read and fix the subquery errors 1242, 1241, 1248 and 1235
Key ideas
  • A subquery is a SELECT in parentheses inside another statement. The inner query answers first; read from the inside out.
  • Scalar subquery = one value: works with =, >, arithmetic and in the SELECT list. = with several rows is 1242.
  • A one-column list goes with IN, ANY, ALL. Two columns in the list is 1241.
  • One NULL in a NOT IN list empties the result. Add IS NOT NULL inside, or use NOT EXISTS.
  • Correlated = refers to the outer row. Alias both copies of the table and qualify every column inside.
  • EXISTS asks "is there at least one row?" SELECT 1 inside says the columns do not matter.
  • A derived table (subquery in FROM) needs an alias (1248) and allows a summary of a summary.
  • No LIMIT inside an IN subquery (1235): wrap it in a derived table.
Worked example: a correlated subquery in two runs

Build a correlated subquery in two runs: the latest customer to sign up in each city. Run 1, the inner query for ONE city, with the city typed in:

SELECT MAX(created_at) FROM customers WHERE city = 'Chicago';
+---------------------+
| MAX(created_at)     |
+---------------------+
| 2026-02-02 08:55:00 |
+---------------------+

It works for Chicago. Run 2: replace the typed city with the outer row's city, and give both copies of the table an alias so MySQL knows which one each column belongs to:

SELECT c.first_name, c.city, c.created_at
FROM customers AS c
WHERE c.created_at = (
    SELECT MAX(c2.created_at)
    FROM customers AS c2
    WHERE c2.city = c.city
)
ORDER BY c.city;
+------------+-------------+---------------------+
| first_name | city        | created_at          |
+------------+-------------+---------------------+
| Grace      | Chicago     | 2026-02-02 08:55:00 |
| Dave       | Houston     | 2026-01-12 16:25:00 |
| Carol      | Los Angeles | 2026-01-09 09:40:00 |
| Frank      | New York    | 2026-01-27 13:30:00 |
+------------+-------------+---------------------+

For every customer c, the inner query asks "what is the latest signup in c's city?", and the row is kept if it is c's own date. Grace is the latest in Chicago; Frank in New York. Eve and Hank never appear: their city is NULL, and NULL = NULL is not true.

Q12
This was meant to list the books priced above THEIR OWN author's average. Why does it return three books instead of one?
SELECT title, author, price
FROM books
WHERE price > (
    SELECT AVG(price)
    FROM books
    WHERE author = author
)
ORDER BY price;
A) The subquery runs once per author, but AVG ignores the out-of-stock books
B) MySQL treats the second author as a string literal
C) HAVING is missing from the subquery
D) Both author names refer to the inner table, so author = author is always true and the subquery returns the store average

Glossary

TermMeaning
aggregate functionCOUNT, SUM, AVG, MIN, MAX: many rows in, one value out
GROUP BYSorts rows into piles that share a value; the aggregates run once per pile
HAVINGKeeps or drops whole groups, after grouping (WHERE filters rows before)
ONLY_FULL_GROUP_BYMySQL's default rule: every selected column is grouped or aggregated (errors 1140, 1055)
COALESCE(a, b)The first value that is not NULL: a label for the NULL group, 0 instead of a NULL sum
subqueryA SELECT in parentheses inside another statement (the inner query)
scalar subqueryA subquery that returns exactly one value
correlated subqueryA subquery that refers to the outer query's current row; re-evaluated per row
EXISTS / NOT EXISTSTrue when the subquery returns at least one row / no row
derived tableA subquery in FROM, read like a table; it must have an alias
ANY / ALLCompare with a list: beats at least one item / beats every item
