Session 2: The MySQL Client and Your First Tables

How to teach the second session of MySQL Foundations. Learners get at home in the mysql client (finding their way around a server, the prompts, client commands, running .sql files, a look at phpMyAdmin), then stop exploring and build: the bookstore database and its first three tables from a script they can rerun, the habits of reading DESCRIBE after every change and of naming things well.

2 lessons 3 hrs session Lessons 1.3–2.1 Session 2 of 14 · Part 1

How to Use This Guide

  • Same rhythm for both lessons: frame (the goal and one mental model) → live demo (you type, they type along) → guided lab (a kit lab, new practice) → the lesson's own project. The lesson exercises, quiz and journal are homework.
  • Type, do not paste. Every SQL block below was run to produce the output printed under it, on MySQL 9.7.2 with the default settings. Ask for a prediction before every statement that prints something, and read error messages aloud from the left: the number, then the reason.
  • Keep lesson_03.html and lesson_04.html open in browser tabs for the diagrams and the phpMyAdmin tour. Labs live in labs/module-02/: _starter.sql files are handouts, _solution.sql files are yours.
  • Today is the day learners stop exploring and build: Lesson 2.1's project, create_bookstore.sql, is done in the room (all five steps), because Session 3 starts from its three empty tables. Lesson 1.3's project starts in the room and finishes at home.
  • Part 1 (Sessions 1 to 7) can run on its own. Teal blocks are hands-on, amber blocks are watch-outs. Lesson codes (1.3, 2.1) match the course site.
The #1 risk of Session 2: leaving without a bookstore

Session 3 begins with USE bookstore; and three empty tables. A learner who leaves today without them starts Session 3 by debugging a build script instead of learning data types. Protect the last 20 minutes before the wrap-up for create_bookstore.sql: every learner runs it twice and shows you the self-check table (books, categories, customers, all utf8mb4_unicode_ci). If the 2.1 demo runs long, cut demo Steps 10 to 12, never the project. The second risk is the machine that was NOT READY in Session 1: the warm-up checks it first.

Lesson Plans

1.3

MySQL CLI & phpMyAdmin

70 min
Objectives (from the lesson page)
  • Log in to and out of the mysql client, and read its prompts (mysql>, ->, '>)
  • Explore a server with SHOW DATABASES, USE, SHOW TABLES, DESCRIBE and SELECT DATABASE()
  • Tell SQL statements apart from client commands such as \G, \c, SOURCE and help
  • Save SQL in a .sql file and run it with SOURCE and with mysql < file.sql, knowing what MySQL 9.x's client does differently in scripts
  • Find the Structure, SQL, Import and Export tabs in phpMyAdmin and choose the right tool for a task
Timing in the room
10mFrame: one server, many clients; SQL statements versus client commands; the prompts
25mLive demo: find your way around, \G, two errors on purpose, SOURCE and the shell, phpMyAdmin
20mGuided lab: find_your_way_starter.sql in pairs
15mStart the lesson project: explore.sql, Steps 1 to 3
Mental model to say

Point at the three boxes from Session 1: "A client is any program that sends SQL to the server and shows you the answer: the mysql command, phpMyAdmin in a browser, Workbench. The server does not care which one you use: same statement, same result."

Then the two columns on the board: "Most of what you type is SQL, sent to the server: SHOW, USE, DESCRIBE, SELECT. A few things only the mysql program understands: backslash G, SOURCE, help, exit. Those are client commands; phpMyAdmin has never heard of them."

Then the prompts: "Nothing runs until the semicolon. The prompt tells you why the client is waiting: -> it wants the end of the statement, '> a quote is open. Backslash c gives up." Tie it to Session 1's missing-semicolon mistake.

Live demo (you type, they follow)

Log in on the projector (mysql -u root -p); learners log in too and type along. A fresh session has no current database. Ask for a prediction before every statement that prints something.

  1. A fresh server (2m). "Logged in, no database chosen yet. What is on this server?" Point at the four system databases: look, never change. 
    SHOW DATABASES;
    +--------------------+
| Database           |
+--------------------+
| information_schema |
| mysql              |
| performance_schema |
| sys                |
+--------------------+
  2. A database that is not there yet (1m). "Which database will we build today? Watch what happens if I go there now." Read the error from the left. 
    USE bookstore;
    ERROR 1049 (42000): Unknown database 'bookstore'
    1049 = no database by that name on this server: a typo, the wrong server, or (here) one you have not created. Lesson 2.1 fixes this at 1:40.
  3. USE, and where am I? (2m). "USE picks the drawer. SELECT DATABASE() answers 'where am I' at any time; before the first USE it says NULL." 
    USE mysql;
SELECT DATABASE();
    Database changed
+------------+
| DATABASE() |
+------------+
| mysql      |
+------------+
  4. What is in this drawer? (2m). "SHOW TABLES on its own lists 38 tables here; LIKE filters the names, % means anything." 
    SHOW TABLES LIKE 'help%';
    +-------------------------+
| Tables_in_mysql (help%) |
+-------------------------+
| help_category           |
| help_keyword            |
| help_relation           |
| help_topic              |
+-------------------------+
  5. What does one table look like? (2m). "DESCRIBE: one row per column. Read the Null, Key and Default columns aloud: NO means required, PRI is the primary key, UNI unique." 
    DESCRIBE help_category;
    +--------------------+-------------------+------+-----+---------+-------+
| Field              | Type              | Null | Key | Default | Extra |
+--------------------+-------------------+------+-----+---------+-------+
| help_category_id   | smallint unsigned | NO   | PRI | NULL    |       |
| name               | char(64)          | NO   | UNI | NULL    |       |
| parent_category_id | smallint unsigned | YES  |     | NULL    |       |
| url                | text              | NO   |     | NULL    |       |
+--------------------+-------------------+------+-----+---------+-------+
  6. Read some rows (2m). "Type it over several lines on purpose: nothing runs until the semicolon. Watch the prompt change to ->." 
    SELECT User, Host
FROM user
ORDER BY User, Host;
    +------------------+-----------+
| User             | Host      |
+------------------+-----------+
| mysql.infoschema | localhost |
| mysql.session    | localhost |
| mysql.sys        | localhost |
| root             | localhost |
+------------------+-----------+
    The three mysql.* accounts are internal and locked. Docker shows a second root with host %.
  7. A wide row, vertically (2m). "End with backslash G instead of the semicolon: one line per column. That is a client command, not SQL." 
    SELECT User, Host, plugin, account_locked
FROM user
WHERE User = 'root' AND Host = 'localhost'\G
    *************************** 1. row ***************************
          User: root
          Host: localhost
        plugin: caching_sha2_password
account_locked: N
  8. Looking in the wrong drawer (2m). "The error names the database it looked in. That is the hint: where am I?" 
    DESCRIBE customers;
    ERROR 1146 (42S02): Table 'mysql.customers' doesn't exist
  9. A reserved word as a name (2m). "1064 is the general 'I could not read this'; near '...' points at the spot. CURRENT_TIME is a built-in function." 
    SELECT NOW() AS current_time;
    ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'current_time' at line 1
  10. The fix: another name (1m). "Pick a name that is not a keyword (or use backticks)." 
    SELECT NOW() AS now_time, CURRENT_USER() AS logged_in_as;
    +---------------------+----------------+
| now_time            | logged_in_as   |
+---------------------+----------------+
| 2026-10-16 01:26:20 | root@localhost |
+---------------------+----------------+
    Your time differs, of course.
  11. Run a file: SOURCE and the shell (4m). Open hello.sql (the lesson's three-line script) in your editor next to the terminal. "At the prompt, SOURCE runs every statement in the file. From the shell, the file goes into mysql with <, in batch mode: plain tab-separated text, -t brings the boxes back." Show SOURCE ~/mysql-course/hello.sql, then exit and the two shell lines. 
    SOURCE ~/mysql-course/hello.sql
exit
mysql -u root -p < ~/mysql-course/hello.sql
mysql -t -u root -p < ~/mysql-course/hello.sql
    The lesson shows the outputs. Say the 9.x rule once: in a redirected file the client ignores its own commands (\G, SOURCE) unless started with --commands. PowerShell has no <: cmd /c "...".
  12. phpMyAdmin in two minutes (2m). If you have it (Docker http://localhost:8080): log in with the same root account, expand mysql > user in the navigation panel, show Browse (and the SELECT it ran above the grid), Structure, the SQL tab with the demo's SELECT, Import and Export. Point at the red Drop and Empty buttons. No phpMyAdmin: show the lesson's tour section instead.
Three mistakes to expect, and how to coach each
  • Typing the password after -p with a space. mysql -u root -p mypassword asks for the password and then fails with 1049 Unknown database 'mypassword'. Coach: "-p means 'ask me'. The next word is read as a database." (Self-check Q4.)
  • Looking for a table in the wrong database. 1146 names the database it looked in. Coach: "Read the name in the message. Where are you? SELECT DATABASE()."
  • SOURCE with the wrong path. Failed to open file almost always means the client was started in another folder, or Windows backslashes. Coach: forward slashes, and start the client in the course folder (or type the full path).

Start the lesson project

The lesson project is A Server Report Script: explore.sql, a short script that describes the server, run three ways. In the room: Steps 1 to 3 (15 minutes).

  • Step 1: the orientation query (USER, CURRENT_USER, DATABASE) at the prompt.
  • Step 2: the information_schema count per system database. Read GROUP BY as "count the rows for each database" (Lesson 3.3 teaches it).
  • Step 3: save the file in mysql-course with a header comment, every statement ending in ; and no \G.
  • Done in the room = explore.sql saved and run once with SOURCE without errors.
  • Goes home: Step 4 (run it from the shell, plain and with -t, and explain the difference) and Step 5 (phpMyAdmin's SQL tab, or DESCRIBE in the client).
Checks for understanding

Ask these out loud during the demo and the lab:

  • Is SHOW TABLES; SQL or a client command? Answer: SQL: phpMyAdmin can send it too.
  • The prompt shows ->. What do you type? Answer: ; and Enter (or \c to give up).
  • ERROR 1146 (42S02): Table 'mysql.customers' doesn't exist: what is the first thing you check? Answer: which database you are in (SELECT DATABASE();): the message says mysql.
  • Why does \G fail in mysql -u root -p < report.sql on 9.7 but not with SOURCE? Answer: a redirected file runs in batch mode, where the 9.x client ignores its own commands unless started with --commands.

Workbook self-check, items Q1 to Q6 (learners do them at the end of the block or at home).

Answers: Q1 C) SOURCE ~/mysql-course/hello.sql; Q2 B) A single quote is still open: close it, then type ;; Q3 5 (time_zone, time_zone_leap_second, time_zone_name, time_zone_transition, time_zone_transition_type); Q4 D) It asks for the password, then fails with ERROR 1049 (42000): Unknown database 'secret123'; Q5 A) mysql -u root -p < report.sql; Q6 B) SHOW COLUMNS FROM mysql.user LIKE '%lock%';. 2.1

Creating Databases & Tables

80 min
Objectives (from the lesson page)
  • Create, select and drop a database, with the utf8mb4 character set and an explicit collation
  • Write a CREATE TABLE statement with column names, data types and basic constraints
  • Inspect a table with SHOW TABLES, DESCRIBE and SHOW CREATE TABLE
  • Add, rename, change and remove columns with ALTER TABLE, without losing a constraint by accident
  • Rename, empty and drop tables, and use IF EXISTS / IF NOT EXISTS to write scripts you can rerun
  • Read and fix errors 1007, 1046, 1050, 1064 and 1146
Timing in the room
10mFrame: cabinet, drawer, folder; utf8mb4 and a named collation; naming conventions
30mLive demo: build bookstore and books, inspect, IF NOT EXISTS, ALTER and the MODIFY trap, three errors, drop it all
20mGuided lab: events_build_starter.sql
20mBuild the lesson project: create_bookstore.sql, Steps 1 to 5, run twice
Mental model to say

Draw the filing cabinet: "The server is the cabinet. Each database is a drawer: mostly a name and a few settings. Each table is a folder in the drawer, and the data lives in the tables." Point at the four system drawers from the 1.3 demo: "Today we add our own: bookstore."

Then the two settings: "The character set decides which characters can be stored: utf8mb4 is all of Unicode, emoji included. Never write utf8: in MySQL that means a three-byte subset. The collation decides comparing and sorting: is dune equal to Dune? We name utf8mb4_unicode_ci so MySQL 9.7, 8.4 and MariaDB sort the same way."

Then the habit that the whole lesson builds to: "Real databases are built from script files that start clean (DROP DATABASE IF EXISTS) and can run any number of times. If an experiment goes wrong in the next two sessions, your script puts everything back in a second." And the naming rules on one line: lowercase, snake_case, plural tables, id, customer_id, no reserved words.

Live demo (you type, they follow)

Type the lesson's statements live; learners type along. This builds a throwaway bookstore on the projector and drops it at the end (Step 13), so the project script after the lab starts from nothing for everyone.

  1. Create the database, named settings (3m). "A database is a drawer: a name and a few settings. utf8mb4 stores every character; the collation decides comparing and sorting. We name it so every server gives the same answers." 
    CREATE DATABASE bookstore
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;
SHOW CREATE DATABASE bookstore;
    +-----------+-------------------------------------------------------------------------------------------------------------------------------------+
| Database  | Create Database                                                                                                                     |
+-----------+-------------------------------------------------------------------------------------------------------------------------------------+
| bookstore | CREATE DATABASE `bookstore` /*!40100 DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci */ /*!80016 DEFAULT ENCRYPTION='N' */ |
+-----------+-------------------------------------------------------------------------------------------------------------------------------------+
    Point at utf8mb4_unicode_ci inside the versioned comment /*!40100 ... */.
  2. The same name again (1m). "Run it again." 
    CREATE DATABASE bookstore;
    ERROR 1007 (HY000): Can't create database 'bookstore'; database exists
    Fix: IF NOT EXISTS, or drop it first if you meant to start over.
  3. Go there (1m). "Where am I now?" 
    USE bookstore;
SELECT DATABASE();
    Database changed
+------------+
| DATABASE() |
+------------+
| bookstore  |
+------------+
  4. The first table (4m). Type it slowly; read each line as "name, type, rule". "Commas between the columns, none after the last. Types today on trust; Session 3 explains each one." 
    CREATE TABLE books (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    title       VARCHAR(200) NOT NULL,
    author      VARCHAR(100) NOT NULL,
    price       DECIMAL(8, 2) NOT NULL,
    pages       INT,
    published   DATE,
    in_stock    BOOLEAN DEFAULT TRUE
);
    Success prints only Query OK (0 rows affected): the table exists and is empty.
  5. Look at what MySQL stored (3m). "DESCRIBE is how you check your own work. Where did BOOLEAN go?" (tinyint(1), default 1.) 
    DESCRIBE books;
    +-----------+--------------+------+-----+---------+----------------+
| Field     | Type         | Null | Key | Default | Extra          |
+-----------+--------------+------+-----+---------+----------------+
| id        | int          | NO   | PRI | NULL    | auto_increment |
| title     | varchar(200) | NO   |     | NULL    |                |
| author    | varchar(100) | NO   |     | NULL    |                |
| price     | decimal(8,2) | NO   |     | NULL    |                |
| pages     | int          | YES  |     | NULL    |                |
| published | date         | YES  |     | NULL    |                |
| in_stock  | tinyint(1)   | YES  |     | 1       |                |
+-----------+--------------+------+-----+---------+----------------+
  6. IF NOT EXISTS keeps the old table (2m). "A smaller definition, IF NOT EXISTS. Did books lose five columns?" Ask for a prediction. 
    CREATE TABLE IF NOT EXISTS books (
    id INT PRIMARY KEY
);
SHOW WARNINGS;
    +-------+------+------------------------------+
| Level | Code | Message                      |
+-------+------+------------------------------+
| Note  | 1050 | Table 'books' already exists |
+-------+------+------------------------------+
    No: a Note, and books is untouched. IF NOT EXISTS never updates a table; ALTER TABLE does.
  7. ALTER TABLE: two new columns (3m). "ALTER changes the structure and keeps the rows. AFTER places a column; a DEFAULT fills existing rows." 
    ALTER TABLE books
    ADD COLUMN isbn CHAR(13) AFTER id,
    ADD COLUMN language VARCHAR(30) DEFAULT 'English';
DESCRIBE books;
    +-----------+--------------+------+-----+---------+----------------+
| Field     | Type         | Null | Key | Default | Extra          |
+-----------+--------------+------+-----+---------+----------------+
| id        | int          | NO   | PRI | NULL    | auto_increment |
| isbn      | char(13)     | YES  |     | NULL    |                |
| title     | varchar(200) | NO   |     | NULL    |                |
| author    | varchar(100) | NO   |     | NULL    |                |
| price     | decimal(8,2) | NO   |     | NULL    |                |
| pages     | int          | YES  |     | NULL    |                |
| published | date         | YES  |     | NULL    |                |
| in_stock  | tinyint(1)   | YES  |     | 1       |                |
| language  | varchar(30)  | YES  |     | English |                |
+-----------+--------------+------+-----+---------+----------------+
  8. The silent trap (3m). "I only want longer titles." Type the MODIFY without NOT NULL; ask the room what DESCRIBE will say before you run the check. 
    ALTER TABLE books MODIFY COLUMN title VARCHAR(250);
SHOW COLUMNS FROM books LIKE 'title';
    +-------+--------------+------+-----+---------+-------+
| Field | Type         | Null | Key | Default | Extra |
+-------+--------------+------+-----+---------+-------+
| title | varchar(250) | YES  |     | NULL    |       |
+-------+--------------+------+-----+---------+-------+
    No error, no warning, and title now allows NULL. MODIFY (and CHANGE) replace the WHOLE definition: repeat every rule.
  9. Put it back, in one statement (2m). "Several changes, commas between them; MySQL rebuilds the table once." 
    ALTER TABLE books
    MODIFY COLUMN title VARCHAR(200) NOT NULL,
    DROP COLUMN isbn,
    DROP COLUMN language;
SHOW COLUMNS FROM books LIKE 'title';
    +-------+--------------+------+-----+---------+-------+
| Field | Type         | Null | Key | Default | Extra |
+-------+--------------+------+-----+---------+-------+
| title | varchar(200) | NO   |     | NULL    |       |
+-------+--------------+------+-----+---------+-------+
  10. A reserved word as a table name (2m). "A table for orders, named order." 
    CREATE TABLE order (
    id INT AUTO_INCREMENT PRIMARY KEY
);
    ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'order (
    id INT AUTO_INCREMENT PRIMARY KEY
)' at line 1
    ORDER is a keyword (ORDER BY). The naming rule: tables are plural nouns, so orders.
  11. A misspelled table (1m). "The table is books, plural." 
    DESCRIBE book;
    ERROR 1146 (42S02): Table 'bookstore.book' doesn't exist
    The message names the database too: bookstore.book.
  12. Copy, rename, look (2m). "LIKE copies the structure and none of the rows: the safe way to practice destructive commands." 
    CREATE TABLE books_copy LIKE books;
RENAME TABLE books_copy TO old_books;
SHOW TABLES;
    +---------------------+
| Tables_in_bookstore |
+---------------------+
| books               |
| old_books           |
+---------------------+
  13. Drop it all (3m). "DROP has no undo. Read the name twice. And after dropping the database you were in, where are you?" 
    DROP TABLE old_books;
DROP DATABASE bookstore;
SELECT DATABASE();
    +------------+
| DATABASE() |
+------------+
| NULL       |
+------------+
    NULL: no current database, so the next CREATE TABLE would fail with 1046. Now everybody builds the real bookstore from a script.
Three mistakes to expect, and how to coach each
  • A comma after the last column, or a missing one between two. Both give 1064, near ) or near the next column's name. Coach: "Read the near '...' part: the mistake is just before it."
  • MODIFY (or CHANGE) without the old rules. No error; NOT NULL or a DEFAULT silently disappears. Coach: "After every ALTER, DESCRIBE. Is Null still NO?" (Self-check Q11, exit ticket 3.)
  • 1046 after DROP DATABASE. Learners drop the database they were in and the next CREATE TABLE fails. Coach: "Where are you? SELECT DATABASE() says NULL: USE one, or write database.table."

Checks for understanding

Ask these out loud during the demo and the lab:

  • Why name the collation if utf8mb4 is already the default? Answer: the default collation differs between servers (9.7/8.4 utf8mb4_0900_ai_ci, MariaDB utf8mb4_uca1400_ai_ci); naming one makes every server sort the same way.
  • CREATE TABLE IF NOT EXISTS books (id INT PRIMARY KEY); on the existing seven-column books: what happens? Answer: nothing changes; a Note 1050.
  • TRUNCATE or DELETE: which one starts the ids at 1 again? Answer: TRUNCATE.
  • Why does create_bookstore.sql start with DROP DATABASE IF EXISTS bookstore;? Answer: so it can run any number of times from any state; only on a practice database.

Workbook self-check, items Q7 to Q12 (learners do them at the end of the block or at home).

Answers: Q7 D) The database is created with utf8mb3 (no emoji), and warning 3719 says to use utf8mb4; Q8 email (then id and name); Q9 A) There is no current database: run USE first, or write database.table; Q10 C) book_reviews; Q11 B) The column is now book_title, VARCHAR(250), and allows NULL; Q12 TRUNCATE TABLE customers;. Closing

Exit ticket (3 questions, no notes, 4 minutes)

Put the three questions on the slide; learners answer in the workbook's Exit Ticket box or on a sticky note. Sort them before Session 3: question 3's "not yet" pile gets a minute of DESCRIBE in the Session 3 warm-up.

  1. Name two statements that work in phpMyAdmin's SQL tab and one command that only the mysql client understands. Answer: SQL (any client): SHOW TABLES;, DESCRIBE books;, USE bookstore;, SELECT DATABASE();, CREATE TABLE .... Client only: \G, SOURCE file.sql, \c, help, exit, status.
  2. A script stops with ERROR 1046 (3D000): No database selected. Give two ways to fix it. Answer: Put USE bookstore; (the right database) before the statement, or write the full name bookstore.books. It happens in a fresh session and after dropping the database you were in.
  3. title is VARCHAR(200) NOT NULL. You run ALTER TABLE books MODIFY COLUMN title VARCHAR(250);. What did you lose, and which statement shows it? Answer: The NOT NULL rule: MODIFY replaces the whole definition. DESCRIBE books; (or SHOW COLUMNS FROM books LIKE 'title';) shows YES under Null. Fix: repeat it, VARCHAR(250) NOT NULL.
