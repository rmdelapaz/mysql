Session 2 12 self-check items Confidential

Warm-Up: Session 1

Not graded. Each reason says where the idea came from in Session 1.

W1
Is MySQL a database?
A) Yes: MySQL is the file that holds your tables
B) No: MySQL is the server (a DBMS); a database such as bookstore lives inside it
C) No: MySQL is a query language
D) Yes: every MySQL install is one database
Why: MySQL is the server software; one server holds many databases. Session 1's exit ticket question 1.
W2
Which error tells you the server is running and answered?
A) ERROR 2002
B) ERROR 2003
C) ERROR 1045 (28000): Access denied
D) None of them
Why: 1045 means the server answered and refused the credentials; 2002 and 2003 mean nothing answered.
W3
What does the SELECT print?
CREATE TABLE pets (id INT PRIMARY KEY, name VARCHAR(20));
INSERT INTO pets VALUES (1, 'Rex'), (2, 'Tom'), (3, 'Fido');
DELETE FROM pets WHERE id = 2;
SELECT * FROM pets;
A) Rows 1 Rex and 3 Fido
B) Rows 1 Rex and 2 Fido: the ids are renumbered
C) All three rows
D) Empty set
Why: DELETE removes only the row whose id is 2; ids are never renumbered. MySQL prints:
+----+------+
| id | name |
+----+------+
|  1 | Rex  |
|  3 | Fido |
+----+------+
W4
Which statement removes Carol's row (id 3) and keeps every other customer?
A) DROP TABLE customers;
B) DELETE FROM customers;
C) DELETE FROM customers WHERE id = 3;
D) UPDATE customers SET id = NULL WHERE id = 3;
Why: DELETE with a WHERE removes the rows the WHERE picks. Without WHERE every row goes; DROP TABLE removes the table.
W5
mysql --version prints 9.7.2. What does that prove about your server?
A) That it is 9.7.2
B) That it is running
C) That it is MySQL, not MariaDB
D) Nothing: it describes the client; ask the server with SELECT VERSION();
Why: The client and the server are different programs. Only a query sent after logging in describes the server.

1.3 · MySQL CLI & phpMyAdmin: self-check

Q1
Which of these does nothing in phpMyAdmin's SQL tab, because only the mysql command-line client understands it?
A) SHOW DATABASES;
B) DESCRIBE user;
C) SOURCE ~/mysql-course/hello.sql
D) SELECT DATABASE();
Why: SOURCE (like \G, \c, help and exit) is a client command: the mysql program handles it itself and never sends it to the server. phpMyAdmin has its own Import tab for files.
A is wrong: SHOW DATABASES is SQL (a MySQL addition to the standard): every client can send it.
B is wrong: DESCRIBE is SQL too; phpMyAdmin also shows it as the Structure tab.
D is wrong: A SELECT is plain SQL and works in any client.
Q2
You press Enter and the prompt changes from mysql> to '>. What does it mean?
A) The statement only needs a semicolon
B) A single quote is still open: close it, then type ;
C) The server is still running the query
D) You were logged out
Why: The client shows '> while a text value in single quotes is unfinished. Close the quote, then end the statement with a semicolon (or \c after closing the quote to throw it away).
A is wrong: That prompt is ->; inside an open quote a semicolon is just part of the text.
C is wrong: Nothing has been sent yet: the statement is not finished.
D is wrong: Logging out prints Bye and returns you to the shell.
Q3
On MySQL 9.7, how many rows does this print?
SHOW TABLES FROM mysql LIKE 'time_zone%';
5 (time_zone, time_zone_leap_second, time_zone_name, time_zone_transition, time_zone_transition_type)
Why: SHOW TABLES FROM lists another database's tables without switching to it, and LIKE filters the names: % means any characters. The mysql database keeps five time-zone tables.
Q4
You type mysql -u root -p secret123 (with a space after -p). What happens?
A) It logs in with the password secret123
B) ERROR 1045 (28000): Access denied
C) It logs in without asking for a password
D) It asks for the password, then fails with ERROR 1049 (42000): Unknown database 'secret123'
Why: -p on its own means "ask me"; the word after the space is read as the database to start in. Type the password at the prompt instead (the lesson's warning box).
A is wrong: Only -psecret123 (no space) would pass it, and that leaves it in your shell history.
B is wrong: The password typed at the prompt can be right; the failure is the unknown database.
C is wrong: -p always makes the client ask.
Q5
report.sql ends its query with \G. Which way of running it stops with Unknown command on MySQL 9.7?
A) mysql -u root -p < report.sql
B) SOURCE report.sql at the mysql> prompt
C) mysql --commands -u root -p < report.sql
D) Typing the query at the prompt
Why: Read from a redirected file, the 9.x client is in batch mode and ignores its own commands unless started with --commands. At the prompt, typed or SOURCEd, client commands always work.
B is wrong: SOURCE runs the file as if you typed it: client commands work.
C is wrong: --commands switches client commands back on in batch mode.
D is wrong: Interactive use is not affected.
Q6
Which statement lists only the columns of mysql.user whose names contain lock?
A) SHOW TABLES FROM mysql LIKE '%lock%';
B) SHOW COLUMNS FROM mysql.user LIKE '%lock%';
C) DESCRIBE mysql.user WHERE lock;
D) SELECT lock FROM mysql.user;
Why: SHOW COLUMNS FROM table LIKE 'pattern' is DESCRIBE with a filter. On 9.7 it prints two columns: Lock_tables_priv and account_locked (LIKE ignores case).
A is wrong: That lists tables, not columns.
C is wrong: DESCRIBE takes no WHERE: a syntax error.
D is wrong: There is no column named lock: ERROR 1054.

1.3 · MySQL CLI & phpMyAdmin: predict, then run

P1
Predict the output, then run it.
SELECT DATABASE() AS before_use;
USE mysql;
SELECT DATABASE() AS after_use;
+------------+
| before_use |
+------------+
| NULL       |
+------------+
Database changed
+-----------+
| after_use |
+-----------+
| mysql     |
+-----------+
Why: Before the first USE a session has no current database, so DATABASE() is NULL. USE mysql; prints Database changed, and from then on it is mysql.
P2
Predict the output, then run it.
SHOW COLUMNS FROM mysql.user LIKE 'account_locked';
+----------------+---------------+------+-----+---------+-------+
| Field          | Type          | Null | Key | Default | Extra |
+----------------+---------------+------+-----+---------+-------+
| account_locked | enum('N','Y') | NO   |     | N       |       |
+----------------+---------------+------+-----+---------+-------+
Why: account_locked is an ENUM of two letters, required, N by default: new accounts are unlocked unless you lock them.

2.1 · Creating Databases & Tables: self-check

Q7
What happens when this runs?
CREATE DATABASE kit_q7 CHARACTER SET utf8;
SHOW WARNINGS;
A) ERROR 1064: utf8 is not a character set
B) The database stores full Unicode, emoji included
C) Nothing: CHARACTER SET is ignored
D) The database is created with utf8mb3 (no emoji), and warning 3719 says to use utf8mb4
Why: MySQL's utf8 is an alias for the three-byte utf8mb3, which cannot store emoji and some rarer characters. The statement works and warns; always write utf8mb4.
A is wrong: utf8 is accepted, with a warning.
B is wrong: Only utf8mb4 stores every character.
C is wrong: It is used: the database gets utf8mb3.
Q8
Which column does the last statement list first?
CREATE TABLE members (
    id   INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(40) NOT NULL
);
ALTER TABLE members ADD COLUMN email VARCHAR(100) FIRST;
SHOW COLUMNS FROM members;
email (then id and name)
Why: ADD COLUMN puts a new column at the end unless you say AFTER column or FIRST. FIRST makes email the first column; existing rows would get NULL in it.
Q9
A script stops with ERROR 1046 (3D000): No database selected. What does it mean?
A) There is no current database: run USE first, or write database.table
B) The database name is misspelled
C) The table already exists
D) Your account may not create tables
Why: A fresh session, or one whose current database was just dropped, has no current database, so a bare table name has nowhere to go.
B is wrong: A misspelled database gives 1049 Unknown database.
C is wrong: That is 1050.
D is wrong: Permission errors are 1044 or 1142 (Lesson 7.4).
Q10
Which name follows the course's naming conventions for a table of book reviews?
A) BookReviews
B) tbl_review
C) book_reviews
D) bookReview
Why: Lowercase, snake_case, a plural noun. Lowercase also keeps the name working when the database moves to a Linux server, where table names are case-sensitive.
A is wrong: Capitals can break on Linux servers.
B is wrong: No tbl_ prefix, and tables are plural.
D is wrong: camelCase and singular.
Q11
In shelf, title was VARCHAR(200) NOT NULL. After the ALTER below, what is true?
CREATE TABLE shelf (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(200) NOT NULL
);
ALTER TABLE shelf CHANGE COLUMN title book_title VARCHAR(250);
SHOW COLUMNS FROM shelf;
A) The column is now book_title and is still required
B) The column is now book_title, VARCHAR(250), and allows NULL
C) ERROR: CHANGE cannot rename a column
D) title is kept and a new column book_title is added
Why: CHANGE takes the old name, the new name and the FULL new definition. Whatever is left out, here NOT NULL, is gone: SHOW COLUMNS prints YES under Null. Repeat every constraint, then check.
A is wrong: Only a definition that says NOT NULL keeps it.
C is wrong: Renaming plus redefining is exactly what CHANGE is for.
D is wrong: CHANGE replaces the column; ADD COLUMN would add one.
Q12
Write the one statement that removes every row of the customers table, keeps the table and starts the ids at 1 again.
TRUNCATE TABLE customers;
Why: TRUNCATE empties the table and resets AUTO_INCREMENT. DELETE FROM customers; also removes every row but keeps counting ids; DROP TABLE removes the table itself.

2.1 · Creating Databases & Tables: predict, then run

P3
Predict the output, then run it.
CREATE TABLE tickets (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    label VARCHAR(20) NOT NULL
);
INSERT INTO tickets (label) VALUES ('first'), ('second');
TRUNCATE TABLE tickets;
INSERT INTO tickets (label) VALUES ('third');
SELECT * FROM tickets;
+----+-------+
| id | label |
+----+-------+
|  1 | third |
+----+-------+
Why: TRUNCATE removed both rows AND reset the AUTO_INCREMENT counter, so the next row gets id 1. A DELETE FROM tickets would have given id 3.
P4
Predict the output, then run it.
CREATE TABLE notes (
    id    INT PRIMARY KEY,
    body  VARCHAR(100) NOT NULL
);
ALTER TABLE notes MODIFY COLUMN body TEXT;
SHOW COLUMNS FROM notes LIKE 'body';
+-------+------+------+-----+---------+-------+
| Field | Type | Null | Key | Default | Extra |
+-------+------+------+-----+---------+-------+
| body  | text | YES  |     | NULL    |       |
+-------+------+------+-----+---------+-------+
Why: MODIFY replaced the whole definition with TEXT alone, so NOT NULL is gone: Null says YES. Write MODIFY COLUMN body TEXT NOT NULL to keep the rule.

The Lesson Pages' Own Quick Quizzes

Lesson 1.3 · MySQL CLI & phpMyAdmin
  1. A The statement has no semicolon yet, so the client is waiting for more: The client sends a statement only when it sees the terminator. The arrow prompt means it is waiting for the rest; type a semicolon.
  2. B ERROR 1146: Table 'mysql.customers' doesn't exist: MySQL looks for the table in the current database, mysql, and reports the full name it tried: Table 'mysql.customers' doesn't exist.
  3. C \G at the end of a query: Backslash commands such as \G are handled by the mysql client itself and never reach the server, so other tools do not understand them.
  4. B ERROR 1064, because current_time is a reserved word: CURRENT_TIME is a reserved word (a built-in function), so it cannot be a plain alias. Rename it (now_time) or wrap it in backticks.
  5. A End the statements with ; instead of \G (or run the client with --commands): In batch mode the 9.x client ignores its own commands. Ending statements with semicolons makes the file work everywhere; --commands is the alternative.
Lesson 2.1 · Creating Databases & Tables
  1. C Nothing changes; MySQL reports a note and keeps the existing table: IF NOT EXISTS turns the error into a note (1050) and leaves the existing table and its rows exactly as they were. The new definition is ignored.
  2. A SHOW CREATE TABLE books;: SHOW CREATE TABLE prints the exact CREATE TABLE statement that would rebuild the table, with every constraint, the engine and the character set and collation.
  3. B title is VARCHAR(250) and now allows NULL: MODIFY replaces the whole column definition with exactly what you typed. NOT NULL was not repeated, so title now accepts NULL, without any warning.
  4. A A table with one row, id 1: TRUNCATE removes every row and resets the AUTO_INCREMENT counter, so the next row gets id 1. The table itself, with its columns and keys, stays.
  5. C MySQL's utf8 is a three-byte subset that cannot store every character: In MySQL, utf8 means utf8mb3, a three-byte subset that cannot store emoji and some rarer characters, and MySQL warns about it (warning 3719). utf8mb4 is full Unicode.

Exit Ticket

  1. Name two statements that work in phpMyAdmin's SQL tab and one command that only the mysql client understands. Answer: SQL (any client): SHOW TABLES;, DESCRIBE books;, USE bookstore;, SELECT DATABASE();, CREATE TABLE .... Client only: \G, SOURCE file.sql, \c, help, exit, status.
  2. A script stops with ERROR 1046 (3D000): No database selected. Give two ways to fix it. Answer: Put USE bookstore; (the right database) before the statement, or write the full name bookstore.books. It happens in a fresh session and after dropping the database you were in.
  3. title is VARCHAR(200) NOT NULL. You run ALTER TABLE books MODIFY COLUMN title VARCHAR(250);. What did you lose, and which statement shows it? Answer: The NOT NULL rule: MODIFY replaces the whole definition. DESCRIBE books; (or SHOW COLUMNS FROM books LIKE 'title';) shows YES under Null. Fix: repeat it, VARCHAR(250) NOT NULL.

Common Wrong Answers and What They Reveal

  • Q1 B ("DESCRIBE does nothing in phpMyAdmin"). Thinks only SELECT is SQL. Show the Structure tab and the SQL tab running DESCRIBE.
  • Q2 A ("it only needs a semicolon"). Has not seen the quote prompt. Type SELECT 'abc; live: the semicolon becomes part of the text.
  • Q4 B (1045). Reads every login failure as a password problem. The message says Unknown database: read the message.
  • Q7 B ("utf8 stores emoji"). The most expensive misconception of the day: a database created with utf8 loses emoji years later. Repeat: always utf8mb4.
  • Q9 B ("misspelled database"). Mixes 1046 with 1049. Write the pair on the board: 1049 = no database by that name; 1046 = no database chosen.
  • Q11 A ("still required"). Expects ALTER to keep what it is not told. The MODIFY trap from the demo; the exit ticket's question 3.
  • Exit ticket 2 answered with "create the database". Needs the cabinet picture: the database exists, the session is just not inside it.
