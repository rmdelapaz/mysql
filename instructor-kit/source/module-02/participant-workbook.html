Lessons

1.3

MySQL CLI & phpMyAdmin

By the end you can
  • Log in to and out of the mysql client, and read its prompts (mysql>, ->, '>)
  • Explore a server with SHOW DATABASES, USE, SHOW TABLES, DESCRIBE and SELECT DATABASE()
  • Tell SQL statements apart from client commands such as \G, \c, SOURCE and help
  • Save SQL in a .sql file and run it with SOURCE and with mysql < file.sql, knowing what MySQL 9.x's client does differently in scripts
  • Find the Structure, SQL, Import and Export tabs in phpMyAdmin and choose the right tool for a task
Key ideas
  • A client is any program that sends SQL to the server: the mysql command, phpMyAdmin, Workbench. Same statement, same result in all of them.
  • Log in with mysql -u root -p (no space and no password after -p); leave with exit, \q or Ctrl+D. Ctrl+C cancels a statement; it does not log you out.
  • Find your way: SHOW DATABASES; · USE name; · SELECT DATABASE(); · SHOW TABLES; · DESCRIBE table;. FROM database and database.table reach other databases without moving.
  • Nothing runs until the semicolon. -> = waiting for the end · '> = a quote is open · \c = give up.
  • SQL versus client commands: SHOW, USE, DESCRIBE work in every client; \G (vertical output), \c, SOURCE, help, status, exit only in the mysql client.
  • Run files with SOURCE path at the prompt or mysql -u root -p < file.sql from the shell (batch mode: no boxes without -t; MySQL 9.x ignores client commands there unless you add --commands).
  • Errors to know: 1049 unknown database · 1146 table not found (the message names the database it looked in) · 1064 cannot read the statement (often a reserved word such as current_time).
Worked example: exploring without moving

You can explore without moving: in a fresh session there is no current database, and a full name database.table (or FROM database) reaches any table.

SELECT DATABASE() AS current_db;

+------------+
| NULL       |
+------------+

2.1

Creating Databases & Tables

By the end you can
  • Create, select and drop a database, with the utf8mb4 character set and an explicit collation
  • Write a CREATE TABLE statement with column names, data types and basic constraints
  • Inspect a table with SHOW TABLES, DESCRIBE and SHOW CREATE TABLE
  • Add, rename, change and remove columns with ALTER TABLE, without losing a constraint by accident
  • Rename, empty and drop tables, and use IF EXISTS / IF NOT EXISTS to write scripts you can rerun
  • Read and fix errors 1007, 1046, 1050, 1064 and 1146
Key ideas
  • Server = cabinet, database = drawer, table = folder. CREATE DATABASE, USE, DROP DATABASE (no undo).
  • Name the text settings: CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci. Never utf8 (a three-byte subset, warning 3719).
  • Names: lowercase, snake_case, plural tables (books), id for the key, customer_id for a link, no reserved words (order).
  • CREATE TABLE lists each column's name, type and rules; commas between columns, none after the last. IF NOT EXISTS leaves an existing table untouched (Note 1050).
  • Inspect: DESCRIBE t; for the columns, SHOW CREATE TABLE t\G for the full definition (engine, charset, collation).
  • ALTER TABLE adds, renames, redefines and drops columns and keeps the rows. MODIFY and CHANGE replace the whole definition: repeat NOT NULL and DEFAULT, then DESCRIBE.
  • TRUNCATE empties a table and resets AUTO_INCREMENT; DROP removes the table or database itself.
  • Build from a script that starts with DROP DATABASE IF EXISTS and can run any number of times. Errors: 1007/1050 exists · 1046 no database selected · 1064 · 1146.
Worked example: a build script for a recipe box

A build script for a recipe box, from nothing: the same shape as create_bookstore.sql, on another subject.

DROP DATABASE IF EXISTS kit_recipes;
CREATE DATABASE kit_recipes
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;
USE kit_recipes;
CREATE TABLE recipes (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    name        VARCHAR(100) NOT NULL UNIQUE,
    minutes     INT,
    vegetarian  BOOLEAN DEFAULT FALSE,
    added_on    DATE
);
SHOW TABLES;
Database changed
+-----------------------+
| Tables_in_kit_recipes |
+-----------------------+
| recipes               |
+-----------------------+

Check what MySQL stored. BOOLEAN became tinyint(1) and FALSE became 0:

DESCRIBE recipes;
+------------+--------------+------+-----+---------+----------------+
| Field      | Type         | Null | Key | Default | Extra          |
+------------+--------------+------+-----+---------+----------------+
| id         | int          | NO   | PRI | NULL    | auto_increment |
| name       | varchar(100) | NO   | UNI | NULL    |                |
| minutes    | int          | YES  |     | NULL    |                |
| vegetarian | tinyint(1)   | YES  |     | 0       |                |
| added_on   | date         | YES  |     | NULL    |                |
+------------+--------------+------+-----+---------+----------------+

The full definition, vertically: the UNIQUE KEY MySQL built for name, the InnoDB engine, and the collation inherited from the database:

SHOW CREATE TABLE recipes\G
*************************** 1. row ***************************
       Table: recipes
Create Table: CREATE TABLE `recipes` (
  `id` int NOT NULL AUTO_INCREMENT,
  `name` varchar(100) COLLATE utf8mb4_unicode_ci NOT NULL,
  `minutes` int DEFAULT NULL,
  `vegetarian` tinyint(1) DEFAULT '0',
  `added_on` date DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci

Clean up (the recipe box was practice):

DROP DATABASE kit_recipes;

Glossary

TermMeaning
clientA program that sends SQL to the server and shows the answer (mysql, phpMyAdmin, Workbench)
client commandSomething only the mysql program understands (\G, \c, SOURCE, help, exit); never sent to the server
promptmysql> ready · -> statement not finished · '> quote open
current databaseThe one USE selected; SELECT DATABASE(); shows it (NULL if none)
information_schemaRead-only system database that describes every database, table and column ("data about data")
batch modeThe client reading a file from the shell (mysql < file.sql): plain text output, no client commands in 9.x
character setWhich characters can be stored; always utf8mb4
collationHow text is compared and sorted; _ci = case-insensitive (utf8mb4_unicode_ci)
constraintA rule on a column: PRIMARY KEY, NOT NULL, UNIQUE, DEFAULT (Lesson 2.2 adds CHECK)
ALTER TABLEChanges a table's structure and keeps its rows (ADD, RENAME, MODIFY, CHANGE, DROP COLUMN)
TRUNCATERemoves every row, keeps the table, resets AUTO_INCREMENT
build scriptA .sql file that rebuilds a database from nothing and can run any number of times
