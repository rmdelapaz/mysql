Refresher answers (W1 to W5)
  1. W1 Which customers have never placed an order? Say the query shape, then the names. Answer: A LEFT JOIN from customers to orders, keeping the customers whose orders side is NULL (or HAVING COUNT(o.id) = 0): Carol and Hank. Lesson 4.3, the anti-join.
  2. W2 employees has a manager_id. How do you show each employee next to their manager's name? Who is Sofia's manager? Answer: A self-join: the table twice with two aliases, ON m.id = e.manager_id. Sofia (id 7) reports to Marcus.
  3. W3 SELECT a.name, COUNT(*) FROM authors a LEFT JOIN books b ON b.author_id = a.id GROUP BY a.id, a.name: what does it say for Isaac Asimov, who has no books, and how do you fix it? Answer: 1, because COUNT(*) counts the NULL-padded row the LEFT JOIN made. Count a column of the right table, COUNT(b.id), which skips NULL: 0. (Lesson 4.3, Common Mistake 4.)
  4. W4 Books per author and copies sold in one query: Orwell shows 5 books, but he wrote 2. What happened? Answer: Fan-out: joining order_items repeats each book once per order line. COUNT(DISTINCT b.id) fixes it. Ask what one row of the join stands for. (Lesson 4.3, Common Mistake 5.)
  5. W5 A subquery in FROM (a derived table) fails with error 1248. What is missing? Answer: An alias: every derived table needs its own name, ( ... ) AS t (Lesson 3.4). Today's CTEs give such steps a name up front, and read top to bottom.

The key shows W1 and W2's real output. labs/module-08/l5_0-part2-start/refresher_starter.sql practices the same four moves (an inner join, LEFT JOIN with COUNT, a derived table, a self-join): hand it to anyone who missed two or more.

CTEs & Recursive Queries

Mental model to say

Point at the three boxes on the board: "A real question takes steps. Total each customer's orders. Average those totals. Keep the customers above it. Until now you nested the steps inside each other and read them inside out. A CTE writes each step once, gives it a name, and lists the steps top to bottom, like a recipe. The name lives for one statement."

Then recursion, with the number series drawn as rounds: "A recursive CTE has an anchor that runs once and makes the starting rows, and a recursive member that runs again and again, each time reading only the rows the last round made. When a round makes no rows, it stops: that is the stop condition. It is how you follow a chain whose length you do not know: managers above managers, months until July."

The two directions of a hierarchy, as two arrows on the board: down = e.manager_id = cte.id ("whose manager is this?"), up = e.id = cte.manager_id ("who is this person's manager?").

Live demo (you type, they follow)

The lesson's own examples, typed live on the freshly loaded bookstore. Learners type along on their own machines; the long queries can be pasted from the lesson page by anyone who falls behind.

  1. The question, inside out (2m). "Which customers spent more than the average customer? Three steps: total each customer, average the totals, keep the ones above. With Lesson 3.4's derived tables it looks like this." Scroll it slowly; ask where to start reading (the middle) and point at the total-per-customer step written twice. 
    SELECT t.customer, t.total
FROM (
    SELECT c.first_name AS customer,
           SUM(oi.quantity * oi.price_at_time) AS total
    FROM customers c
    JOIN orders o       ON o.customer_id = c.id
    JOIN order_items oi ON oi.order_id = o.id
    GROUP BY c.id, c.first_name
) AS t
WHERE t.total > (
    SELECT AVG(t2.total)
    FROM (
        SELECT SUM(oi.quantity * oi.price_at_time) AS total
        FROM orders o
        JOIN order_items oi ON oi.order_id = o.id
        GROUP BY o.customer_id
    ) AS t2
)
ORDER BY t.total DESC;
    +----------+-------+
| customer | total |
+----------+-------+
| Alice    | 58.95 |
| Dave     | 45.96 |
| Frank    | 41.96 |
+----------+-------+
  2. The same question, top to bottom (3m). "Name the step once, up front, with WITH. Now it reads like a recipe: here is customer_totals; show the ones above its average." Same three rows: Alice, Dave, Frank. 
    WITH customer_totals AS (
    SELECT c.first_name AS customer,
           SUM(oi.quantity * oi.price_at_time) AS total
    FROM customers c
    JOIN orders o       ON o.customer_id = c.id
    JOIN order_items oi ON oi.order_id = o.id
    GROUP BY c.id, c.first_name
)
SELECT customer, total
FROM customer_totals
WHERE total > (SELECT AVG(total) FROM customer_totals)
ORDER BY total DESC;
    +----------+-------+
| customer | total |
+----------+-------+
| Alice    | 58.95 |
| Dave     | 45.96 |
| Frank    | 41.96 |
+----------+-------+
    Average of the six customers who ordered: about 39.55 (Carol and Hank never ordered, so the inner joins leave them out).
  3. Two steps, one WITH (2m). "One WITH, several CTEs, separated by commas. The second reads the first. average has one row, so CROSS JOIN attaches it to every customer." 
    WITH customer_totals AS (
    SELECT o.customer_id,
           SUM(oi.quantity * oi.price_at_time) AS total
    FROM orders o
    JOIN order_items oi ON oi.order_id = o.id
    GROUP BY o.customer_id
),
average AS (
    SELECT AVG(total) AS avg_total
    FROM customer_totals
)
SELECT c.first_name, c.last_name, t.total,
       ROUND(t.total - a.avg_total, 2) AS above_average
FROM customer_totals t
JOIN customers c ON c.id = t.customer_id
CROSS JOIN average a
WHERE t.total > a.avg_total
ORDER BY t.total DESC;
    +------------+-----------+-------+---------------+
| first_name | last_name | total | above_average |
+------------+-----------+-------+---------------+
| Alice      | Johnson   | 58.95 |         19.40 |
| Dave       | Brown     | 45.96 |          6.41 |
| Frank      | Miller    | 41.96 |          2.41 |
+------------+-----------+-------+---------------+
  4. A CTE joined to itself (2m). "A CTE is read like a table, so it can be read twice, under two aliases: this month next to last month." Point at January's NULLs: the LEFT JOIN keeps a month with no previous month. Say: "after the break, LAG does this in one line". 
    WITH monthly AS (
    SELECT MONTH(o.order_date)                 AS month_num,
           SUM(oi.quantity * oi.price_at_time) AS revenue
    FROM orders o
    JOIN order_items oi ON oi.order_id = o.id
    GROUP BY MONTH(o.order_date)
)
SELECT cur.month_num,
       cur.revenue,
       prev.revenue                AS previous_month,
       cur.revenue - prev.revenue  AS change_amount
FROM monthly cur
LEFT JOIN monthly prev ON prev.month_num = cur.month_num - 1
ORDER BY cur.month_num;
    +-----------+---------+----------------+---------------+
| month_num | revenue | previous_month | change_amount |
+-----------+---------+----------------+---------------+
|         1 |   61.95 |           NULL |          NULL |
|         2 |   51.95 |          61.95 |        -10.00 |
|         3 |   33.47 |          51.95 |        -18.48 |
|         4 |   38.97 |          33.47 |          5.50 |
|         5 |   31.97 |          38.97 |         -7.00 |
|         6 |   18.98 |          31.97 |        -12.99 |
+-----------+---------+----------------+---------------+
  5. Gone after the semicolon (1m). "The CTE belongs to its statement. The next statement cannot see it." 
    WITH monthly AS (
    SELECT MONTH(order_date) AS month_num, COUNT(*) AS orders
    FROM orders
    GROUP BY MONTH(order_date)
)
SELECT MAX(orders) AS busiest FROM monthly;
SELECT * FROM monthly;

| busiest |
+---------+
|       3 |
+---------+

    Fix: repeat the WITH, or, if many scripts need it, make it a view (Session 9).
  6. Recursion in rounds (3m). Draw the rounds on the board as you type: anchor 1; round 1 reads 1, makes 2; ... round 5 reads 5, the stop condition fails, nothing comes out, done. "Each round sees only the rows the previous round made." 
    WITH RECURSIVE numbers AS (
    SELECT 1 AS n            -- anchor: the first row
    UNION ALL
    SELECT n + 1             -- recursive member: next row from the last one
    FROM numbers
    WHERE n < 5              -- stop condition
)
SELECT n FROM numbers;
    +------+
| n    |
+------+
|    1 |
|    2 |
|    3 |
|    4 |
|    5 |
+------+
  7. A calendar that fills the gaps (2m). "Nobody ordered in July, so GROUP BY over orders cannot show July. Generate the months first, then hang the orders on them with a LEFT JOIN." 
    WITH RECURSIVE months AS (
    SELECT DATE('2026-01-01') AS month_start
    UNION ALL
    SELECT month_start + INTERVAL 1 MONTH
    FROM months
    WHERE month_start < '2026-07-01'
)
SELECT DATE_FORMAT(m.month_start, '%Y-%m') AS month,
       COUNT(o.id)                         AS orders
FROM months m
LEFT JOIN orders o
       ON o.order_date >= m.month_start
      AND o.order_date <  m.month_start + INTERVAL 1 MONTH
GROUP BY m.month_start
ORDER BY m.month_start;
    +---------+--------+
| month   | orders |
+---------+--------+
| 2026-01 |      2 |
| 2026-02 |      3 |
| 2026-03 |      2 |
| 2026-04 |      2 |
| 2026-05 |      2 |
| 2026-06 |      1 |
| 2026-07 |      0 |
+---------+--------+
    COUNT(o.id) counts matched orders only, so July is 0. The date range in ON is the safe way to say "in this month".
  8. The org chart, top down (3m). "Anchor: the person with no manager. Each round: the people whose manager is someone from the round before. The data itself is the stop condition." Point at the CAST in the anchor: the anchor fixes every column's width. 
    WITH RECURSIVE org AS (
    SELECT id, first_name, last_name, department, 1 AS level,
           CAST(first_name AS CHAR(200)) AS path
    FROM employees
    WHERE manager_id IS NULL
    UNION ALL
    SELECT e.id, e.first_name, e.last_name, e.department, o.level + 1,
           CONCAT(o.path, ' > ', e.first_name)
    FROM employees e
    JOIN org o ON e.manager_id = o.id
)
SELECT CONCAT(REPEAT('    ', level - 1), first_name, ' ', last_name) AS org_chart,
       department
FROM org
ORDER BY path;

  9. A chain of command, bottom up (1m). "Swap the join and it climbs: who is this person's manager?" 
    WITH RECURSIVE chain AS (
    SELECT id, first_name, last_name, manager_id, 0 AS steps_up
    FROM employees
    WHERE id = 7

Three mistakes to expect, and how to coach each
  • Expecting a CTE to persist. "I made monthly and now it is gone." Coach: "Which statement was it written in? A CTE is part of one statement; for something everyone reuses, that is a view (Session 9)."
  • Reading the stop condition as a row filter. Learners expect WHERE n < 5 to stop before 5. Coach with the rounds on the board: "Which row does the round read? 4 passes and makes 5; 5 fails and makes nothing." (Self-check Q2.)
  • An anchor that starts everywhere. No WHERE in the anchor: 30 rows for 10 employees, no error. Coach: "How many starting points did you give it? Compare COUNT(*) with COUNT(DISTINCT id)." (Self-check Q5, the lesson's Common Mistake 5.)

Checks for understanding

Ask these out loud during the demo and the lab:

  • Can the main statement read a CTE twice? Answer: yes: the demo's average step reads customer_totals, and the month comparison joins monthly to itself.
  • Which part of a recursive CTE runs exactly once? Answer: the anchor.
  • What stops the org chart's recursion? Answer: the data: in the last round nobody has Tom, Lena, Ben or Sofia as a manager, the join finds nothing, no rows come out.
  • When would you raise cte_max_recursion_depth? Answer: only for a series that really needs more than 1000 rounds, for your session only, and back to DEFAULT afterward; never to silence a missing stop condition.

Window Functions

70 min
Objectives (from the lesson page)
  • Explain how OVER() differs from GROUP BY, and split a window with PARTITION BY
  • Number and rank rows with ROW_NUMBER, RANK and DENSE_RANK, and pick the right one when there are ties
  • Build running totals and moving averages, and control them with a frame (ROWS BETWEEN ...)
  • Compare each row with the one before or after it using LAG and LEAD
  • Return the top N rows per group by filtering a window result in a CTE, and explain why WHERE cannot do it (error 3593)

Mental model to say

The two columns on the board: "GROUP BY answers 'what is the total?' by squashing each group into one row. A window function computes the same kind of number across a set of rows, the window, and hands it back to every row. Eleven books in, eleven books out, each next to the average."

Then the three parts of OVER, written one under the other: PARTITION BY (one window per group), ORDER BY (an order inside each window: needed for ranks, running totals, LAG), the frame (which neighbors count: ROWS BETWEEN 2 PRECEDING AND CURRENT ROW).

Last, the clause order as a vertical list: FROM/JOIN → WHERE → GROUP BY/HAVING → window functions → SELECT list → ORDER BY/LIMIT. "Windows are computed late. That is why WHERE cannot filter on them, and why the fix is one more step: a CTE."

Three mistakes to expect, and how to coach each
  • Filtering a window in WHERE (3593, or 1054 with the alias). Coach with the clause list on the board: "Where in this list does WHERE run? Where do windows run?" Then the two-step CTE pattern.
  • Forgetting PARTITION BY. "Top 2 per category" returns two books in total. Coach: "Where does the numbering restart? Nowhere: tell it to restart per category." (The lab's TODO 2 is built on this.)
  • Trusting a running total with ties. No error, two rows with the same total. Coach: "Which frame did you get by default? RANGE. Say ROWS, and make the order unique."

Checks for understanding

Ask these out loud during the demo and the lab:

  • Does the ORDER BY inside OVER sort the result? Answer: no, it orders the rows for the function; always end with the query's own ORDER BY.
  • Why does January's three-month average equal January? Answer: there are no earlier rows in its frame.
  • Which function do you want for "every book at the top two sales levels"? Answer: DENSE_RANK (ties included, no gaps).
  • A WHERE that filters a plain column, like WHERE is_active: does it break a window? Answer: no: it runs first and decides which rows enter the windows (the lesson's Exercise 1).

ERROR 1406 (22001): Data too long for column 'path' at row 1
ERROR 3593 (HY000): You cannot use the window function 'row_number' in this context.'
ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'rank
FROM books
ORDER BY price DESC
LIMIT 3' at line 1
ERROR 6037 (HY000): 'QUALIFY clause' can be used only if the hypergraph optimizer is enabled.
  • A, 1146: WITH countdown refers to itself: add RECURSIVE.
  • B, 3636: no stop condition: WHERE d < '2026-12-31' in the recursive member (365 rows).
  • C, 1406: the anchor's 'Maria' made a five-character column: CAST('Maria' AS CHAR(200)) (or CAST(first_name AS CHAR(200))).

Closing

Exit ticket (3 questions, no notes, 4 minutes)

Learners answer in the workbook's Exit Ticket box or on a sticky note. Sort into "got it" and "not yet" before Session 9: question 3's pile tells you whether to open Session 9's warm-up with the CTE-filter pattern.

  1. Write the skeleton of a recursive CTE that counts from 1 to 10, and label the anchor, the recursive member and the stop condition. Answer: WITH RECURSIVE s AS (SELECT 1 AS n /* anchor */ UNION ALL SELECT n + 1 FROM s /* recursive member */ WHERE n < 10 /* stop */) SELECT n FROM s;
  2. GROUP BY department versus PARTITION BY department: what is the difference in the rows you get back? Answer: GROUP BY returns one row per department; PARTITION BY keeps every employee row and adds the department's figure to each.
  3. Why can't WHERE filter on ROW_NUMBER(), and what do you do instead? Answer: window functions are computed after WHERE (error 3593); compute the number in a CTE and filter it in the outer query.
