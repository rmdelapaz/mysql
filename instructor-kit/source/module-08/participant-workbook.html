5.1

CTEs & Recursive Queries

By the end you can
  • Rewrite a nested subquery as a WITH query and name each step
  • Chain several CTEs in one statement, letting later steps read earlier ones
  • Choose between a CTE, a derived table and a view for a given job
  • Write a recursive CTE with an anchor, a recursive member and a stop condition, and generate number and month series with it
  • Walk the employee hierarchy down (an org chart) and up (a chain of command)
  • Read and fix errors 1146, 3636 and 1406 from broken CTEs
Key ideas
  • A CTE (WITH name AS (...)) is a named result that lives for ONE statement and is read like a table: select, filter, join, group it.
  • Several CTEs, one WITH, separated by commas; each can read the ones before it, and each can be read more than once.
  • CTE, derived table or view? Derived table: a small one-off step. CTE: multi-step questions and hierarchies. View: a question the whole team asks every day (Session 9).
  • A recursive CTE = anchor (runs once) + UNION ALL + recursive member (runs per round, reading only the previous round's rows) with a stop condition.
  • The anchor fixes every column's type and width: CAST(... AS CHAR(200)) for paths and lists, or error 1406.
  • Down a hierarchy: e.manager_id = cte.id. Up: e.id = cte.manager_id.
  • cte_max_recursion_depth (1000) stops runaway recursion with error 3636; MariaDB stops quietly with a warning.
Worked example: counting counts, and weeks with no orders

A CTE can count, then the main query can count the counts. How many authors have 0, 1 or 2 books? The LEFT JOIN keeps Isaac Asimov, who has none:

WITH book_counts AS (
    SELECT a.name AS author, COUNT(b.id) AS books
    FROM authors AS a
    LEFT JOIN books AS b ON b.author_id = a.id
    GROUP BY a.id, a.name
)
SELECT books, COUNT(*) AS authors
FROM book_counts
GROUP BY books
ORDER BY books;
+-------+---------+
| books | authors |
+-------+---------+
|     0 |       1 |
|     1 |       7 |
|     2 |       2 |
+-------+---------+

A recursive series does not have to count by one. Here it makes the four Sundays of February 2026 (every 7 days), and a LEFT JOIN hangs the orders on each week, so the empty last week still shows:

WITH RECURSIVE weeks AS (
    SELECT DATE('2026-02-01') AS week_start
    UNION ALL
    SELECT week_start + INTERVAL 7 DAY
    FROM weeks
    WHERE week_start < '2026-02-22'
)
SELECT w.week_start, COUNT(o.id) AS orders
FROM weeks AS w
LEFT JOIN orders AS o
       ON o.order_date >= w.week_start
      AND o.order_date <  w.week_start + INTERVAL 7 DAY
GROUP BY w.week_start
ORDER BY w.week_start;
+------------+--------+
| week_start | orders |
+------------+--------+
| 2026-02-01 |      1 |
| 2026-02-08 |      1 |
| 2026-02-15 |      1 |
| 2026-02-22 |      0 |
+------------+--------+

The stop condition reads the row the round starts from: the round that reads February 22 fails week_start < '2026-02-22', so no March 1 row is made.

5.2

Window Functions

By the end you can
  • Explain how OVER() differs from GROUP BY, and split a window with PARTITION BY
  • Number and rank rows with ROW_NUMBER, RANK and DENSE_RANK, and pick the right one when there are ties
  • Build running totals and moving averages, and control them with a frame (ROWS BETWEEN ...)
  • Compare each row with the one before or after it using LAG and LEAD
  • Return the top N rows per group by filtering a window result in a CTE, and explain why WHERE cannot do it (error 3593)
Key ideas
  • A window function computes across a set of rows (the window) and returns a value for EVERY row: OVER turns an aggregate into one.
  • PARTITION BY splits the window per group without collapsing rows; ORDER BY inside OVER orders each window; the frame (ROWS BETWEEN ...) says which neighbors count.
  • ROW_NUMBER never ties; RANK ties and skips (1, 2, 2, 4); DENSE_RANK ties without gaps (1, 2, 2, 3).
  • Running total: SUM(x) OVER (ORDER BY t ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW). The default frame is RANGE, which lumps ties together.
  • LAG / LEAD read the previous / next row, with an optional offset and default.
  • Windows run after WHERE, GROUP BY and HAVING: filter on them in an outer query over a CTE (error 3593 otherwise). Top N per group = ROW_NUMBER in a CTE, WHERE pos <= N outside.
  • Reserved words: rank, row_number, window, groups: name columns rank_num, pos.
Worked example: two windows per customer, and the first value

Two windows over the same partition: which order is this for the customer (ROW_NUMBER), and how many orders does the customer have in all (COUNT(*) OVER)? No GROUP BY, so every order stays:

SELECT c.first_name,
       o.id AS order_id,
       o.order_date,
       ROW_NUMBER() OVER (PARTITION BY o.customer_id ORDER BY o.order_date) AS nth_order,
       COUNT(*)     OVER (PARTITION BY o.customer_id)                       AS of_total
FROM orders AS o
JOIN customers AS c ON c.id = o.customer_id
WHERE c.first_name IN ('Alice', 'Bob')
ORDER BY c.first_name, o.order_date;
+------------+----------+------------+-----------+----------+
| first_name | order_id | order_date | nth_order | of_total |
+------------+----------+------------+-----------+----------+
| Alice      |        1 | 2026-01-15 |         1 |        3 |
| Alice      |        2 | 2026-02-20 |         2 |        3 |
| Alice      |        8 | 2026-04-05 |         3 |        3 |
| Bob        |        3 | 2026-03-10 |         1 |        2 |
| Bob        |        7 | 2026-03-28 |         2 |        2 |
+------------+----------+------------+-----------+----------+

FIRST_VALUE reads the first row of the window. Ordered by price within each author, that is the author's cheapest book, shown on every row of that author (LAST_VALUE would need a frame to the end of the window: the lesson's Common Mistake 5):

SELECT a.name AS author,
       b.title,
       b.price,
       FIRST_VALUE(b.title) OVER (PARTITION BY a.id ORDER BY b.price) AS cheapest_by_author
FROM books AS b
JOIN authors AS a ON a.id = b.author_id
WHERE a.id IN (2, 6)
ORDER BY a.name, b.price;
+----------------+-------------------+-------+--------------------+
| author         | title             | price | cheapest_by_author |
+----------------+-------------------+-------+--------------------+
| George Orwell  | Animal Farm       |  8.49 | Animal Farm        |
| George Orwell  | 1984              |  9.99 | Animal Farm        |
| J.R.R. Tolkien | The Hobbit        | 10.99 | The Hobbit         |
| J.R.R. Tolkien | Lord of the Rings | 15.99 | The Hobbit         |
+----------------+-------------------+-------+--------------------+

Glossary

TermMeaning
CTE (common table expression)A named, temporary result written with WITH; it lives for one statement
derived tableA subquery in FROM, with an alias (Lesson 3.4); read inside out
recursive CTEA CTE that reads itself, round by round (WITH RECURSIVE)
anchorThe part of a recursive CTE that runs once and makes the starting rows
recursive memberThe part after UNION ALL that runs every round, from the previous round's rows
stop conditionThe condition in the recursive member that eventually lets a round make no rows
cte_max_recursion_depthThe session's cap on rounds (1000); error 3636 when it is reached
window functionA function that computes across a window of rows and returns a value for every row
OVERThe clause that turns a function into a window function and describes its window
PARTITION BYSplits the rows into separate windows, one per group
frameThe rows around the current row that an aggregate sees (ROWS BETWEEN ...)
ROW_NUMBER / RANK / DENSE_RANKNumbering without ties / with ties and gaps / with ties, no gaps
LAG / LEADThe value from the previous / next row of the window
top N per groupNumber the rows per group in a CTE, keep the low numbers in the outer query
