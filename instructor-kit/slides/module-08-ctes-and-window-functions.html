5.1

CTEs & Recursive Queries

Name each step of a long question, and follow chains of rows.

5.1 · Mental model

One question, three steps

  1. Total each customer's orders
  2. Average those totals
  3. Keep the customers above the average
WHY A CTE names a step once, up front. The query reads top to bottom.
5.1 · Code

The steps, named

WITH customer_totals AS (
    SELECT o.customer_id,
           SUM(oi.quantity * oi.price_at_time) AS total
    FROM orders o
    JOIN order_items oi ON oi.order_id = o.id
    GROUP BY o.customer_id
)
SELECT customer_id, total
FROM customer_totals
WHERE total > (SELECT AVG(total) FROM customer_totals)
ORDER BY total DESC;
+-------------+-------+
| customer_id | total |
+-------------+-------+
|           1 | 58.95 |
|           4 | 45.96 |
|           6 | 41.96 |
+-------------+-------+
WHY customer_totals is written once and read twice.
5.1 · Several CTEs

One WITH, a list of steps

  • WITH a AS (...), b AS (SELECT ... FROM a)
  • Each CTE can read the ones before it
  • A one-row CTE + CROSS JOIN: its value on every row
  • A CTE can be joined to itself: this month next to last month
WHY Name CTEs after what they hold, test each with SELECT * on its own.
5.1 · Code

A CTE joined to itself

WITH monthly AS (
    SELECT MONTH(o.order_date) AS m,
           SUM(oi.quantity * oi.price_at_time) AS revenue
    FROM orders o
    JOIN order_items oi ON oi.order_id = o.id
    GROUP BY m)
SELECT cur.m, cur.revenue,
       prev.revenue AS previous
FROM monthly cur
LEFT JOIN monthly prev ON prev.m = cur.m - 1
ORDER BY cur.m;
+------+---------+----------+
| m    | revenue | previous |
+------+---------+----------+
|    1 |   61.95 |     NULL |
|    2 |   51.95 |    61.95 |
|    3 |   33.47 |    51.95 |
|    4 |   38.97 |    33.47 |
|    5 |   31.97 |    38.97 |
|    6 |   18.98 |    31.97 |
+------+---------+----------+
WHY After the break: LAG() does this in one line.
5.1 · Which one?

Derived table, CTE or view?

  • Derived table: one statement, read inside out, a small one-off step
  • CTE: one statement, top to bottom, can read itself (RECURSIVE)
  • View: stored until dropped, for the question everyone asks (Session 9)
  • After the semicolon a CTE is gone: ERROR 1146
5.1 · Recursion

Rounds, not magic

WITH RECURSIVE numbers AS (
    SELECT 1 AS n                                  -- anchor: runs once
    UNION ALL
    SELECT n + 1 FROM numbers WHERE n < 5          -- recursive member + stop
)
SELECT GROUP_CONCAT(n ORDER BY n) AS rows_made FROM numbers;
+-----------+
| rows_made |
+-----------+
| 1,2,3,4,5 |
+-----------+
WHY Round 4 reads 4 and makes 5. Round 5 reads 5, fails n < 5, makes nothing: stop.
5.1 · Recursion

A calendar that fills the gaps

WITH RECURSIVE months AS (
    SELECT DATE('2026-01-01') AS month_start
    UNION ALL
    SELECT month_start + INTERVAL 1 MONTH
    FROM months
    WHERE month_start < '2026-07-01'
)
SELECT DATE_FORMAT(m.month_start, '%Y-%m') AS month,
       COUNT(o.id)                         AS orders
FROM months m
LEFT JOIN orders o
       ON o.order_date >= m.month_start
      AND o.order_date <  m.month_start + INTERVAL 1 MONTH
GROUP BY m.month_start
ORDER BY m.month_start;
WHY July: 0 orders. Generate the months first, then LEFT JOIN the data.

5.1 · Hierarchy

The org chart, top down

WITH RECURSIVE org AS (
    SELECT id, first_name, last_name, department, 1 AS level,
           CAST(first_name AS CHAR(200)) AS path
    FROM employees
    WHERE manager_id IS NULL
    UNION ALL
    SELECT e.id, e.first_name, e.last_name, e.department, o.level + 1,
           CONCAT(o.path, ' > ', e.first_name)
    FROM employees e
    JOIN org o ON e.manager_id = o.id
)
SELECT CONCAT(REPEAT('    ', level - 1), first_name, ' ', last_name) AS org_chart,
       department
FROM org
ORDER BY path;
WHY Down: e.manager_id = o.id · the anchor's CAST makes path wide enough

5.1 · Hierarchy

A chain of command, bottom up

WITH RECURSIVE chain AS (
    SELECT id, first_name, manager_id, 0 AS steps_up
    FROM employees
    WHERE id = 7
    UNION ALL
    SELECT e.id, e.first_name, e.manager_id,
           c.steps_up + 1
    FROM employees e
    JOIN chain c ON e.id = c.manager_id   -- walk UP
)
SELECT steps_up, first_name
FROM chain
ORDER BY steps_up;
+----------+------------+
| steps_up | first_name |
+----------+------------+
|        0 | Sofia      |
|        1 | Marcus     |
|        2 | Daniel     |
|        3 | Maria      |
+----------+------------+
WHY Up: e.id = c.manager_id. Maria has no manager: the climb stops.
5.1 · The database says no

Three errors to know

WITH org AS ( ... JOIN org ... )              -- RECURSIVE forgotten
WITH RECURSIVE numbers AS ( ... )             -- no stop condition
SELECT 'Maria' AS path ... CONCAT(path, ...)  -- anchor too narrow
ERROR 1146 (42S02): Table 'bookstore.org' doesn't exist
ERROR 3636 (HY000): Recursive query aborted after 1001 iterations. Try
    increasing @@cte_max_recursion_depth to a larger value.
ERROR 1406 (22001): Data too long for column 'path' at row 1
RULE Never raise the limit to silence a missing stop condition.

5.2

Window Functions

Each row next to a total, a rank or its neighbor.

5.2 · Mental model

Squash, or keep every row

  • GROUP BY: one row per group, the rows are gone
  • OVER: every row stays, each gets the group's number
  • PARTITION BY: one window per group
  • ORDER BY inside OVER: ranks, running totals, LAG
  • Frame: ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
5.2 · Code

Every book, next to the average

SELECT title, price,
       ROUND(AVG(price) OVER (), 2) AS avg_price
FROM books
ORDER BY price DESC
LIMIT 4;
+-----------------------+-------+-----------+
| title                 | price | avg_price |
+-----------------------+-------+-----------+
| Lord of the Rings     | 15.99 |     10.76 |
| Dune                  | 14.99 |     10.76 |
| To Kill a Mockingbird | 11.99 |     10.76 |
| The Hobbit            | 10.99 |     10.76 |
+-----------------------+-------+-----------+
WHY Eleven rows in, eleven rows out (four shown).
5.2 · Code

A window per department

SELECT first_name, department, salary,
       ROUND(AVG(salary) OVER (PARTITION BY department), 2) AS dept_avg
FROM employees
WHERE department IN ('inventory', 'support')
ORDER BY department, salary DESC;

| first_name | department | salary   | dept_avg |

| James      | support    | 52000.00 | 44250.00 |
| Nina       | support    | 36500.00 | 44250.00 |
+------------+------------+----------+----------+
WHY Every inventory row sees the inventory average.

5.2 · Code

Running total and the month before

WITH monthly AS (
    SELECT MONTH(o.order_date) AS m,
           SUM(oi.quantity * oi.price_at_time) AS revenue
    FROM orders o
    JOIN order_items oi ON oi.order_id = o.id
    GROUP BY m)
SELECT m, revenue,
       SUM(revenue) OVER (ORDER BY m) AS running,
       LAG(revenue) OVER (ORDER BY m) AS prev
FROM monthly
ORDER BY m;
+------+---------+---------+-------+
| m    | revenue | running | prev  |
+------+---------+---------+-------+
|    1 |   61.95 |   61.95 |  NULL |
|    2 |   51.95 |  113.90 | 61.95 |
|    3 |   33.47 |  147.37 | 51.95 |
|    4 |   38.97 |  186.34 | 33.47 |
|    5 |   31.97 |  218.31 | 38.97 |
|    6 |   18.98 |  237.29 | 31.97 |
+------+---------+---------+-------+
WHY Each row adds its month. LAG reads the previous row: January has none.
5.2 · Top N per group

Number in a CTE, filter outside

WITH ranked AS (
    SELECT department, first_name, salary,
           ROW_NUMBER() OVER (
               PARTITION BY department
               ORDER BY salary DESC) AS pos
    FROM employees)
SELECT department, first_name, salary
FROM ranked
WHERE pos = 1
ORDER BY salary DESC;
+------------+------------+----------+
| department | first_name | salary   |
+------------+------------+----------+
| management | Maria      | 92000.00 |
| support    | James      | 52000.00 |
| inventory  | Marcus     | 47000.00 |
| sales      | Priya      | 46000.00 |
+------------+------------+----------+
WHY pos <= 2: the top two per department.
5.2 · Why not WHERE?

Windows are computed late

  1. FROM and JOIN
  2. WHERE
  3. GROUP BY and HAVING
  4. window functions
  5. SELECT list
  6. ORDER BY, LIMIT
RULE WHERE ROW_NUMBER() ... = ERROR 3593. One more step: a CTE.
5.2 · Common mistakes

Three traps

  • AS rank: a reserved word (1064). Use rank_num
  • QUALIFY from other databases: 6037 on MySQL 9.7
  • Running total with ties: the default RANGE frame lumps them
  • Fix: ORDER BY price, title ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
