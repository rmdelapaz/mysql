3.3

Aggregate Functions & GROUP BY

Many rows in, one number out. One number per pile.

3.3 · Mental model

The cashier's end-of-day slip

  • Nobody reads every receipt: they read the totals
  • COUNT SUM AVG MIN MAX: many rows, one value
  • GROUP BY: sort the rows into piles, one answer per pile
  • Every column you show: the pile's label, or a summary of the pile
WHY Every aggregate skips NULL, except COUNT(*).
3.3 · Run order

You write SELECT first; MySQL runs it fifth

  1. FROM: pick the table
  2. WHERE: keep rows (the piles do not exist yet)
  3. GROUP BY: make piles
  4. HAVING: keep piles
  5. SELECT, then ORDER BY, then LIMIT
WHY Condition on one row: WHERE. Condition on a pile: HAVING.
3.3 · Code

COUNT three ways

SELECT
    COUNT(*)             AS customers,
    COUNT(city)          AS with_a_city,
    COUNT(DISTINCT city) AS cities
FROM customers;
+-----------+-------------+--------+
| customers | with_a_city | cities |
+-----------+-------------+--------+
|         8 |           6 |      4 |
+-----------+-------------+--------+
WHY COUNT(city) skips Eve and Hank; DISTINCT counts New York once.
3.3 · Code

SUM and AVG: why six decimals?

SELECT
    SUM(price)           AS one_of_each,
    AVG(price)           AS avg_price,
    ROUND(AVG(price), 2) AS avg_rounded
FROM books;
+-------------+-----------+-------------+
| one_of_each | avg_price | avg_rounded |
+-------------+-----------+-------------+
|      109.90 | 10.990000 |       10.99 |
+-------------+-----------+-------------+
WHY Money for people: ROUND(AVG(price), 2).
3.3 · Code

MIN gives the value, not the row

SELECT MIN(price) AS cheapest, MAX(price) AS priciest
FROM books;
SELECT title, price
FROM books
ORDER BY price
LIMIT 1;
+----------+----------+
| cheapest | priciest |
+----------+----------+
|     7.99 |    15.99 |

+---------------------+-------+

+---------------------+-------+
| Pride and Prejudice |  7.99 |
+---------------------+-------+
WATCH Which book? Sort and LIMIT. Ties? After the break.
3.3 · Code

Nothing matches: 0 and NULL

SELECT
    COUNT(*)   AS books_over_100,
    SUM(price) AS their_total
FROM books
WHERE price > 100;
+----------------+-------------+
| books_over_100 | their_total |
+----------------+-------------+
|              0 |        NULL |
+----------------+-------------+
WHY COALESCE(SUM(price), 0) when a report needs 0.
3.3 · GROUP BY

One pile per author

SELECT author, COUNT(*) AS book_count
FROM books
GROUP BY author
ORDER BY book_count DESC, author
LIMIT 4;
+---------------------+------------+
| author              | book_count |
+---------------------+------------+
| J.R.R. Tolkien      |          2 |
| Aldous Huxley       |          1 |
| F. Scott Fitzgerald |          1 |
| Frank Herbert       |          1 |
+---------------------+------------+
WATCH GROUP BY does not sort (MySQL 8.0 and later). Always ORDER BY.
3.3 · GROUP BY

Several aggregates per pile

SELECT
    in_stock,
    COUNT(*)             AS books,
    ROUND(AVG(price), 2) AS avg_price,
    MAX(pages)           AS longest
FROM books
GROUP BY in_stock
ORDER BY in_stock DESC;
+----------+-------+-----------+---------+
| in_stock | books | avg_price | longest |
+----------+-------+-----------+---------+
|        1 |     8 |     11.49 |    1178 |
|        0 |     2 |      8.99 |     234 |
+----------+-------+-----------+---------+
3.3 · HAVING

Keep whole piles

SELECT city, COUNT(*) AS customers
FROM customers
WHERE city IS NOT NULL
GROUP BY city
HAVING customers > 1
ORDER BY city;
+----------+-----------+
| city     | customers |
+----------+-----------+
| Chicago  |         2 |
| New York |         2 |
+----------+-----------+
WHY Houston and Los Angeles fail HAVING and disappear.
3.3 · HAVING

WHERE and HAVING together

SELECT author, ROUND(AVG(price), 2) AS avg_price
FROM books
WHERE in_stock = TRUE
GROUP BY author
HAVING AVG(price) > 10
ORDER BY avg_price DESC;
+----------------+-----------+
| author         | avg_price |
+----------------+-----------+
| Frank Herbert  |     14.99 |
| J.R.R. Tolkien |     13.49 |
| Harper Lee     |     11.99 |
| Ray Bradbury   |     10.49 |
+----------------+-----------+
WHY Rows out first (WHERE), piles out last (HAVING).
3.3 · Errors on purpose

Three numbered refusals

SELECT title, COUNT(*) FROM books;
SELECT author, title, COUNT(*) AS books FROM books GROUP BY author;
SELECT author, COUNT(*) ... WHERE COUNT(*) > 1 GROUP BY author;
ERROR 1140 (42000)
ERROR 1055 (42000)
ERROR 1111 (HY000)
  • 1140: ten titles, one row: which title?
  • 1055: Tolkien's pile has two titles
  • 1111: WHERE runs before the piles exist

3.4

Subqueries & Nested Queries

A query inside a query: the inner one answers first.

3.4 · Mental model

Fill in the blank

  • WHERE price > ( ___ ): before, you typed 10.99
  • Now a whole SELECT goes in the blank
  • Read from the inside out
  • The blank expects a shape: one value · a list · a named table
WHY Most subquery errors are a shape mismatch: 1242, 1241, 1248.
3.4 · Code

Above the average, computed fresh

SELECT title, price
FROM books
WHERE price > (SELECT AVG(price) FROM books)
ORDER BY price;
+-----------------------+-------+
| title                 | price |
+-----------------------+-------+
| To Kill a Mockingbird | 11.99 |
| Dune                  | 14.99 |
| Lord of the Rings     | 15.99 |
+-----------------------+-------+
WHY Run the inner query alone first. Every time.
3.4 · Code

The row behind the maximum

SELECT title, author, price
FROM books
WHERE price = (SELECT MAX(price) FROM books);
+-------------------+----------------+-------+
| title             | author         | price |
+-------------------+----------------+-------+
| Lord of the Rings | J.R.R. Tolkien | 15.99 |
+-------------------+----------------+-------+
WHY Ties? The subquery returns all of them; LIMIT 1 would hide one.
3.4 · Code

A list: IN with GROUP BY inside

SELECT first_name, city
FROM customers
WHERE city IN (
    SELECT city FROM customers
    GROUP BY city
    HAVING COUNT(*) > 1
)
ORDER BY city, first_name;
+------------+----------+
| first_name | city     |
+------------+----------+
| Bob        | Chicago  |
| Grace      | Chicago  |
| Alice      | New York |
| Frank      | New York |
+------------+----------+
3.4 · The NOT IN trap

No error, no rows

SELECT first_name, city
FROM customers
WHERE created_at < '2026-02-01'
  AND city NOT IN (
      SELECT city FROM customers
      WHERE created_at >= '2026-02-01'
  );
inner query returns:
+---------+
| city    |
+---------+
| Chicago |
| NULL    |
+---------+
outer result:
Empty set
RULE Every NOT IN subquery gets IS NOT NULL. Or use NOT EXISTS.
3.4 · Code

The fix: keep NULL out of the list

SELECT first_name, city
FROM customers
WHERE created_at < '2026-02-01'
  AND city NOT IN (
      SELECT city FROM customers
      WHERE created_at >= '2026-02-01'
        AND city IS NOT NULL
  )
ORDER BY first_name;
+------------+-------------+
| first_name | city        |
+------------+-------------+
| Alice      | New York    |
| Carol      | Los Angeles |
| Dave       | Houston     |
| Frank      | New York    |
+------------+-------------+
3.4 · Correlated

Above their OWN author's average

SELECT b.title, b.author, b.price
FROM books AS b
WHERE b.price > (
    SELECT AVG(b2.price)
    FROM books AS b2
    WHERE b2.author = b.author
);
+-------------------+----------------+-------+
| title             | author         | price |
+-------------------+----------------+-------+
| Lord of the Rings | J.R.R. Tolkien | 15.99 |
+-------------------+----------------+-------+
WHY b = the row being tested · b2 = the inner scan of the same table.
3.4 · Correlated

Walk it one row at a time

  1. Outer row: The Hobbit, Tolkien, 10.99
  2. Inner: average of Tolkien's books = 13.49
  3. 10.99 above 13.49? No: dropped
  4. Next row: Lord of the Rings, 15.99 above 13.49? Yes: kept
  5. Single-book authors: a price is never above itself
HOW Build it inner query first, for one author, then correlate.
3.4 · EXISTS

Nobody else in my city

SELECT c.first_name, c.city
FROM customers AS c
WHERE NOT EXISTS (
    SELECT 1
    FROM customers AS other
    WHERE other.city = c.city
      AND other.id != c.id
)
ORDER BY c.first_name;
+------------+-------------+
| first_name | city        |
+------------+-------------+
| Carol      | Los Angeles |
| Dave       | Houston     |
| Eve        | NULL        |
| Hank       | NULL        |
+------------+-------------+
WHY No NULL trap: Eve and Hank are kept.
3.4 · Derived table

A summary of a summary

SELECT ROUND(AVG(book_count), 2) AS avg_books_per_author,
       MAX(book_count)            AS most_books
FROM (
    SELECT author, COUNT(*) AS book_count
    FROM books
    GROUP BY author
) AS author_counts;
+----------------------+------------+
| avg_books_per_author | most_books |
+----------------------+------------+
|                 1.11 |          2 |
+----------------------+------------+
WHY AVG(COUNT(*)) in one level is error 1111. Two levels: FROM ( ... ) AS name.
3.4 · SELECT list

A whole-table number on every row

SELECT
    title,
    price,
    ROUND(price - (SELECT AVG(price) FROM books), 2) AS diff_from_avg
FROM books
ORDER BY diff_from_avg DESC, title
LIMIT 4;
+-----------------------+-------+---------------+
| title                 | price | diff_from_avg |
+-----------------------+-------+---------------+
| Lord of the Rings     | 15.99 |          5.00 |
| Dune                  | 14.99 |          4.00 |
| To Kill a Mockingbird | 11.99 |          1.00 |
| The Hobbit            | 10.99 |          0.00 |
+-----------------------+-------+---------------+
3.4 · Errors on purpose

Shape mismatches

WHERE price = (SELECT price FROM books WHERE in_stock = FALSE)
