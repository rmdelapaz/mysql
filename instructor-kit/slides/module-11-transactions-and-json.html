7.2

Transactions

Several changes that happen completely or not at all.

7.2 · Mental model

All or nothing

  1. START TRANSACTION: from here on, nothing is final
  2. Your statements: visible to you, invisible to everyone else
  3. COMMIT keeps all of it · ROLLBACK throws all of it away
WHY Autocommit: without START TRANSACTION, every statement commits by itself.
7.2 · ACID

Four promises, in the bookstore

  • Atomicity: an order never exists without its items
  • Consistency: CHECK (balance >= 0) holds after every commit
  • Isolation: a report never counts a half-placed order
  • Durability: after COMMIT, it survives a power cut
7.2 · Code

COMMIT: a transfer that sticks

START TRANSACTION;
UPDATE accounts SET balance = balance - 30 WHERE id = 1;
UPDATE accounts SET balance = balance + 30 WHERE id = 2;
COMMIT;
SELECT * FROM accounts ORDER BY id;
+----+----------------+---------+
| id | name           | balance |
+----+----------------+---------+
|  1 | Alice Johnson  |  120.00 |
|  2 | Bob Smith      |   80.00 |
|  3 | Carol Williams |    0.00 |
+----+----------------+---------+
WHY Between START TRANSACTION and COMMIT, only this session sees 120 and 80.
7.2 · Code

ROLLBACK: a rehearsal

START TRANSACTION;
DELETE FROM order_items;
SELECT COUNT(*) AS items_inside FROM order_items;
ROLLBACK;
SELECT COUNT(*) AS items_after_rollback FROM order_items;
+--------------+
| items_inside |
+--------------+
|            0 |
+--------------+
+----------------------+
| items_after_rollback |
+----------------------+
|                   18 |
+----------------------+
7.2 · Implicit commits

Statements that commit by themselves

  • CREATE, ALTER, DROP, RENAME, TRUNCATE
  • CREATE USER, GRANT, REVOKE
  • A second START TRANSACTION, LOCK TABLES
  • ROLLBACK undoes only what came after the last commit
RULE Keep schema changes out of transactions: before or after.
7.2 · Silent trap 1

A CREATE TABLE in the middle

START TRANSACTION;
UPDATE accounts SET balance = 0 WHERE id = 2;
CREATE TABLE demo_audit (note VARCHAR(100));
ROLLBACK;
SELECT id, balance FROM accounts WHERE id = 2;
+----+---------+
| id | balance |
+----+---------+
|  2 |    0.00 |
+----+---------+
WATCH Bob's 0.00 is real: CREATE TABLE committed it before it ran.
7.2 · Silent trap 2

COMMIT after an error

START TRANSACTION;
UPDATE accounts SET balance = balance + 40 WHERE id = 2;
UPDATE accounts SET balance = balance - 40 WHERE id = 3;
COMMIT;
SELECT * FROM accounts ORDER BY id;
ERROR 3819 (HY000): Check constraint 'chk_balance' is violated.
+----+----------------+---------+
| id | name           | balance |
+----+----------------+---------+
|  1 | Alice Johnson  |  120.00 |
|  2 | Bob Smith      |  120.00 |
|  3 | Carol Williams |    0.00 |
+----+----------------+---------+
WATCH A failed statement undoes only itself. Bob got 40 from nothing.
7.2 · Two windows

Who sees what, who waits

  1. A: START TRANSACTION; Alice minus 20 · A sees 100.00
  2. B: plain SELECT · sees 120.00 at once, no waiting
  3. B: UPDATE the same row · waits for A's row lock
  4. A: COMMIT · the lock is released
  5. B: SELECT again · sees 100.00
WHY Readers never wait and never see unfinished work. Writers wait for writers.
7.2 · Lock wait

When B waits too long

UPDATE accounts SET balance = balance + 1 WHERE id = 1;   -- window B
ERROR 1205 (HY000): Lock wait timeout exceeded; try restarting transaction
  • After innodb_lock_wait_timeout: 50 s by default
  • Only the waiting statement fails; nothing is undone
  • If A commits in time, B's UPDATE simply finishes
7.2 · Locking reads

FOR UPDATE and deadlocks

  • Read-then-write? SELECT ... FOR UPDATE locks the rows you will change
  • Two cashiers can no longer spend the same balance
  • Deadlock: InnoDB rolls one transaction back with 1213
  • Retry the WHOLE transaction; lock rows in the same order everywhere
7.2 · Procedures

The handler: two lines

DECLARE EXIT HANDLER FOR SQLEXCEPTION
BEGIN
    ROLLBACK;   -- undo everything this call did
    RESIGNAL;   -- and pass the original error to the caller
END;
  • Declared after the variables, before the other statements
  • Catches every error, including your own SIGNALs
WATCH ROLLBACK without RESIGNAL hides the failure from the app.
7.2 · Code

The hardest failing call

CALL transfer(1, 3, 5.00);
CALL transfer(1, 99, 5.00);
SELECT * FROM accounts ORDER BY id;
ERROR 1644 (45000): No such destination account
+----+----------------+---------+
| id | name           | balance |
+----+----------------+---------+
|  1 | Alice Johnson  |   95.00 |
|  2 | Bob Smith      |   80.00 |
|  3 | Carol Williams |    5.00 |
+----+----------------+---------+
WHY The debit to 99 succeeded, the credit found no row: the handler undid the debit.
7.2 · Predict, then run

What does this print?

CREATE TABLE seats (id INT PRIMARY KEY, taken INT NOT NULL);
INSERT INTO seats VALUES (1, 0), (2, 0);
START TRANSACTION;
UPDATE seats SET taken = 1 WHERE id = 1;
SAVEPOINT one_seat;
UPDATE seats SET taken = 1 WHERE id = 2;
ROLLBACK TO SAVEPOINT one_seat;
COMMIT;
SELECT SUM(taken) AS seats_taken FROM seats;
  • Which UPDATE survives the ROLLBACK TO?
7.2 · Common mistakes

What goes wrong

  • COMMIT after an error: the earlier changes are saved
  • A schema change inside a transaction: ROLLBACK does nothing
  • A savepoint name typo: ERROR 1305, transaction still open
  • Writing in START TRANSACTION READ ONLY: ERROR 1792
  • A MyISAM table: ROLLBACK ignored, warning 1196

7.3

JSON Columns

Flexible details next to the ordinary columns, and when not to use them.

7.3 · Mental model

Columns, or JSON?

  • Every row has it, you join, sum or constrain it: a column
  • A list of related things: a table
  • Optional, varied, mostly for display: JSON
  • Design the tables first; JSON gets the leftovers
7.3 · Code

One document per row

SELECT id, title, attributes->>'$.format' AS format,
       attributes->'$.awards' AS awards
FROM books
WHERE id IN (1, 2, 6)
ORDER BY id;
+----+------------+-----------+--------------------+
| id | title      | format    | awards             |
+----+------------+-----------+--------------------+
|  1 | Dune       | paperback | ["Hugo", "Nebula"] |
|  2 | 1984       | paperback | []                 |
|  6 | The Hobbit | hardcover | NULL               |
+----+------------+-----------+--------------------+
WHY Paths start at $: $.format, $.awards[0]. Keys come back sorted.
7.3 · Code

MySQL checks every document

UPDATE books SET attributes = '{format: "ebook"}' WHERE id = 2;
  • ERROR 3140 (22032): Invalid JSON text
  • Missing a name for object member. at position 1
  • JSON keys need double quotes; JavaScript's bare keys are not JSON
FIX Or let JSON_OBJECT() write the document for you.
7.3 · Code

Two arrows

SELECT title, JSON_EXTRACT(attributes, '$.format') AS extracted,
       attributes->'$.format' AS arrow, attributes->>'$.format' AS double_arrow
FROM books WHERE id IN (1, 6) ORDER BY id;
+------------+-------------+-------------+--------------+
| title      | extracted   | arrow       | double_arrow |
+------------+-------------+-------------+--------------+
| Dune       | "paperback" | "paperback" | paperback    |
| The Hobbit | "hardcover" | "hardcover" | hardcover    |
+------------+-------------+-------------+--------------+
WHY -> gives JSON (with quotes) · ->> gives plain text
7.3 · Code

Missing keys are NULL

SELECT title, attributes->>'$.awards[0]' AS first_award,
       JSON_LENGTH(attributes->'$.awards') AS award_count, attributes->>'$.series' AS series
FROM books WHERE id IN (1, 2, 6) ORDER BY id;
+------------+-------------+-------------+-----------------+
| title      | first_award | award_count | series          |
+------------+-------------+-------------+-----------------+
| Dune       | Hugo        |           2 | Dune Chronicles |
| 1984       | NULL        |           0 | NULL            |
| The Hobbit | NULL        |        NULL | Middle-earth    |
+------------+-------------+-------------+-----------------+
WHY 1984 has an empty list; the Hobbit has no awards key at all. No error either way.
7.3 · Code

Change part of a document

UPDATE books
SET attributes = JSON_SET(attributes, '$.edition', '75th anniversary')
WHERE id = 6;
SELECT attributes->>'$.edition' AS edition, attributes->>'$.format' AS format
FROM books WHERE id = 6;
Query OK, 1 row affected
Rows matched: 1  Changed: 1  Warnings: 0
+------------------+-----------+
| edition          | format    |
+------------------+-----------+
| 75th anniversary | hardcover |
+------------------+-----------+
WHY JSON_SET adds or replaces · JSON_INSERT only adds · JSON_REPLACE only replaces
7.3 · Code

JSON from rows

SELECT JSON_OBJECT('id', id, 'title', title, 'price', price) AS item
FROM books
WHERE id <= 3
ORDER BY id;
+-------------------------------------------------------------+
| item                                                        |
+-------------------------------------------------------------+
| {"id": 1, "price": 14.99, "title": "Dune"}                  |
| {"id": 2, "price": 9.99, "title": "1984"}                   |
| {"id": 3, "price": 11.99, "title": "To Kill a Mockingbird"} |
+-------------------------------------------------------------+
WHY JSON_ARRAYAGG and JSON_OBJECTAGG build JSON from a group of rows.
7.3 · Code

JSON back to rows

SELECT b.title, aw.award
FROM books AS b,
     JSON_TABLE(b.attributes, '$.awards[*]' COLUMNS (award VARCHAR(40) PATH '$')) AS aw
ORDER BY b.title, aw.award;
+-------+--------+
| title | award  |
+-------+--------+
| Dune  | Hugo   |
| Dune  | Nebula |
+-------+--------+
WHY One row per array element. Books with no awards produce no rows.
7.3 · Code

Index a path

ALTER TABLE books
    ADD COLUMN format VARCHAR(20)
        GENERATED ALWAYS AS (attributes->>'$.format') VIRTUAL,
    ADD INDEX idx_books_format (format);
SELECT title, format FROM books WHERE format = 'hardcover' ORDER BY title;
+-------------------+-----------+
| title             | format    |
+-------------------+-----------+
| Lord of the Rings | hardcover |
| The Hobbit        | hardcover |
+-------------------+-----------+
WHY EXPLAIN on the original ->> query: Index lookup ... idx_books_format
7.3 · Silent mistake 1

A misspelled key

SELECT title
FROM books
WHERE attributes->>'$.Format' = 'hardcover';
Empty set
WATCH Keys are case-sensitive, and a missing key is NULL: nothing matches, nothing warns.
7.3 · Silent mistake 2

The single arrow on a web page

SELECT CONCAT(title, ' (', attributes->'$.format', ')') AS label

+--------------------+

+--------------------+
