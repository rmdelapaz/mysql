2.2

Data Types & Constraints

Stop bad data at the door, not in next month's report.

2.2 · Mental model

A value at the door

  1. Does it fit the column's type?
  2. Does it pass the constraints?
  3. Yes and yes: stored · otherwise: refused, with a number
WHY Strict mode (STRICT_TRANS_TABLES) is the default: keep it on.
2.2 · Choosing

The type that says what the value is

  • Ids and counts: INT, UNSIGNED when negatives are nonsense
  • Money: DECIMAL(8, 2), never FLOAT
  • Names, emails, phone numbers: VARCHAR(n) · fixed codes: CHAR(n)
  • Dates: DATE · moments: DATETIME (TIMESTAMP ends in 2038)
  • Yes/no: BOOLEAN · a short fixed list: ENUM
2.2 · Code

A number that does not fit

INSERT INTO number_demo (stars) VALUES (200);  -- stars is TINYINT
ERROR 1264 (22003): Out of range value for column 'stars' at row 1
WHY TINYINT stops at 127. Strict mode refuses instead of clamping.
2.2 · Code

Why money is never FLOAT

SELECT
    price * 3        AS decimal_times_3,
    weight_kg * 3    AS float_times_3,
    weight_kg = 0.1  AS float_equals_0_1
FROM number_demo
WHERE stars = 5;
+-----------------+---------------------+------------------+
| decimal_times_3 | float_times_3       | float_equals_0_1 |
+-----------------+---------------------+------------------+
|           44.97 | 0.30000000447034836 |                0 |
+-----------------+---------------------+------------------+
RULE DECIMAL is exact. FLOAT's crumbs add up to money no report can explain.
2.2 · Text, dates, lists

Refused, each with a number

INSERT INTO text_demo (label) VALUES ('Fahrenheit 451');   -- VARCHAR(5)
INSERT INTO date_demo (d) VALUES ('2026-02-30');
INSERT INTO date_demo (d) VALUES ('03/10/2026');
INSERT INTO format_demo (title, format) VALUES ('1984', 'audiobook');
ERROR 1406 (22001): Data too long for column 'label' at row 1
ERROR 1292 (22007): Incorrect date value: '2026-02-30' for column 'd' at row 1
ERROR 1292 (22007): Incorrect date value: '03/10/2026' for column 'd' at row 1
ERROR 1265 (01000): Data truncated for column 'format' at row 1
WHY Dates are year first: '2026-03-10'.
2.2 · Code

A table with every kind of rule

CREATE TABLE coupons (
    id           INT AUTO_INCREMENT PRIMARY KEY,
    code         VARCHAR(20) NOT NULL UNIQUE,
    percent_off  TINYINT UNSIGNED NOT NULL,
    min_order    DECIMAL(8, 2) NOT NULL DEFAULT 0.00,
    expires      DATE,
    CONSTRAINT chk_coupon_percent CHECK (percent_off BETWEEN 5 AND 50)
);
WHY Name the CHECK: the error then says which rule failed.

BOOLEAN is a small number

SELECT title, in_stock FROM flag_demo WHERE in_stock = TRUE;

WATCH = TRUE means = 1. Write WHERE in_stock.

2.3

CRUD Operations

Add, read, change and remove exactly the rows you mean.

2.3 · Mental model

WHERE picks the rows

  • INSERT adds · SELECT reads · UPDATE changes · DELETE removes
  • UPDATE and DELETE touch every row the WHERE matches
  • No WHERE: every row in the table. No undo.
  • Preview → same WHERE → compare the counts
WHY Read the second line: Rows matched, Changed.
2.3 · Code

Create, then read the new id

INSERT INTO books (title, author, price, pages, published)
VALUES ('Dune', 'Frank Herbert', 12.99, 412, '1965-08-01');
SELECT LAST_INSERT_ID();
+------------------+
| LAST_INSERT_ID() |
+------------------+
|                1 |
+------------------+
WHY List the columns; id and in_stock fill themselves.
2.3 · Code

A calculated column with an alias

SELECT
    title,
    price,
    ROUND(price * 1.08, 2) AS price_with_tax
FROM books
WHERE price > 11;
+-----------------------+-------+----------------+
| title                 | price | price_with_tax |
+-----------------------+-------+----------------+
| Dune                  | 12.99 |          14.03 |
| To Kill a Mockingbird | 11.99 |          12.95 |
| Lord of the Rings     | 15.99 |          17.27 |
+-----------------------+-------+----------------+
WHY A calculation never changes the table.
2.3 · Code

Update, and read the second line

UPDATE books
SET price = 14.99
WHERE id = 1;
-- the same statement again
Query OK, 1 row affected
Rows matched: 1  Changed: 1  Warnings: 0
Query OK, 0 rows affected
Rows matched: 1  Changed: 0  Warnings: 0
WHY Matched 1, Changed 0: the price was already 14.99.
2.3 · Code

Preview first, then the same WHERE

SELECT id, title, price
FROM books
WHERE price > 10
ORDER BY id;
+----+-----------------------+-------+
| id | title                 | price |
+----+-----------------------+-------+
|  1 | Dune                  | 14.99 |
|  3 | To Kill a Mockingbird | 11.99 |
|  6 | The Hobbit            | 10.99 |
|  9 | Lord of the Rings     | 15.99 |
| 10 | Fahrenheit 451        | 10.49 |
+----+-----------------------+-------+
WHY Then UPDATE books SET price = ROUND(price * 0.90, 2) WHERE price > 10;: Rows matched: 5 Changed: 5 Warnings: 0
2.3 · Code

Ids are never reused

DELETE FROM books WHERE id = 10;
INSERT INTO books (title, author, price, pages, published)
VALUES ('Fahrenheit 451', 'Ray Bradbury', 10.49, 158, '1953-10-19');
SELECT id, title FROM books WHERE title = 'Fahrenheit 451';
+----+----------------+
| id | title          |
+----+----------------+
| 11 | Fahrenheit 451 |
+----+----------------+
WHY Never fill gaps: a receipt may still say id 10.
2.3 · Upsert

Insert it, or update it

INSERT INTO categories (name, description)
VALUES ('Fiction', 'Imaginative prose of every kind') AS new
ON DUPLICATE KEY UPDATE description = new.description;
Query OK, 2 rows affected
WHY 1 inserted · 2 updated · 0 unchanged. MariaDB: VALUES(description).
2.3 · Safety

The switch that catches a missing WHERE

SET SQL_SAFE_UPDATES = 1;
UPDATE books SET price = 0;
ERROR 1175 (HY000): You are using safe update mode and
  you tried to update a table without a WHERE that uses a KEY column.
TIP Permanently: mysql --safe-updates -u root -p
2.3 · The silent trap

AND instead of a comma

UPDATE books
SET price = 15.99 AND in_stock = FALSE
WHERE id = 1;
SELECT title, price, in_stock FROM books WHERE id = 1;
Query OK, 1 row affected
Rows matched: 1  Changed: 1  Warnings: 0
+-------+-------+----------+
| title | price | in_stock |
+-------+-------+----------+
| Dune  |  0.00 |        1 |
+-------+-------+----------+
WATCH Assignments are separated by commas: SET price = 15.99, in_stock = FALSE
