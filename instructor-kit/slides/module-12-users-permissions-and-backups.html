7.4

User Management & Permissions

Every person and program gets only what its job needs.

7.4 · Mental model

Why not root?

  • A clerk's DELETE without WHERE: every customer gone
  • An attacker in the search box: reads everything, drops databases
  • A dashboard password in a shared config file
  • Least privilege: the minimum for the job, nothing more
7.4 · Mental model

GRANT what ON where TO whom

  • An account is 'user'@'host': another host is another account
  • Levels: *.* · bookstore.* · bookstore.books · SELECT (id, email)
  • A new account has only USAGE: it may connect
  • Grant the narrowest level that works; test it as the account
7.4 · Code

An account, and what it may do

GRANT SELECT ON bookstore.* TO 'shop_reports'@'localhost';
SHOW GRANTS FOR 'shop_reports'@'localhost';
+-------------------------------------------------------------+
| Grants for shop_reports@localhost                           |
+-------------------------------------------------------------+
| GRANT USAGE ON *.* TO `shop_reports`@`localhost`            |
| GRANT SELECT ON `bookstore`.* TO `shop_reports`@`localhost` |
+-------------------------------------------------------------+
WHY No FLUSH PRIVILEGES: grants take effect at once.

7.4 · Error ladder

Which refusal is which?

  • 1045 wrong password · 1044 no access to that database
  • 1142 table denied · 1143 column denied
  • 3118 the account is locked
  • 1524 mysql_native_password: update the driver

7.4 · Lock and refuse

Disable, do not delete

ALTER USER 'shop_reports'@'localhost' ACCOUNT LOCK;
ERROR 3118 (HY000): Access denied for user 'shop_reports'@'localhost'. Account is locked.
  • The account keeps its grants; UNLOCK opens it again
  • Never practice on root or CURRENT_USER()

8.1

Importing & Exporting Data

A backup you have restored, and data in and out of spreadsheets.

8.1 · Mental model

Two kinds of moving data

  • Whole databases: mysqldump at the terminal, restored with mysql
  • Rows: SELECT ... INTO OUTFILE and LOAD DATA at mysql>
  • Server-side files: one folder, secure_file_priv
  • A backup you have never restored is a hope
8.1 · Terminal

A backup on 9.7

mysqldump -u root -p --single-transaction --routines --events \
    --set-gtid-purged=OFF bookstore > bookstore_backup.sql
WHY --routines and --events are off by default. --set-gtid-purged=OFF: next slides.
8.1 · Terminal

Restore, then compare

mysql -u root -p -t -e "SELECT
    (SELECT COUNT(*) FROM bookstore.order_items) AS items_original,
    (SELECT COUNT(*) FROM bookstore_test.order_items) AS items_copy"
+----------------+------------+
| items_original | items_copy |
+----------------+------------+
|             18 |         18 |
+----------------+------------+
WHY First CREATE DATABASE bookstore_test, then mysql ... bookstore_test < bookstore_backup.sql. Same counts: now it is a backup.
8.1 · The 9.7 trap

A plain dump will not restore here

mysqldump -u root -p --single-transaction bookstore > plain_dump.sql
  • Warning: A partial dump from a server that has GTIDs will by...
  • Restoring it into another database on the same server:
  • ERROR 3546 (HY000): @@GLOBAL.GTID_PURGED cannot be changed: th...
  • No tables created. Dump again with --set-gtid-purged=OFF

FIX Type exit, then run it at $ or PS>.
8.1 · Files

Where the server may read and write

  • SHOW VARIABLES LIKE 'secure_file_priv';
  • Linux packages and Docker: /var/lib/mysql-files/
  • Empty = anywhere (unsafe) · NULL = nowhere
  • Anywhere else: ERROR 1290 · an existing file: ERROR 1086
8.1 · Code

Export a CSV

SELECT b.id, b.title, a.name AS author, b.price, b.published
FROM books AS b
JOIN authors AS a ON a.id = b.author_id
ORDER BY b.id
INTO OUTFILE '/var/lib/mysql-files/books_export.csv'
    FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
    LINES TERMINATED BY '\n';
Query OK, 11 rows affected
1,"Dune","Frank Herbert",14.99,"1965-08-01"
2,"1984","George Orwell",9.99,"1949-06-08"
WHY Text and dates in quotes, numbers bare. NULL is written as \N.
8.1 · Import

A messy file: look before you load

  • A header line: IGNORE 1 LINES
  • A comma inside "I, Robot": OPTIONALLY ENCLOSED BY
  • US dates: STR_TO_DATE(@d, '%m/%d/%Y')
  • An empty page count: NULLIF(@pages, '')
  • An author the store does not know yet
RULE Never load a stranger's file straight into a real table.
8.1 · Code

Into a staging table

LOAD DATA INFILE '/var/lib/mysql-files/new_books.csv'
INTO TABLE import_books
    FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
    LINES TERMINATED BY '\n'
    IGNORE 1 LINES
    (title, author, price, @pages, @published)
SET pages     = NULLIF(@pages, ''),
    published = STR_TO_DATE(@published, '%m/%d/%Y');
Query OK, 4 rows affected
Records: 4  Deleted: 0  Skipped: 0  Warnings: 0
