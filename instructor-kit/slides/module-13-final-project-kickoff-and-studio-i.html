8.2 · Mental model

From requirements to tables

  1. Nouns become tables; facts become columns
  2. Verbs become relationships: one or many, both ways?
  3. Rules get a home: constraint, foreign key or procedure
  4. Derived values are computed, never stored
8.2 · Where rules live

One row, or other rows?

One valuetype, NOT NULL, UNIQUE, ENUM, CHECK
Between tablesFOREIGN KEY
Other rowsthe procedure that writes, in a transaction
Today's datethe query (@today), never a CHECK
WHY "At most three tools" counts other rows: it can never be a CHECK.
8.2 · Mistake 1

A reserved word as a column name

CREATE TABLE demo_tools (
    id        INT AUTO_INCREMENT PRIMARY KEY,
    condition VARCHAR(10)
);
ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that
    corresponds to your MySQL server version for the right syntax to use near
    'condition VARCHAR(10)
)' at line 3
FIX Rename it: tool_condition. Same trap: order, group, rank, key.
8.2 · Mistake 2

A foreign key whose type does not match

CREATE TABLE demo_loans (
    id      INT AUTO_INCREMENT PRIMARY KEY,
    tool_id BIGINT NOT NULL,
    FOREIGN KEY (tool_id) REFERENCES demo_tools (id)
);
ERROR 3780 (HY000): Referencing column 'tool_id' and referenced column 'id' in foreign
    key constraint 'demo_loans_ibfk_1' are incompatible.
FIX INT and BIGINT clash; so do INT and INT UNSIGNED. One key type everywhere.
8.2 · Mistake 3

Today's date in a CHECK

CREATE TABLE demo_loans (
    id     INT AUTO_INCREMENT PRIMARY KEY,
    due_on DATE NOT NULL,
    CONSTRAINT chk_due_future CHECK (due_on >= CURDATE())
);
ERROR 3814 (HY000): An expression of a check constraint 'chk_due_future' contains
    disallowed function: curdate.
FIX Compare columns of the row: due_on >= loaned_on.
8.2 · Mistake 4

The child before the parent

CREATE TABLE demo_courses_done (
    member_id INT NOT NULL,
    FOREIGN KEY (member_id) REFERENCES demo_members (id)
);
ERROR 1824 (HY000): Failed to open the referenced table 'demo_members'
FIX Parents first, junction and history tables last; drop in reverse.
8.2 · Mistake 5 · predict first

June loans per member, zeros included

SELECT m.name, COUNT(l.member_id) AS june_loans
FROM demo_members AS m
LEFT JOIN demo_member_loans AS l ON l.member_id = m.id
WHERE l.loaned_on >= '2026-06-01'
GROUP BY m.id, m.name
ORDER BY m.name;
  • Rosa June · Kevin May · Tessa none
  • How many rows come back?
8.2 · Mistake 5

Silent: two members vanish

SELECT m.name, COUNT(l.member_id) AS june_loans
FROM demo_members AS m
LEFT JOIN demo_member_loans AS l ON l.member_id = m.id
WHERE l.loaned_on >= '2026-06-01'
GROUP BY m.id, m.name
ORDER BY m.name;
+------+------------+
| name | june_loans |
+------+------------+
| Rosa |          1 |
+------+------------+
WATCH WHERE runs after the join and drops the NULL rows. The LEFT does nothing.
8.2 · The fix

Conditions on the right table go in ON

SELECT m.name, COUNT(l.member_id) AS june_loans
FROM demo_members AS m
LEFT JOIN demo_member_loans AS l
       ON l.member_id = m.id AND l.loaned_on >= '2026-06-01'
GROUP BY m.id, m.name
ORDER BY m.name;
+-------+------------+
| name  | june_loans |
+-------+------------+
| Kevin |          0 |
| Rosa  |          1 |
| Tessa |          0 |
+-------+------------+

8.2 · Guided lab

Every rule named

CREATE TABLE gift_cards (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    code        CHAR(8)       NOT NULL,
    customer_id INT           NOT NULL,
    amount      DECIMAL(8, 2) NOT NULL,
    issued_on   DATE          NOT NULL,
    expires_on  DATE          NOT NULL,
    CONSTRAINT uq_gift_cards_code     UNIQUE (code),
    CONSTRAINT fk_gift_cards_customer FOREIGN KEY (customer_id) REFERENCES customers (id),
    CONSTRAINT chk_gift_cards_amount  CHECK (amount > 0),
    CONSTRAINT chk_gift_cards_dates   CHECK (expires_on > issued_on)
);
WHY An error that names chk_gift_cards_dates explains itself; gift_cards_chk_2 does not.
8.2 · Guided lab

Proof: each bad row refused

START TRANSACTION;
INSERT INTO gift_cards (code, customer_id, amount, issued_on, expires_on)
VALUES ('GCTEST03', 1, 25.00, '2026-06-01', '2026-05-01');
INSERT INTO gift_cards (code, customer_id, amount, issued_on, expires_on)
VALUES ('GCTEST04', 99, 25.00, '2026-06-01', '2027-06-01');
ROLLBACK;
ERROR 3819 (HY000): Check constraint 'chk_gift_cards_dates' is violated.
ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails
    (`bookstore`.`gift_cards`, CONSTRAINT `fk_gift_cards_customer` FOREIGN KEY
    (`customer_id`) REFERENCES `customers` (`id`))
WHY Tests in a transaction, then ROLLBACK: no test row ever stays.

8.2 · The test pattern

A failed statement undoes only itself

INSERT INTO loans (tool_id, member_id, loaned_on, due_on)
VALUES (1, 1, '2026-06-10', '2026-06-03');

ROLLBACK;

SELECT COUNT(*) AS members_left FROM members;
ERROR 3819 (HY000): Check constraint 'chk_loans_due' is violated.
+--------------+
| members_left |
+--------------+
|            0 |
+--------------+
WHY Inside START TRANSACTION, with one parent row each; ROLLBACK at the end.
