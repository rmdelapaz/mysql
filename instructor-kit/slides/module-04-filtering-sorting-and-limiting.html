3.1

WHERE Clauses, Operators & Filtering

Ask for exactly the rows you mean.

3.1 · Mental model

A test on every row

  1. MySQL runs the condition on each row
  2. The answer is true, false, or unknown (a NULL is involved)
  3. Only true rows are kept
WHY Say how many rows you expect before you run it.
3.1 · Code

WHERE, and the test as a column

SELECT title, price, price < 10 AS passes
FROM books
ORDER BY id
LIMIT 4;
+-----------------------+-------+--------+
| title                 | price | passes |
+-----------------------+-------+--------+
| Dune                  | 14.99 |      0 |
| 1984                  |  9.99 |      1 |
| To Kill a Mockingbird | 11.99 |      0 |
| The Great Gatsby      |  8.99 |      1 |
+-----------------------+-------+--------+
WHY A condition is a value: 1, 0 or NULL.
3.1 · Code

Eight customers, two in New York

SELECT first_name, city
FROM customers
WHERE city != 'New York'
ORDER BY first_name;
+------------+-------------+
| first_name | city        |
+------------+-------------+
| Bob        | Chicago     |
| Carol      | Los Angeles |
| Dave       | Houston     |
| Grace      | Chicago     |
+------------+-------------+
COUNT Only four: Eve and Hank have no city, and unknown is dropped.
3.1 · Operators

Combine and match

  • AND narrows · OR widens · NOT flips
  • IN (...) a list · BETWEEN a AND b both ends included
  • LIKE: % any characters, _ exactly one
  • DATETIME: >= '2026-01-01' AND < '2026-02-01'
3.1 · Code

LIKE: contains

SELECT title
FROM books
WHERE title LIKE '%the%'
ORDER BY title;
+------------------------+
| title                  |
+------------------------+
| Lord of the Rings      |
| The Catcher in the Rye |
| The Great Gatsby       |
| The Hobbit             |
+------------------------+
WHY Case-insensitive: 'the' finds The.
3.1 · NULL

Unknown, even compared with itself

SELECT
    NULL = NULL   AS equals,
    NULL != 'x'   AS not_equals,
    NULL IS NULL  AS is_null;
+--------+------------+---------+
| equals | not_equals | is_null |
+--------+------------+---------+
|   NULL |       NULL |       1 |
+--------+------------+---------+
WHY Test missing values with IS NULL.
3.1 · NULL

Keep the NULL rows on purpose

SELECT first_name, city
FROM customers
WHERE city != 'New York' OR city IS NULL
ORDER BY first_name;
+------------+-------------+
| first_name | city        |
+------------+-------------+
| Bob        | Chicago     |
| Carol      | Los Angeles |
| Dave       | Houston     |
| Eve        | NULL        |
| Grace      | Chicago     |
| Hank       | NULL        |
+------------+-------------+
WHY Six now: Eve and Hank are back.
3.1 · Precedence

AND before OR

SELECT title, author, price
FROM books
WHERE author = 'J.R.R. Tolkien' OR author = 'George Orwell' AND price < 12
ORDER BY price;
+-------------------+----------------+-------+
| title             | author         | price |
+-------------------+----------------+-------+
| 1984              | George Orwell  |  9.99 |
| The Hobbit        | J.R.R. Tolkien | 10.99 |
| Lord of the Rings | J.R.R. Tolkien | 15.99 |
+-------------------+----------------+-------+
WATCH Lord of the Rings at 15.99 got in: A OR (B AND C).
3.1 · Precedence

Parentheses say what you meant

SELECT title, author, price
FROM books
WHERE (author = 'J.R.R. Tolkien' OR author = 'George Orwell')
  AND price < 12
ORDER BY price;
+------------+----------------+-------+
| title      | author         | price |
+------------+----------------+-------+
| 1984       | George Orwell  |  9.99 |
| The Hobbit | J.R.R. Tolkien | 10.99 |
+------------+----------------+-------+
WHY Mixing AND and OR? Always add them.
3.1 · Mistakes

Loud and silent

SELECT title FROM books WHERE author = Tolkien;
SELECT first_name, city FROM customers WHERE city = NULL;
ERROR 1054 (42S22): Unknown column 'Tolkien' in 'where clause'
Empty set
WATCH The silent one: = NULL finds nothing. IS NULL.

3.2

Sorting & Limiting Results

An order you can trust, and the right slice of it.

3.2 · Mental model

A table has no order

  • Without ORDER BY: whatever is cheapest for the server
  • ASC is the default; DESC belongs to one column
  • Extra columns break ties: end with a unique one
  • FROM → WHERE → SELECT → ORDER BY → LIMIT
3.2 · Code

A direction per column

SELECT title, in_stock, price
FROM books
WHERE price < 10
ORDER BY in_stock DESC, price, title;
+------------------------+----------+-------+
| title                  | in_stock | price |
+------------------------+----------+-------+
| Pride and Prejudice    |        1 |  7.99 |
| Brave New World        |        1 |  9.49 |
| 1984                   |        1 |  9.99 |
| The Catcher in the Rye |        0 |  8.99 |
| The Great Gatsby       |        0 |  8.99 |
+------------------------+----------+-------+
WHY In stock first (1 before 0), then cheapest.
3.2 · Code

A custom order with CASE

SELECT first_name, city
FROM customers
ORDER BY
    CASE city
        WHEN 'Chicago'  THEN 1
        WHEN 'New York' THEN 2
        ELSE 3
    END,
    first_name;
+------------+-------------+
| first_name | city        |
+------------+-------------+
| Bob        | Chicago     |
| Grace      | Chicago     |
| Alice      | New York    |
| Frank      | New York    |
| Carol      | Los Angeles |
| Dave       | Houston     |
| Eve        | NULL        |
| Hank       | NULL        |
+------------+-------------+
3.2 · NULLs

Missing values last

SELECT first_name, city
FROM customers
ORDER BY city IS NULL, city, first_name;
+------------+-------------+
| first_name | city        |
+------------+-------------+
| Bob        | Chicago     |
| Grace      | Chicago     |
| Dave       | Houston     |
| Carol      | Los Angeles |
| Alice      | New York    |
| Frank      | New York    |
| Eve        | NULL        |
| Hank       | NULL        |
+------------+-------------+
WHY MySQL has no NULLS LAST: col IS NULL, col.
3.2 · Code

Top 3

SELECT title, pages
FROM books
ORDER BY pages DESC
LIMIT 3;
+---------------------+-------+
| title               | pages |
+---------------------+-------+
| Lord of the Rings   |  1178 |
| Pride and Prejudice |   432 |
| Dune                |   412 |
+---------------------+-------+
WHY LIMIT runs last: filter, sort, then cut.
3.2 · Code

OFFSET: rows 4 to 6

SELECT title, price
FROM books
ORDER BY price, title
LIMIT 3 OFFSET 3;
+-----------------+-------+
| title           | price |
+-----------------+-------+
| Brave New World |  9.49 |
| 1984            |  9.99 |
| Fahrenheit 451  | 10.49 |
+-----------------+-------+
WHY Same ORDER BY, with a tie-breaker, on every page.
3.2 · Pages

Page 2 of the catalog

SELECT title, price
FROM books
ORDER BY title
LIMIT 4 OFFSET 4;
+------------------------+-------+
| title                  | price |
+------------------------+-------+
| Lord of the Rings      | 15.99 |
| Pride and Prejudice    |  7.99 |
| The Catcher in the Rye |  8.99 |
| The Great Gatsby       |  8.99 |
+------------------------+-------+
WHY Page count: CEILING(COUNT(*) / 4) = 3 (10 books). Page N: OFFSET (N - 1) x 4.
3.2 · Keyset

The page after id 4

SELECT id, title
FROM books
WHERE id > 4
ORDER BY id
LIMIT 4;
+----+------------------------+
| id | title                  |
+----+------------------------+
|  5 | Pride and Prejudice    |
|  6 | The Hobbit             |
|  7 | Brave New World        |
|  8 | The Catcher in the Rye |
+----+------------------------+
WHY No jump to page 37, but fast however deep.
