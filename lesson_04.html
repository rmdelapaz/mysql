🗄️ Creating and Managing Databases

One MySQL server can hold many databases, and each database holds many tables. Think of a filing cabinet: the server is the cabinet, each database is a drawer, and each table is a folder in that drawer. A database is mostly a name and a few settings; the data itself lives in the tables.

graph TD A["MySQL server"] --> B["database: bookstore"] A --> C["database: mysql (system)"] B --> D["table: books"] B --> E["table: customers"]

💡 Follow along

Open the mysql client (mysql -u root -p) or phpMyAdmin's SQL tab and type each statement as you read. Every output on this page is what MySQL 9.7 really printed for that statement, so yours should match.

CREATE DATABASE

CREATE DATABASE bookstore;

Output

Query OK, 1 row affected (0.01 sec)

"Query OK" means the statement worked. Check that the new database is there:

SHOW DATABASES;

Output

+--------------------+
| Database           |
+--------------------+
| bookstore          |
| information_schema |
| mysql              |
| performance_schema |
| sys                |
+--------------------+

The other four are MySQL's own system databases, which you met in Lesson 1.3. Leave them alone.

USE: pick the database you are working in

USE bookstore;
SELECT DATABASE();

Output

Database changed
+------------+
| DATABASE() |
+------------+
| bookstore  |
+------------+

From now on, every table name you type means "the table in bookstore". SELECT DATABASE(); answers "where am I?" whenever you are not sure.

IF NOT EXISTS: create only when missing

Creating a database that already exists is an error (you will see it in Common Mistakes). Add IF NOT EXISTS and MySQL skips the creation with a note instead:

CREATE DATABASE IF NOT EXISTS bookstore;
SHOW WARNINGS;

Output

Query OK, 1 row affected, 1 warning (0.00 sec)
+-------+------+----------------------------------------------------+
| Level | Code | Message                                            |
+-------+------+----------------------------------------------------+
| Note  | 1007 | Can't create database 'bookstore'; database exists |
+-------+------+----------------------------------------------------+
1 row in set (0.00 sec)

The client says "1 warning" but nothing changed: the existing database and its tables are untouched. SHOW WARNINGS displays the notes and warnings of the statement you just ran; make it a habit whenever you see a warning count.

DROP DATABASE

DROP DATABASE deletes a database and every table and row in it:

DROP DATABASE bookstore;
DROP DATABASE IF EXISTS bookstore;

Output

Query OK, 0 rows affected (0.01 sec)
Query OK, 0 rows affected, 1 warning (0.00 sec)

The first statement dropped the (still empty) database. The second found nothing to drop, and IF EXISTS turned what would have been an error into a warning.

🛑 There is no undo

DROP DATABASE asks no questions, has no recycle bin and cannot be rolled back. On your practice server that is fine; on a server with real data, only a backup (Lesson 8.1) brings it back. Before you press Enter on any DROP, read the name twice and run SELECT DATABASE(); to see where you are.

🔤 Character Sets and Collations

Every database has two text settings that its tables inherit:

  • The character set decides which characters can be stored. utf8mb4 stores every Unicode character: accents, Chinese, Arabic, emoji.
  • The collation decides how text is compared and sorted: is 'dune' equal to 'Dune', and does é sort with e? Collations ending in _ci are case-insensitive.

Create the bookstore again, this time saying exactly what you want:

CREATE DATABASE bookstore
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;
SHOW CREATE DATABASE bookstore;

Output

+-----------+-------------------------------------------------------------------------------------------------------------------------------------+
| Database  | Create Database                                                                                                                     |
+-----------+-------------------------------------------------------------------------------------------------------------------------------------+
| bookstore | CREATE DATABASE `bookstore` /*!40100 DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci */ /*!80016 DEFAULT ENCRYPTION='N' */ |
+-----------+-------------------------------------------------------------------------------------------------------------------------------------+

SHOW CREATE DATABASE prints the statement that would recreate the database. The /*!40100 ... */ parts are "versioned comments": MySQL runs what is inside, other databases skip it. You can ignore them.

🐬 Version note: why name the collation?

utf8mb4 is already the default in MySQL 8.0 and later, but the default collation differs between servers: MySQL 9.7 and 8.4 use utf8mb4_0900_ai_ci, MariaDB uses utf8mb4_uca1400_ai_ci. Both are case-insensitive, but they can sort a few characters differently. This course names utf8mb4_unicode_ci, which all three servers support, so your results match the ones shown here wherever you run them.

Never write utf8

For historical reasons, MySQL's utf8 is a three-byte subset now called utf8mb3: it cannot store emoji or some rarer characters. MySQL warns you when you ask for it. Try it on a throwaway database:

CREATE DATABASE sandbox CHARACTER SET utf8;
SHOW WARNINGS;

Output

Query OK, 1 row affected, 1 warning (0.01 sec)
+---------+------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| Level   | Code | Message                                                                                                                                                                     |
+---------+------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------+
| Warning | 3719 | 'utf8' is currently an alias for the character set UTF8MB3, but will be an alias for UTF8MB4 in a future release. Please consider using UTF8MB4 in order to be unambiguous. |
+---------+------+-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------+

The message says it all: write utf8mb4. Remove the throwaway database and go back to the bookstore:

DROP DATABASE sandbox;
USE bookstore;

Output

Database changed

🏷️ Naming Conventions

Names are the part of a database people read most. These are the conventions used in this course and by most MySQL teams:

RuleGoodAvoid
Lowercase everythingcustomersCustomers, CUSTOMERS
snake_case for several wordsorder_itemsorderItems, OrderItems
Tables are plural nounsbooks, categoriesbook, tbl_book
Columns are singular and descriptivefirst_name, publishedfn, data1
The primary key is ididbookID, pk_book
A link to another table is singular_table_idcustomer_idcustID, cust
No reserved wordsorders, order_dateorder, select, table

💡 Why lowercase matters

MySQL stores each table as a file, so whether Books and books are the same table depends on the operating system: on Linux (most servers) they are different, on Windows and macOS they are the same. A database built with mixed-case names on a laptop can break when it moves to a Linux server. All-lowercase names never have that problem.

A good test for a name: would a new teammate know what the column holds without asking you? published passes; pd does not.

📐 Creating Tables

CREATE TABLE names a table and lists its columns. Each column gets a name, a data type, and optionally some constraints (rules). The general shape:

CREATE TABLE table_name (
    column_name  DATA_TYPE  [constraints],
    column_name  DATA_TYPE  [constraints],
    ...
);

Here is the bookstore's first table. Type it in carefully: commas between the column lines, none after the last one.

CREATE TABLE books (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    title       VARCHAR(200) NOT NULL,
    author      VARCHAR(100) NOT NULL,
    price       DECIMAL(8, 2) NOT NULL,
    pages       INT,
    published   DATE,
    in_stock    BOOLEAN DEFAULT TRUE
);

Output

Query OK, 0 rows affected (0.02 sec)

"0 rows affected" is normal: the table exists, but it is empty. Here is what each line asks for:

ColumnDefinitionMeaning
idINT AUTO_INCREMENT PRIMARY KEYA whole number MySQL fills in for you (1, 2, 3...); it identifies each row
titleVARCHAR(200) NOT NULLText of up to 200 characters; every book must have one
authorVARCHAR(100) NOT NULLText of up to 100 characters; required
priceDECIMAL(8, 2) NOT NULLAn exact number with 2 decimal places, up to 999999.99; required
pagesINTA whole number; may be left empty (NULL) if unknown
publishedDATEA date written 'YYYY-MM-DD'; may be empty
in_stockBOOLEAN DEFAULT TRUETrue or false; true unless you say otherwise

💡 A first look at types and constraints

For now: INT is a whole number, VARCHAR(n) is text up to n characters, DECIMAL(m, d) is an exact decimal, DATE is a date and BOOLEAN is true/false. PRIMARY KEY, AUTO_INCREMENT, NOT NULL, DEFAULT and UNIQUE are constraints. Lesson 2.2 explains every one of them, with the errors they produce.

CREATE TABLE IF NOT EXISTS

Like databases, tables can be created "only if missing". If the table is already there, MySQL leaves it exactly as it is, even if your new definition is different:

CREATE TABLE IF NOT EXISTS books (
    id    INT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(200) NOT NULL
);
SHOW WARNINGS;

Output

Query OK, 0 rows affected, 1 warning (0.00 sec)
+-------+------+------------------------------+
| Level | Code | Message                      |
+-------+------+------------------------------+
| Note  | 1050 | Table 'books' already exists |
+-------+------+------------------------------+
1 row in set (0.00 sec)

The two-column definition was ignored; books still has its seven columns. IF NOT EXISTS protects existing data, but it will not update a table whose definition has changed. That is what ALTER TABLE is for.

📚 Building the Bookstore Tables

The bookstore needs two more tables for now: its customers and the categories its books belong to. Later modules add authors, orders and staff.

CREATE TABLE customers (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    first_name  VARCHAR(50) NOT NULL,
    last_name   VARCHAR(50) NOT NULL,
    email       VARCHAR(100) NOT NULL UNIQUE,
    city        VARCHAR(50),
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE categories (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    name        VARCHAR(50) NOT NULL UNIQUE,
    description VARCHAR(255)
);

Output

Query OK, 0 rows affected (0.02 sec)
Query OK, 0 rows affected (0.02 sec)

Two new pieces:

  • UNIQUE on email and on name: no two customers can share an email address, and no two categories can share a name.
  • DATETIME DEFAULT CURRENT_TIMESTAMP: when a row is added without a created_at value, MySQL stores the current date and time.
SHOW TABLES;

Output

+---------------------+
| Tables_in_bookstore |
+---------------------+
| books               |
| categories          |
| customers           |
+---------------------+

✅ You just built a database

Three tables, sensibly named, each with a primary key and the right types. You will fill them with rows in Lesson 2.3, query them all through Module 3, and connect them to new tables in Module 4.

🔍 Inspecting Your Work

After you create or change a table, look at what MySQL actually stored. Two commands cover almost every need.

DESCRIBE: the column overview

DESCRIBE books;

Output

+-----------+--------------+------+-----+---------+----------------+
| Field     | Type         | Null | Key | Default | Extra          |
+-----------+--------------+------+-----+---------+----------------+
| id        | int          | NO   | PRI | NULL    | auto_increment |
| title     | varchar(200) | NO   |     | NULL    |                |
| author    | varchar(100) | NO   |     | NULL    |                |
| price     | decimal(8,2) | NO   |     | NULL    |                |
| pages     | int          | YES  |     | NULL    |                |
| published | date         | YES  |     | NULL    |                |
| in_stock  | tinyint(1)   | YES  |     | 1       |                |
+-----------+--------------+------+-----+---------+----------------+

Read it row by row: Null says whether the column may be empty (NO = NOT NULL), Key shows PRI for the primary key (and UNI for a unique column), Default is the value used when you give none. DESC books; is a shorter spelling of the same command.

SHOW CREATE TABLE: the full definition

SHOW CREATE TABLE books\G

Output

*************************** 1. row ***************************
       Table: books
Create Table: CREATE TABLE `books` (
  `id` int NOT NULL AUTO_INCREMENT,
  `title` varchar(200) COLLATE utf8mb4_unicode_ci NOT NULL,
  `author` varchar(100) COLLATE utf8mb4_unicode_ci NOT NULL,
  `price` decimal(8,2) NOT NULL,
  `pages` int DEFAULT NULL,
  `published` date DEFAULT NULL,
  `in_stock` tinyint(1) DEFAULT '1',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci

The \G ending (instead of ;) prints the result vertically, which keeps long text readable. This is the exact statement that would rebuild the table, and it shows a few things MySQL did on its own:

  • BOOLEAN became tinyint(1) and DEFAULT TRUE became DEFAULT '1': MySQL stores true as 1 and false as 0.
  • The table uses the InnoDB storage engine (the default, and the one you want) and inherited utf8mb4 / utf8mb4_unicode_ci from the database.
  • Text columns list their collation because it differs from the server's default, utf8mb4_0900_ai_ci.

🐬 Version note: INT(11) in older tutorials

Older examples write INT(11). The number was only a display width and never limited the value. MySQL 8.0 and later deprecate it (warning 1681) and print plain int, as above; MariaDB still prints int(11). Write INT. TINYINT(1) for booleans is the one width MySQL keeps.

In phpMyAdmin: click the table in the left panel, then the Structure tab for the same information as DESCRIBE. SHOW CREATE TABLE books; works in the SQL tab too.

🔧 Changing Tables with ALTER TABLE

Requirements change: the store wants ISBNs, a column needs a better name, a type turns out too small. ALTER TABLE changes a table's structure while keeping its rows. You will try each form on books and put the table back the way it was at the end of the section.

graph TD A["ALTER TABLE books"] --> B["ADD or DROP a column"] A --> C["RENAME, MODIFY or CHANGE one"] B --> D["new structure"] C --> D D --> E["existing rows are kept"]

ADD COLUMN

ALTER TABLE books
    ADD COLUMN isbn VARCHAR(13) AFTER id;

Output

Query OK, 0 rows affected (0.03 sec)
Records: 0  Duplicates: 0  Warnings: 0

A new column goes at the end unless you say AFTER column or FIRST. Existing rows (there are none yet) would get NULL, or the column's DEFAULT, in the new column.

RENAME COLUMN

ALTER TABLE books
    RENAME COLUMN isbn TO isbn13;

Output

Query OK, 0 rows affected (0.01 sec)
Records: 0  Duplicates: 0  Warnings: 0

RENAME COLUMN changes only the name; the type and constraints stay.

MODIFY COLUMN: a new definition

ISBN-13 codes are always exactly 13 characters, and every book should have one. MODIFY replaces the column's whole definition:

ALTER TABLE books
    MODIFY COLUMN isbn13 CHAR(13) NOT NULL;

Output

Query OK, 0 rows affected (0.04 sec)
Records: 0  Duplicates: 0  Warnings: 0

⚠️ MODIFY replaces everything

Whatever you leave out of a MODIFY is gone: MODIFY COLUMN title VARCHAR(250) silently drops the NOT NULL that title had. Always repeat the full definition, constraints included. On a table that already holds rows, a change can also fail (text into a number column) or be refused because it would cut values short; you will see both in Lesson 2.2.

CHANGE COLUMN: rename and redefine at once

ALTER TABLE books
    CHANGE COLUMN isbn13 isbn CHAR(13);

Output

Query OK, 0 rows affected (0.04 sec)
Records: 0  Duplicates: 0  Warnings: 0

CHANGE takes the old name, the new name and the full new definition (and, like MODIFY, forgets anything you leave out, so isbn may be NULL again). Use RENAME COLUMN for a plain rename, MODIFY for a plain redefinition, and CHANGE when you need both.

Several changes in one statement, and DROP COLUMN

Separate changes with commas. One statement is easier to read and lets MySQL rebuild the table once instead of several times.

ALTER TABLE books
    ADD COLUMN language VARCHAR(30) DEFAULT 'English',
    MODIFY COLUMN pages INT UNSIGNED;
DESCRIBE books;

Output

Query OK, 0 rows affected (0.04 sec)
Records: 0  Duplicates: 0  Warnings: 0
+-----------+--------------+------+-----+---------+----------------+
| Field     | Type         | Null | Key | Default | Extra          |
+-----------+--------------+------+-----+---------+----------------+
| id        | int          | NO   | PRI | NULL    | auto_increment |
| isbn      | char(13)     | YES  |     | NULL    |                |
| title     | varchar(200) | NO   |     | NULL    |                |
| author    | varchar(100) | NO   |     | NULL    |                |
| price     | decimal(8,2) | NO   |     | NULL    |                |
| pages     | int unsigned | YES  |     | NULL    |                |

ALTER TABLE quick reference

You want toWrite
Add a columnALTER TABLE t ADD COLUMN col TYPE;
Add it in a given place... ADD COLUMN col TYPE AFTER other; (or FIRST)
Rename a columnALTER TABLE t RENAME COLUMN old TO new;
Change a column's definitionALTER TABLE t MODIFY COLUMN col FULL_DEFINITION;
Rename and redefineALTER TABLE t CHANGE COLUMN old new FULL_DEFINITION;
Remove a columnALTER TABLE t DROP COLUMN col;
Rename the tableALTER TABLE t RENAME TO new_name;

🗑️ Renaming, Emptying and Dropping Tables

To practice the destructive commands without touching the real tables, make a copy. CREATE TABLE ... LIKE copies another table's structure (columns, keys, defaults) but none of its rows:

CREATE TABLE books_copy LIKE books;
RENAME TABLE books_copy TO old_books;
SHOW TABLES;

Output

+---------------------+
| Tables_in_bookstore |
+---------------------+
| books               |
| categories          |
| customers           |
| old_books           |
+---------------------+

RENAME TABLE a TO b and ALTER TABLE a RENAME TO b do the same thing; RENAME TABLE can also rename several tables in one statement (RENAME TABLE a TO b, c TO d;).

TRUNCATE TABLE: remove every row, keep the table

To see the difference, the copy needs some rows. The INSERT statement is the subject of Lesson 2.3; for now, read it as "add these two books":

INSERT INTO old_books (title, author, price)
VALUES ('Dune', 'Frank Herbert', 14.99), ('1984', 'George Orwell', 9.99);
SELECT id, title FROM old_books;

Output

+----+-------+
| id | title |
+----+-------+
|  1 | Dune  |
|  2 | 1984  |
+----+-------+
TRUNCATE TABLE old_books;
INSERT INTO old_books (title, author, price)
VALUES ('The Hobbit', 'J.R.R. Tolkien', 10.99);
SELECT id, title FROM old_books;

Output

+----+------------+
| id | title      |
+----+------------+
|  1 | The Hobbit |
+----+------------+

TRUNCATE emptied the table and reset its AUTO_INCREMENT counter, so the next book got id 1 again. It works by recreating the table, which makes it fast on big tables, but it cannot be undone and it removes every row; to remove only some rows you use DELETE ... WHERE (Lesson 2.3).

DROP TABLE: remove the table itself

DROP TABLE old_books;
DROP TABLE IF EXISTS old_books;

Output

Query OK, 0 rows affected (0.02 sec)
Query OK, 0 rows affected, 1 warning (0.00 sec)

The first statement removed old_books, structure and rows. The second found nothing and, thanks to IF EXISTS, only warned.

CommandRowsTableAUTO_INCREMENT
TRUNCATE TABLE tAll removedKeptBack to 1
DROP TABLE tAll removedRemovedGone with the table
DROP DATABASE dAll removedEvery table removedGone

⚠️ Common Mistakes

1. Creating something that already exists

CREATE DATABASE bookstore;

Error

ERROR 1007 (HY000): Can't create database 'bookstore'; database exists

What it means: the name is taken. The table version is ERROR 1050 (42S01): Table 'books' already exists. Fix: if you meant "make sure it exists", add IF NOT EXISTS. If you meant "start over", drop it first, knowing that its data goes with it.

2. Dropping the database you are in

CREATE DATABASE sandbox;
USE sandbox;
DROP DATABASE sandbox;
CREATE TABLE notes (id INT PRIMARY KEY);

Error

Database changed
ERROR 1046 (3D000): No database selected

What it means: after the drop, the session has no current database, so MySQL does not know where notes should go. The same error appears whenever you forget USE in a fresh session. Fix: pick a database again (or write the full name, bookstore.notes):

USE bookstore;

Output

Database changed

3. Using a reserved word as a name

CREATE TABLE order (
    id INT AUTO_INCREMENT PRIMARY KEY
);

Error

ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'order (
    id INT AUTO_INCREMENT PRIMARY KEY
)' at line 1

What it means: error 1064 is the general "I could not read this". The near '...' part shows where MySQL got lost: at order, which is a keyword (ORDER BY). Fix: pick a name that is not a keyword: orders, as the naming table recommends. Wrapping it in backticks (`order`) also works, but then every query has to do the same forever. A trailing comma after the last column produces the same error, pointing at the closing ).

4. Misspelling a table name

DESCRIBE customer;

Error

ERROR 1146 (42S02): Table 'bookstore.customer' doesn't exist

What it means: there is no table called customer in bookstore; the table is customers, plural. The message names the database too, which also catches the case where you are in the wrong one. Fix: SHOW TABLES; and copy the exact name.

5. Losing a constraint with MODIFY (silent)

You want longer titles and change the length, nothing else:

ALTER TABLE books MODIFY COLUMN title VARCHAR(250);
DESCRIBE books;

Output

+-----------+--------------+------+-----+---------+----------------+
| Field     | Type         | Null | Key | Default | Extra          |
+-----------+--------------+------+-----+---------+----------------+
| id        | int          | NO   | PRI | NULL    | auto_increment |
| title     | varchar(250) | YES  |     | NULL    |                |
| author    | varchar(100) | NO   |     | NULL    |                |
| price     | decimal(8,2) | NO   |     | NULL    |                |
| pages     | int          | YES  |     | NULL    |                |
| published | date         | YES  |     | NULL    |                |
| in_stock  | tinyint(1)   | YES  |     | 1       |                |
+-----------+--------------+------+-----+---------+----------------+

What it means: no error, no warning, but title now says YES under Null: books without a title would be accepted. MODIFY uses exactly the definition you typed. Fix: repeat every part you want to keep, then check with DESCRIBE. Here, put the table back to its original definition:

ALTER TABLE books MODIFY COLUMN title VARCHAR(200) NOT NULL;

Output

Query OK, 0 rows affected (0.03 sec)
Records: 0  Duplicates: 0  Warnings: 0

🛠️ Project: The Bookstore Build Script

Typing statements at the prompt is fine for exploring, but real databases are built from script files: plain-text .sql files that anyone can rerun to get exactly the same result. You will write create_bookstore.sql, which rebuilds the empty bookstore from nothing. Whenever an experiment goes wrong in the next two lessons, this file puts everything back. Allow about 30 minutes.

🛠️ Step 1: Start the file with a clean slate (5 min)

In VS Code (or any plain-text editor), create create_bookstore.sql in a folder you can find again, for example mysql-course in your home folder. Lines starting with -- (two dashes and a space) are comments. Begin with a header, then drop and recreate the database:

-- create_bookstore.sql
-- Builds the empty bookstore database for MySQL Foundations.
-- WARNING: deletes any existing bookstore database first.

DROP DATABASE IF EXISTS bookstore;

CREATE DATABASE bookstore
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE bookstore;

Output

Database changed

Starting with DROP DATABASE IF EXISTS is what makes the script repeatable: every run starts from nothing, whatever state the last experiment left behind.

🛑 Only for practice databases

A script that begins with DROP DATABASE is perfect for a course database and dangerous anywhere else. Never point a script like this at a database that holds data you care about.

🛠️ Step 2: Add the books table (5 min)

Below USE bookstore;, add a comment and the books table. Run the statement at the prompt as you add it, so a typo shows up now rather than later.

-- Books for sale. author is plain text for now (Module 4 gives it its own table).
CREATE TABLE books (
    id          INT AUTO_INCREMENT PRIMARY KEY,
    title       VARCHAR(200) NOT NULL,
    author      VARCHAR(100) NOT NULL,
    price       DECIMAL(8, 2) NOT NULL,
    pages       INT,
    published   DATE,
    in_stock    BOOLEAN DEFAULT TRUE
);

Output

Query OK, 0 rows affected (0.02 sec)

❓ Common Questions at This Stage

Do I have to type SQL keywords in capitals?

No. create table works exactly like CREATE TABLE. Capital keywords and lowercase names are a convention that makes statements easier to scan, and this course follows it. Table names are the part where case can matter (on Linux servers), which is why they stay lowercase.

Can I undo a DROP TABLE?

Not with SQL. A dropped table is gone unless you have a backup or a script that recreates it. That is one reason the project is a script: create_bookstore.sql rebuilds the structure in a second. Backups with mysqldump come in Lesson 8.1.

Does ALTER TABLE lock or slow down a big table?

On the empty tables in this lesson it is instant. On a table with millions of rows, some changes (such as changing a column's type) rebuild the whole table and can take a long time, while others (such as adding a column at the end, or renaming one) are nearly instant in MySQL 8.0 and later. Teams test big changes on a copy first.

What is the difference between a database and a schema?

In MySQL there is none: CREATE SCHEMA is another spelling of CREATE DATABASE, which is why information_schema calls the database column TABLE_SCHEMA. In PostgreSQL and SQL Server, a schema is a folder inside a database, so you will see the words used differently there.

📝 Lesson Summary

🎓 Key Takeaways

  • A server holds databases; a database holds tables. CREATE DATABASE makes one, USE selects it, SELECT DATABASE() tells you where you are
  • Create databases with CHARACTER SET utf8mb4 and an explicit collation; never write utf8
  • CREATE TABLE lists each column's name, type and constraints; IF NOT EXISTS skips existing tables without changing them
  • DESCRIBE shows columns at a glance; SHOW CREATE TABLE ...\G shows the full definition
  • ALTER TABLE adds, renames, redefines and drops columns; MODIFY and CHANGE replace the whole definition, so repeat every constraint
  • TRUNCATE empties a table and resets AUTO_INCREMENT; DROP removes the table or database itself, with no undo
  • Build databases from script files that start clean, so you can rerun them any time
