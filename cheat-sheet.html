📋 MySQL Cheat Sheet

A quick reference for the commands and syntax you use in this course, written for MySQL 9.7 LTS. Every SQL example on this page has been run, top to bottom, against the course's bookstore database, so you can copy any of them and it will work.

💡 Follow along

Load the practice database first: download bookstore.sql and run SOURCE bookstore.sql; inside the client (or mysql -u root -p < bookstore.sql from a terminal). Running it again resets everything, so experiment freely. Examples that change data say so, and most of them undo themselves with ROLLBACK.

💻 Connecting & the mysql Client

Covered in Lesson 1.3: MySQL CLI & phpMyAdmin. Type these in a terminal, not at the mysql> prompt.

# Log in (you are asked for the password)
mysql -u root -p

# Log in and open a database straight away
mysql -u root -p bookstore

# Run a script file, then exit
mysql -u root -p < bookstore.sql

# Docker: open the client inside your container (use your container's name)
docker exec -it mysql97 mysql -u root -p

# Which client version do I have?
mysql --version

Inside the client:

SELECT VERSION();                 -- server version
SELECT CURRENT_USER();            -- who am I logged in as?
SELECT DATABASE();                -- which database is selected?
SHOW WARNINGS;                    -- details of the last statement's warnings

-- Run a script file (path relative to the folder you started mysql in)

In MySQL 9.x the client ignores \G, SOURCE and the other client commands when it reads a redirected file or runs -e "..." (Unknown command '\G'). ⚠️ Skip the old display widths

Old tutorials write INT(11). The number never limited the value, it is deprecated, and MySQL 9.7 ignores it with a warning: write plain INT. TINYINT(1) (what BOOLEAN becomes) is the one exception MySQL still shows.

🔄 CRUD Operations

Covered in Lesson 2.3: CRUD Operations. These examples change data, so they run inside a transaction and end with ROLLBACK, which puts everything back.

START TRANSACTION;                -- practice mode: ROLLBACK at the end undoes it all

-- INSERT (Create): name the columns, one row or many
INSERT INTO authors (name, birth_year) VALUES ('Ursula K. Le Guin', 1929);
INSERT INTO books (title, author_id, price, pages, published) VALUES
    ('The Left Hand of Darkness', LAST_INSERT_ID(), 12.99, 304, '1969-03-01'),
    ('I, Robot', 10, 9.99, 253, '1950-12-02');

-- Copy rows from a query
INSERT INTO book_categories (book_id, category_id)
SELECT id, 2 FROM books WHERE title IN ('The Left Hand of Darkness', 'I, Robot');

-- SELECT (Read)
SELECT * FROM books;
SELECT title, price FROM books;
SELECT title AS book_title, price AS cost FROM books;   -- column aliases
SELECT DISTINCT author_id FROM books;                   -- unique values only

-- UPDATE: always with a WHERE
UPDATE books SET price = 13.49 WHERE title = 'The Left Hand of Darkness';
UPDATE books SET price = ROUND(price * 1.10, 2) WHERE price < 9;  -- 10% raise on cheap books

-- UPDATE using another table
UPDATE books b
JOIN authors a ON a.id = b.author_id
SET b.in_stock = FALSE
WHERE a.name = 'Isaac Asimov';

-- DELETE: always with a WHERE
DELETE FROM book_categories WHERE book_id IN (SELECT id FROM books WHERE author_id = 10);
DELETE FROM books WHERE author_id = 10;

-- Upsert: insert, or update the row that already has this key
INSERT INTO categories (name, description)
VALUES ('Fantasy', 'Magic, quests and other worlds') AS new
ON DUPLICATE KEY UPDATE description = new.description;

ROLLBACK;                         -- undo everything since START TRANSACTION

⚠️ Always use WHERE with UPDATE and DELETE

Without WHERE, every row changes. Run a SELECT with the same WHERE first to see exactly which rows you will hit.

🐬 Version note: the upsert row alias

The AS new ... new.description form works in MySQL 8.0.19 and later. The older description = VALUES(description) still runs but is deprecated (warning 1287). MariaDB is the other way round: it rejects the alias with ERROR 1064 and wants VALUES(description).

🔍 Filtering & Sorting

Covered in Lesson 3.1: WHERE Clauses, Operators & Filtering and Lesson 3.2: Sorting & Limiting Results.

-- WHERE
SELECT title, price FROM books WHERE price > 10;
SELECT title, price FROM books WHERE price BETWEEN 9 AND 11;     -- inclusive
SELECT title FROM books WHERE author_id IN (2, 6);
SELECT title FROM books WHERE author_id NOT IN (2, 6);
SELECT title FROM books WHERE title LIKE '%the%';               -- contains (case-insensitive here)
SELECT title FROM books WHERE title LIKE 'The%';                -- starts with
SELECT title FROM books WHERE title LIKE '_984';                 -- _ = exactly one character
SELECT title FROM books WHERE price > 10 AND in_stock = TRUE;
SELECT title FROM books WHERE price > 15 OR pages > 400;
SELECT title FROM books WHERE NOT in_stock;
SELECT title FROM books WHERE published >= '1950-01-01';

-- NULL needs IS / IS NOT (= NULL is never true)
SELECT first_name, last_name FROM customers WHERE city IS NULL;
SELECT first_name, last_name FROM customers WHERE city IS NOT NULL;

-- ORDER BY
SELECT title, price FROM books ORDER BY price;                  -- ascending (ASC) is the default
SELECT title, price FROM books ORDER BY price DESC;
SELECT title, author_id, price FROM books ORDER BY author_id, price DESC;

-- LIMIT and OFFSET (page 2 of 5 rows per page)
SELECT title, price FROM books ORDER BY price DESC LIMIT 5;
SELECT title, price FROM books ORDER BY price DESC LIMIT 5 OFFSET 5;

-- How many rows in total? (for "page 2 of 3"): a separate COUNT
SELECT COUNT(*) FROM books;

💡 Pagination without SQL_CALC_FOUND_ROWS

SQL_CALC_FOUND_ROWS and FOUND_ROWS() are deprecated. Count the rows with a separate SELECT COUNT(*) using the same WHERE.

📈 Aggregate Functions & GROUP BY

Covered in Lesson 3.3: Aggregate Functions & GROUP BY.

SELECT COUNT(*) FROM books;                       -- rows
SELECT COUNT(city) FROM customers;                -- non-NULL values only
SELECT COUNT(DISTINCT author_id) FROM books;      -- different values
SELECT SUM(pages), AVG(price), MIN(price), MAX(price) FROM books;
SELECT ROUND(AVG(price), 2) AS avg_price FROM books;

-- GROUP BY: one result row per group. Add ORDER BY: groups come back unsorted
SELECT author_id, COUNT(*) AS books, AVG(price) AS avg_price
FROM books
GROUP BY author_id
ORDER BY author_id;

-- HAVING filters groups (WHERE filters rows before grouping)
SELECT author_id, COUNT(*) AS books
FROM books
WHERE in_stock = TRUE
GROUP BY author_id
HAVING COUNT(*) >= 2
ORDER BY books DESC;

-- All values of a group in one string
SELECT author_id, GROUP_CONCAT(title ORDER BY title SEPARATOR ', ') AS titles
FROM books
GROUP BY author_id
ORDER BY author_id;

-- Subtotals plus a grand total row (NULL in the grouped column)
SELECT department, COUNT(*) AS staff, SUM(salary) AS payroll
FROM employees
GROUP BY department WITH ROLLUP;

💡 The order MySQL evaluates a query in

FROM / JOIN → WHERE → GROUP BY → HAVING → window functions → SELECT → DISTINCT → ORDER BY → LIMIT. That is why a column alias from SELECT is not available in WHERE (error 1054), but is in ORDER BY.

⚠️ Every selected column must be grouped or aggregated

MySQL's default ONLY_FULL_GROUP_BY mode rejects SELECT author_id, title, COUNT(*) ... GROUP BY author_id with ERROR 1055. Never "fix" it by changing sql_mode; group by the column or aggregate it. MariaDB does not have this check on by default and quietly picks a value.

🔀 Joins

Covered in Lesson 4.3: Joins; the relationships behind them in Lesson 4.1: Table Relationships.

-- INNER JOIN: only rows that match on both sides
SELECT b.title, a.name AS author
FROM books b
JOIN authors a ON a.id = b.author_id
ORDER BY b.title;

-- LEFT JOIN: every author, with NULL where there is no book (Isaac Asimov)
SELECT a.name, b.title
FROM authors a
LEFT JOIN books b ON b.author_id = a.id
ORDER BY a.name, b.title;

-- Find the rows with no match ("anti-join")
SELECT c.first_name, c.last_name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;

-- RIGHT JOIN: the same idea from the other side
SELECT b.title, a.name
FROM books b
RIGHT JOIN authors a ON a.id = b.author_id
ORDER BY a.name;

-- CROSS JOIN: every combination (5 categories x 5 categories = 25 rows)
SELECT c1.name AS first_pick, c2.name AS second_pick
FROM categories c1
CROSS JOIN categories c2;

-- Self-join: employees and their managers
SELECT CONCAT(e.first_name, ' ', e.last_name) AS employee,
       CONCAT(m.first_name, ' ', m.last_name) AS manager
FROM employees e
LEFT JOIN employees m ON m.id = e.manager_id
ORDER BY e.id;

-- Many-to-many through the junction table
SELECT b.title, c.name AS category
FROM books b
JOIN book_categories bc ON bc.book_id = b.id
JOIN categories c ON c.id = bc.category_id
ORDER BY b.title, c.name;

-- Four tables: what did each order contain?
SELECT o.id AS order_id, c.first_name, b.title, oi.quantity,
       oi.quantity * oi.price_at_time AS line_total
FROM orders o
JOIN customers c   ON c.id = o.customer_id
JOIN order_items oi ON oi.order_id = o.id
JOIN books b       ON b.id = oi.book_id
ORDER BY o.id, b.title;

💡 No FULL OUTER JOIN in MySQL

MySQL has no FULL OUTER JOIN. Combine a LEFT JOIN and a RIGHT JOIN with UNION when you need both sides.

🪆 Subqueries

Covered in Lesson 3.4: Subqueries & Nested Queries.

-- Scalar subquery (returns one value)
SELECT title, price
FROM books
WHERE price > (SELECT AVG(price) FROM books);

-- IN with a subquery (returns a list)
SELECT name FROM authors
WHERE id IN (SELECT author_id FROM books WHERE price > 12);

-- EXISTS / NOT EXISTS: is there at least one matching row?
SELECT first_name, last_name FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);

-- Correlated subquery: runs once per outer row
SELECT title, price, author_id
FROM books b
WHERE price = (SELECT MAX(price) FROM books WHERE author_id = b.author_id)
ORDER BY author_id;

-- Derived table: a subquery in FROM needs an alias
SELECT author_id, avg_price
FROM (
    SELECT author_id, AVG(price) AS avg_price
    FROM books
    GROUP BY author_id
) AS author_prices
WHERE avg_price > 10
ORDER BY avg_price DESC;

🧩 CTEs & Recursive Queries

Covered in Lesson 5.1: CTEs & Recursive Queries. A CTE (WITH) names a query so the main query can use it like a table.

-- One CTE
WITH order_totals AS (
    SELECT order_id, SUM(quantity * price_at_time) AS total
    FROM order_items
    GROUP BY order_id
)
SELECT order_id, total
FROM order_totals
WHERE total > 20
ORDER BY total DESC;

-- Several CTEs: separate them with commas; later ones may use earlier ones
WITH customer_spend AS (
    SELECT o.customer_id, SUM(oi.quantity * oi.price_at_time) AS spent
    FROM orders o
    JOIN order_items oi ON oi.order_id = o.id
    GROUP BY o.customer_id
),
big_spenders AS (
    SELECT customer_id, spent FROM customer_spend WHERE spent > 30
)
SELECT c.first_name, c.last_name, b.spent
FROM big_spenders b
JOIN customers c ON c.id = b.customer_id
ORDER BY b.spent DESC;

-- Recursive CTE: walk the org chart from the top down
WITH RECURSIVE org AS (
    SELECT id, first_name, manager_id, 1 AS level
    FROM employees
    WHERE manager_id IS NULL                      -- anchor: where to start
    UNION ALL
    SELECT e.id, e.first_name, e.manager_id, org.level + 1
    FROM employees e
    JOIN org ON e.manager_id = org.id             -- recursive step
)
SELECT level, first_name FROM org ORDER BY level, first_name;

-- Recursive CTE that generates rows: the numbers 1 to 6 (months, for example)
WITH RECURSIVE months AS (
    SELECT 1 AS m
    UNION ALL
    SELECT m + 1 FROM months WHERE m < 6           -- the stop condition
)
SELECT m FROM months;

⚠️ Recursion needs a stop condition

A recursive CTE without a working stop condition is aborted after cte_max_recursion_depth iterations (1000 by default) with ERROR 3636.

🪟 Window Functions

Covered in Lesson 5.2: Window Functions. A window function computes over a set of rows related to the current row without collapsing them like GROUP BY does.

-- Rank books by copies sold (ties: RANK skips numbers, DENSE_RANK does not)
WITH sales AS (
    SELECT b.title, SUM(oi.quantity) AS copies
    FROM books b
    JOIN order_items oi ON oi.book_id = b.id
    GROUP BY b.title
)
SELECT title, copies,
       ROW_NUMBER() OVER (ORDER BY copies DESC, title) AS row_num,
       RANK()       OVER (ORDER BY copies DESC)        AS rank_num,
       DENSE_RANK() OVER (ORDER BY copies DESC)        AS dense_num
FROM sales
ORDER BY copies DESC, title;

-- PARTITION BY: restart the calculation for each group
SELECT department, first_name, salary,
       AVG(salary) OVER (PARTITION BY department) AS dept_avg,
       salary - AVG(salary) OVER (PARTITION BY department) AS vs_avg
FROM employees
ORDER BY department, salary DESC;

-- Running total and previous value
WITH monthly AS (
    SELECT DATE_FORMAT(o.order_date, '%Y-%m') AS month,
           SUM(oi.quantity * oi.price_at_time) AS revenue
    FROM orders o
    JOIN order_items oi ON oi.order_id = o.id
    GROUP BY month
)
SELECT month, revenue,
       SUM(revenue) OVER (ORDER BY month) AS running_total,
       LAG(revenue) OVER (ORDER BY month) AS previous_month
FROM monthly
ORDER BY month;

-- A named window (WINDOW clause) reused by several functions
SELECT title, price,
       MIN(price) OVER w AS cheapest_by_author,
       MAX(price) OVER w AS dearest_by_author
FROM books
WINDOW w AS (PARTITION BY author_id)
ORDER BY author_id, price;

⚠️ "rank" is a reserved word

Since MySQL 8.0, RANK, ROW_NUMBER, WINDOW, GROUPS and friends are keywords, so AS rank is ERROR 1064. Use names like rank_num. Window functions cannot go in WHERE: filter them in an outer query or a CTE.

⚡ Indexes & EXPLAIN

Covered in Lesson 6.1: Indexes & Query Optimization.

-- Create indexes
CREATE INDEX idx_books_published ON books (published);
CREATE INDEX idx_customers_name ON customers (last_name, first_name);   -- composite: leftmost column first
CREATE UNIQUE INDEX idx_categories_name_desc ON categories (name, description);

-- See them
SHOW INDEX FROM books;

-- How will MySQL run this query?
EXPLAIN SELECT title FROM books WHERE published >= '1950-01-01';
EXPLAIN FORMAT=TREE SELECT title FROM books WHERE published >= '1950-01-01';

-- Run it for real and show actual timings (MySQL only; MariaDB: ANALYZE SELECT ...)
EXPLAIN ANALYZE SELECT title FROM books WHERE published >= '1950-01-01';

-- Hide an index from the optimizer without dropping it (test before you delete)
ALTER TABLE books ALTER INDEX idx_books_published INVISIBLE;
ALTER TABLE books ALTER INDEX idx_books_published VISIBLE;

-- Drop indexes
DROP INDEX idx_books_published ON books;
DROP INDEX idx_customers_name ON customers;
DROP INDEX idx_categories_name_desc ON categories;

💡 Reading EXPLAIN

type: ALL means a full table scan; ref, range and const mean an index is used. The key column names the index MySQL chose, and rows is its estimate of rows to examine.

⚙️ Stored Procedures & Functions

Covered in Lesson 7.1: Stored Procedures & Functions. In the mysql client, change the DELIMITER so the semicolons inside the body do not end the statement.

-- A procedure with an IN parameter
DELIMITER //
CREATE PROCEDURE get_books_by_author(IN p_author_id INT)
BEGIN
    SELECT title, price FROM books WHERE author_id = p_author_id ORDER BY title;
END //
DELIMITER ;

CALL get_books_by_author(2);

-- An OUT parameter comes back in a user variable
DELIMITER //
CREATE PROCEDURE count_books(IN p_author_id INT, OUT p_count INT)
BEGIN
    SELECT COUNT(*) INTO p_count FROM books WHERE author_id = p_author_id;
END //
DELIMITER ;

CALL count_books(6, @total);
SELECT @total;

-- A stored function returns one value and is used inside queries.
-- DETERMINISTIC (or NO SQL / READS SQL DATA) is required when binary logging is on, the default.
DELIMITER //
CREATE FUNCTION discount_price(p_price DECIMAL(8, 2), p_pct INT)
RETURNS DECIMAL(8, 2)
DETERMINISTIC
BEGIN
    RETURN ROUND(p_price * (100 - p_pct) / 100, 2);
END //
DELIMITER ;

SELECT title, price, discount_price(price, 20) AS sale_price FROM books ORDER BY id;

-- What is defined here?
SHOW PROCEDURE STATUS WHERE Db = 'bookstore';
SHOW FUNCTION STATUS WHERE Db = 'bookstore';
SHOW CREATE PROCEDURE count_books\G

-- Drop them
DROP PROCEDURE IF EXISTS get_books_by_author;
DROP PROCEDURE IF EXISTS count_books;
DROP FUNCTION IF EXISTS discount_price;

🔐 Transactions

Covered in Lesson 7.2: Transactions. Either every statement in the transaction takes effect (COMMIT) or none does (ROLLBACK).

-- Place an order: the order and its line must both be saved, or neither
START TRANSACTION;
INSERT INTO orders (customer_id, order_date) VALUES (3, '2026-06-10');
SET @order_id = LAST_INSERT_ID();
INSERT INTO order_items (order_id, book_id, quantity, price_at_time)
SELECT @order_id, id, 1, price FROM books WHERE id = 9;
COMMIT;                                   -- make it permanent

-- Change your mind: ROLLBACK undoes everything since START TRANSACTION
START TRANSACTION;
DELETE FROM order_items WHERE order_id = @order_id;
ROLLBACK;

-- Savepoints: undo part of a transaction
START TRANSACTION;
UPDATE books SET price = price - 1 WHERE id = 1;
SAVEPOINT after_dune;
UPDATE books SET price = price - 1 WHERE id = 2;
ROLLBACK TO SAVEPOINT after_dune;         -- undoes only the second UPDATE
ROLLBACK;                                 -- ...and now the first one too

-- Lock the rows you read until you commit (SELECT ... FOR SHARE for a shared lock)
START TRANSACTION;
SELECT id, price FROM books WHERE id = 1 FOR UPDATE;
COMMIT;

-- Isolation level (REPEATABLE-READ is the InnoDB default)
SELECT @@transaction_isolation;
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;

💡 ACID

Atomicity: all or nothing. Consistency: constraints hold before and after. Isolation: concurrent transactions do not see each other's half-finished work. Durability: committed data survives a crash. CREATE, ALTER and DROP commit automatically and cannot be rolled back.

🧾 JSON Columns

Covered in Lesson 7.3: JSON Columns. The setup below adds the lesson's attributes column to books.

-- Setup (as in Lesson 7.3)
ALTER TABLE books ADD COLUMN attributes JSON;
UPDATE books SET attributes = '{"format": "paperback", "series": "Dune Chronicles", "awards": ["Hugo", "Nebula"]}' WHERE id = 1;
UPDATE books SET attributes = '{"format": "hardcover", "series": "Middle-earth", "illustrated": true}' WHERE id IN (6, 9);
UPDATE books SET attributes = '{"format": "paperback", "awards": []}' WHERE attributes IS NULL;

-- Read values: -> returns JSON (with quotes), ->> returns plain text
SELECT title,
       attributes->'$.format'  AS format_json,
       attributes->>'$.format' AS format_text
FROM books
WHERE id IN (1, 6);

-- The same with functions (these also work in MariaDB)
SELECT title, JSON_UNQUOTE(JSON_EXTRACT(attributes, '$.series')) AS series
FROM books
WHERE JSON_EXTRACT(attributes, '$.series') IS NOT NULL
ORDER BY title;

-- Filter: does the awards array contain "Hugo"? How long is it?
SELECT title FROM books WHERE JSON_CONTAINS(attributes->'$.awards', '"Hugo"');
SELECT title, JSON_LENGTH(attributes, '$.awards') AS award_count FROM books WHERE id = 1;

-- Change part of a document
UPDATE books SET attributes = JSON_SET(attributes, '$.format', 'ebook') WHERE id = 2;
UPDATE books SET attributes = JSON_REMOVE(attributes, '$.awards') WHERE id = 2;

-- Build JSON from rows
SELECT JSON_OBJECT('id', id, 'title', title, 'price', price) AS doc FROM books WHERE id = 1;
SELECT JSON_ARRAYAGG(name) AS category_names FROM categories;

-- Turn a JSON array into rows
SELECT b.title, jt.award
FROM books b,
     JSON_TABLE(b.attributes, '$.awards[*]' COLUMNS (award VARCHAR(50) PATH '$')) AS jt
ORDER BY b.title, jt.award;

-- Cleanup: remove the column again if you are not doing Lesson 7.3
ALTER TABLE books DROP COLUMN attributes;

🐬 Version note: MariaDB

MariaDB stores JSON as LONGTEXT with a json_valid() check and has no ->> operator (ERROR 1064). Use JSON_VALUE(attributes, '$.format') or JSON_UNQUOTE(JSON_EXTRACT(...)), which work on MySQL too.

👥 Users, Privileges & Roles

Covered in Lesson 7.4: User Management & Permissions. Passwords below are placeholders: choose your own.

-- Create an account for an application (never let an app log in as root)
CREATE USER 'bookstore_app'@'localhost' IDENTIFIED BY 'Replace-With-A-Long-Passphrase-1';

-- Least privilege: only what the app needs, only on its database
GRANT SELECT, INSERT, UPDATE ON bookstore.* TO 'bookstore_app'@'localhost';
GRANT DELETE ON bookstore.order_items TO 'bookstore_app'@'localhost';   -- one table only
SHOW GRANTS FOR 'bookstore_app'@'localhost';

REVOKE UPDATE ON bookstore.* FROM 'bookstore_app'@'localhost';

-- Account maintenance
ALTER USER 'bookstore_app'@'localhost' IDENTIFIED BY 'Another-Long-Passphrase-2';
ALTER USER 'bookstore_app'@'localhost' ACCOUNT LOCK;
ALTER USER 'bookstore_app'@'localhost' ACCOUNT UNLOCK;
SELECT user, host, plugin, account_locked FROM mysql.user WHERE user = 'bookstore_app';

-- Roles: named bundles of privileges
CREATE ROLE 'bookstore_read', 'bookstore_write';
GRANT SELECT ON bookstore.* TO 'bookstore_read';
GRANT INSERT, UPDATE, DELETE ON bookstore.* TO 'bookstore_write';

CREATE USER 'report_user'@'localhost' IDENTIFIED BY 'Replace-With-A-Long-Passphrase-3';
GRANT 'bookstore_read' TO 'report_user'@'localhost';
SET DEFAULT ROLE ALL TO 'report_user'@'localhost';     -- active at every login
SHOW GRANTS FOR 'report_user'@'localhost' USING 'bookstore_read';

-- Clean up
DROP USER IF EXISTS 'bookstore_app'@'localhost', 'report_user'@'localhost';
DROP ROLE IF EXISTS 'bookstore_read', 'bookstore_write';

🛑 Do not switch accounts to mysql_native_password

New accounts use caching_sha2_password, which every current client and connector understands. mysql_native_password is removed in MySQL 9.x (and disabled in 8.4): IDENTIFIED WITH mysql_native_password fails with ERROR 1524. If an old tool cannot log in, upgrade the tool.

📦 Import & Export

Covered in Lesson 8.1: Importing & Exporting Data. In a terminal (not inside mysql>):

# Back up one database (the file recreates the tables and rows)
mysqldump -u root -p bookstore > bookstore_backup.sql

# A consistent backup of InnoDB tables, including procedures, functions and triggers
mysqldump -u root -p --single-transaction --routines --triggers bookstore > bookstore_backup.sql

# Only some tables / only the structure / everything on the server
mysqldump -u root -p bookstore books authors > books_only.sql
mysqldump -u root -p --no-data bookstore > bookstore_schema.sql
mysqldump -u root -p --all-databases > all_databases.sql

# Restore into an existing database
mysql -u root -p bookstore < bookstore_backup.sql

Inside mysql, the server reads and writes files only in the folder named by secure_file_priv (/var/lib/mysql-files/ on Linux packages). A sample CSV with a header row:

-- Export a query to CSV (fails if the file already exists)
SELECT id, title, price
INTO OUTFILE '/var/lib/mysql-files/books_export.csv'
FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
LINES TERMINATED BY '\n'
FROM books
ORDER BY id;

-- Import a CSV into a table (practice table, dropped at the end)

💡 Files on your own computer: LOCAL

LOAD DATA LOCAL INFILE 'new_books.csv' ... reads the file from the client's machine instead. It needs local_infile=ON on the server and mysql --local-infile=1 on the client; otherwise you get ERROR 3948 or 2068 (see Common Errors).
