💻 Lesson 1.3: MySQL CLI & phpMyAdmin

Your server is running. Now you need to be at home in the tools that talk to it: the mysql command-line client, which you will use in every lesson, and phpMyAdmin, the browser-based tool you will meet on many web hosts. By the end you will find your way around any MySQL server and run a whole .sql file with one command.

🎯 Learning Objectives

By the end of this lesson, you will be able to:

  • Log in to and out of the mysql client, and read its prompts (mysql>, ->, '>)
  • Explore a server with SHOW DATABASES, USE, SHOW TABLES, DESCRIBE and SELECT DATABASE()
  • Tell SQL statements apart from client commands such as \G, \c, SOURCE and help
  • Save SQL in a .sql file and run it with SOURCE and with mysql < file.sql, knowing what MySQL 9.x's client does differently in scripts
  • Find the Structure, SQL, Import and Export tabs in phpMyAdmin and choose the right tool for a task
  • ⏱️ Time 85 minutes
  • 📋 Prerequisites Lesson 1.2: Installing MySQL (a running server and your root password)
  • 🛠️ You will build explore.sql, a script that reports on your server, run three ways
  • 🗄️ Database None of your own yet: you explore MySQL's built-in mysql and information_schema databases

🔌 One Server, Many Clients

A client is any program that connects to the MySQL server, sends it SQL and shows you the answer. The server does not care which client you use: the same statement gives the same result in all of them.

graph TD A["mysql command-line client"] -->|"SQL"| C["MySQL server"] B["phpMyAdmin in a browser"] -->|"SQL"| C C --> D["same databases, same data"]
mysql clientphpMyAdmin
InterfaceText in a terminalWeb pages in a browser
Comes withEvery MySQL installationInstalled separately (needs PHP and a web server, or Docker)
Strong atTyping SQL fast, running scripts, remote servers over SSHBrowsing rows, seeing a table's structure, one-off imports and exports
Learning SQLYou type every statement yourselfButtons can write SQL for you (and hide it)

✅ This course's approach

Every lesson shows SQL as you would type it at the mysql> prompt, with the output exactly as the client prints it. Everything also works in phpMyAdmin's SQL tab, MySQL Workbench or DBeaver; only the look of the results changes.

🔑 Logging In and Out

Open a terminal (PowerShell on Windows, Terminal on macOS, your shell on Linux) and connect:

mysql -u root -p
OptionMeaning
-u rootLog in as the user root
-pAsk for the password (it is not shown while you type, and stays out of your shell history)
-h 127.0.0.1Server address; leave it out for a server on this computer
-P 3307Port (capital P); only needed when it is not 3306
bookstore (at the end)Start inside this database, as if you typed USE bookstore;

With Docker, open the client inside the container instead: docker exec -it mysql97 mysql -u root -p. After the password you see a welcome message:

Output (connection id, version and year differ)

Enter password:
Welcome to the MySQL monitor.  Commands end with ; or \g.
Your MySQL connection id is 9
Server version: 9.7.2 MySQL Community Server - GPL

Copyright (c) 2000, 2026, Oracle and/or its affiliates.

Oracle is a registered trademark of Oracle Corporation and/or its
affiliates. Other names may be trademarks of their respective
owners.

Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

mysql>

The mysql> prompt means the client is waiting for you. Everything you type there goes to the server when you finish it with a semicolon.

⚠️ No space after -p

mysql -u root -p mypassword does not do what it looks like. The client still asks for the password, and then treats mypassword as the name of a database, failing with ERROR 1049 (42000): Unknown database 'mypassword'. (Gluing it on, -pmypassword, works but leaves the password in your shell history and triggers a "can be insecure" warning. Just use -p and type it at the prompt.)

Logging out

Type exit, quit or \q (a semicolon is optional for these), or press Ctrl+D on macOS and Linux. The client says Bye and you are back in your shell. Ctrl+C does not log you out: it cancels the statement that is running or being typed.

🧭 Finding Your Way Around

Follow along at your own prompt. On a fresh server there are no databases of your own yet, so you will explore the built-in ones.

SHOW DATABASES: what is on this server?

SHOW DATABASES;

Output

+--------------------+
| Database           |
+--------------------+
| information_schema |
| mysql              |
| performance_schema |
| sys                |
+--------------------+

These four come with every MySQL server:

  • mysql: accounts, privileges, settings, the help texts. MySQL's own bookkeeping.
  • information_schema: read-only views that describe every database, table and column on the server ("data about data").
  • performance_schema and sys: performance measurements, and friendlier views over them.

Look, but never create or change tables in them. Your own databases (starting with bookstore in Lesson 2.1) will appear in this list too.

USE: pick the database to work in

USE mysql;

Output

Database changed

From now on, a table name like user means mysql.user. To check where you are at any time:

SELECT DATABASE();

Output

+------------+
| DATABASE() |
+------------+
| mysql      |
+------------+

Before the first USE, DATABASE() returns NULL: no database selected.

SHOW TABLES: what is in this database?

SHOW TABLES;

Output (38 rows on MySQL 9.7; the middle is cut here)

+------------------------------------------------------+
| Tables_in_mysql                                      |
+------------------------------------------------------+
| columns_priv                                         |
| component                                            |
| db                                                   |
| default_roles                                        |
| ...                                                  |
| time_zone_transition_type                            |
| user                                                 |
+------------------------------------------------------+

DESCRIBE: what does a table look like?

DESCRIBE (or its short form DESC) lists a table's columns with their types, whether they may be empty (Null), key information and default values. You will use it constantly to remind yourself of column names.

DESCRIBE user;

Output (the user table has 51 columns; most are cut here)

+--------------------------+-----------------------------------+------+-----+-----------------------+-------+
| Field                    | Type                              | Null | Key | Default               | Extra |
+--------------------------+-----------------------------------+------+-----+-----------------------+-------+
| Host                     | char(255)                         | NO   | PRI |                       |       |
| User                     | char(32)                          | NO   | PRI |                       |       |
| Select_priv              | enum('N','Y')                     | NO   |     | N                     |       |
| ...                      | ...                               | ...  | ... | ...                   | ...   |
| plugin                   | char(64)                          | NO   |     | caching_sha2_password |       |
| ...                      | ...                               | ...  | ... | ...                   | ...   |
+--------------------------+-----------------------------------+------+-----+-----------------------+-------+

Host and User together form the primary key (PRI): an account is a user name plus the place it connects from.

SELECT: read some rows

SELECT User, Host FROM user ORDER BY User, Host;

Output

+------------------+-----------+
| User             | Host      |
+------------------+-----------+
| mysql.infoschema | localhost |
| mysql.session    | localhost |
| mysql.sys        | localhost |
| root             | localhost |
+------------------+-----------+

The three mysql.* accounts are internal and locked: nobody logs in with them. Your list may have more rows: a Docker server adds root with host %, Ubuntu's own package adds debian-sys-maint, and a phpMyAdmin installed with apt adds phpmyadmin.

🐬 Version note: MariaDB's account tables

On MariaDB (XAMPP, many shared hosts), mysql.user is a compatibility view: SELECT User, Host works, but some columns differ (there is no account_locked, for example), and the real account data lives in mysql.global_priv. Exploring MySQL's system databases is one place where the two products really part ways.

💡 SHOW, DESCRIBE and USE are SQL too

They are MySQL's own additions to standard SQL, so they work in any client: phpMyAdmin's SQL tab, Workbench, and the program code you write later. (PostgreSQL and SQLite do not have them; they have other ways to list tables.) Commands that only the mysql client understands are a different family, coming up next.

StatementWhat it does
SHOW DATABASES;List the databases you can see
USE name;Make name the current database
SELECT DATABASE();Show the current database (NULL if none)
SHOW TABLES;List the tables of the current database
SHOW TABLES FROM name;List another database's tables without switching
DESCRIBE table;Show a table's columns
SHOW CREATE TABLE table;Show the full CREATE TABLE statement (Lesson 2.1)

⌨️ Semicolons, Prompts and Multi-Line Statements

The client sends a statement only when it sees the terminator, normally a semicolon. Until then, pressing Enter just starts a new line, and the prompt changes to tell you why it is waiting:

Output (a session transcript)

mysql> SELECT
    -> VERSION()
    -> ;
+-----------+
| VERSION() |
+-----------+
| 9.7.2     |
+-----------+
1 row in set (0.000 sec)
PromptMeansDo this
mysql>Ready for a new statementType
->Statement not finishedType ; and Enter
'> or ">A quote is still openClose it (' or "), then ;
`>A backtick is still openType `, then ;
/*>A /* comment is still openType */

To give up on a half-typed statement, type \c and press Enter (inside an open quote, close the quote first). Use the ↑ and ↓ arrows to bring back earlier statements.

Because nothing runs before the semicolon, you can and should spread longer statements over several lines. Keywords are not case-sensitive (select works), but writing them in capitals makes SQL easier to read:

SELECT
    User,
    Host
FROM user
WHERE Host = 'localhost'
ORDER BY User;

Output

+------------------+-----------+
| User             | Host      |
+------------------+-----------+
| mysql.infoschema | localhost |
| mysql.session    | localhost |
| mysql.sys        | localhost |
| root             | localhost |
+------------------+-----------+

🧰 Client Commands: \G, \c, help

Some things you type are not SQL at all: the mysql client handles them itself and never sends them to the server. They start with a backslash or a keyword such as help, and phpMyAdmin does not understand them.

CommandLong formWhat it does
\GegoEnd the statement (instead of ;) and show the result vertically
\cclearThrow away the statement you are typing
\qexit, quitLeave the client
\sstatusConnection details: server version, user, current database, character sets
\.source file.sqlRun every statement in a file
\hhelpList the client commands
\!systemRun a shell command. Off by default in MySQL 9.x (the client must be started with --system-command)

Vertical output with \G

A row with many columns wraps into an unreadable mess in a narrow terminal. End the statement with \G instead of ; and every column gets its own line:

SELECT User, Host, plugin, account_locked
FROM user
WHERE User = 'root' AND Host = 'localhost'\G

Output

*************************** 1. row ***************************
          User: root
          Host: localhost
        plugin: caching_sha2_password
account_locked: N

Try SELECT * FROM user WHERE User = 'root'\G to see all of root's 50-odd columns, one per line.

Help, two kinds

help on its own lists the client commands from the table above. help followed by an SQL keyword asks the server for its built-in reference page on that statement:

HELP 'SHOW DATABASES';

Output (abbreviated; the link's version number can differ)

Name: 'SHOW DATABASES'
Description:
Syntax:
SHOW {DATABASES | SCHEMAS}
    [LIKE 'pattern' | WHERE expr]

SHOW DATABASES lists the databases on the MySQL server host. SHOW
SCHEMAS is a synonym for SHOW DATABASES. ...

HELP contents lists the topics. For anything longer, the online MySQL Reference Manual is easier to read, but the built-in help works offline and over SSH.

📄 Saving and Running .sql Files

Typing long statements again and again gets old fast. Save them in a plain-text file with the .sql extension and let the client run the whole file. Create a folder for the course, for example mysql-course in your home folder, and in it a file hello.sql (VS Code or any plain-text editor; not Word):

-- hello.sql: my first script
SELECT 'Hello from a SQL file!' AS message;
SELECT NOW() AS now_time;
SELECT CURRENT_USER() AS logged_in_as;

Output (your time differs)

+------------------------+
| message                |
+------------------------+
| Hello from a SQL file! |
+------------------------+
+---------------------+
| now_time            |
+---------------------+
| 2026-03-02 14:05:31 |
+---------------------+
+----------------+
| logged_in_as   |
+----------------+
| root@localhost |
+----------------+

Lines starting with -- (two dashes and a space) are comments. Note the alias now_time: why not current_time is one of the Common Mistakes below.

Way 1: SOURCE, from inside the client

At the mysql> prompt, give the path to the file. On Windows, write the path with forward slashes:

SOURCE ~/mysql-course/hello.sql
SOURCE C:/Users/you/mysql-course/hello.sql

The results print one after another, exactly as if you had typed each statement. SOURCE is a client command, so it needs no semicolon, and it is the way the course loads its practice database in later lessons.

Way 2: redirect the file into mysql, from the shell

Without logging in first, hand the file to the client with <. It runs the file and exits:

mysql -u root -p < ~/mysql-course/hello.sql

Output (your time differs)

Enter password:
message
Hello from a SQL file!
now_time
2026-03-02 14:06:12
logged_in_as
root@localhost

When it reads from a file, the client switches to batch mode and prints plain tab-separated text instead of boxes. Add -t (mysql -t -u root -p < hello.sql) to get the boxes back. Add a database name to start in it: mysql -u root -p bookstore < report.sql. Batch mode is how scripts, scheduled jobs and deployment tools run SQL.

⚠️ Windows PowerShell has no < redirect

PowerShell answers "The '<' operator is reserved for future use." Run the line through the classic command interpreter instead: cmd /c "mysql -u root -p < C:\Users\you\mysql-course\hello.sql", or use SOURCE from inside the client.

🐬 Version note: client commands in scripts (MySQL 9.x)

Since MySQL 9, the mysql client ignores its own backslash commands and SOURCE in batch mode, that is when it reads a redirected file or runs -e "...". A script containing \G stops with ERROR at line 1: Unknown command '\G'., and a SOURCE line is sent to the server, which answers with syntax error 1064. Interactive use is not affected, and neither is a file you run with SOURCE from the prompt. In scripts, end statements with ;, and if you really need client commands, start the client with --commands: mysql --commands -u root -p < file.sql. MySQL 8.4 and MariaDB still allow them by default.

🌐 phpMyAdmin: A Guided Tour

phpMyAdmin is a free web application for managing MySQL and MariaDB. You meet it on most shared web hosts (often inside cPanel), in XAMPP, and anywhere someone installed it for you. If you set it up in Lesson 1.2, open it now: http://localhost:8080 for the Docker container, http://localhost/phpmyadmin for apt or XAMPP. No phpMyAdmin? Read along; you will recognize it when you meet it.

graph TD A["Log in: username and password"] --> B["Navigation panel: database tree"] B --> C["Pick a database or table"] C --> D["Tabs: Browse, Structure, SQL, Import, Export"]

Logging in and the layout

  • The login page asks for a Username and Password: the same MySQL account you use in the terminal (here root). phpMyAdmin has no accounts of its own.
  • The navigation panel on the left lists every database as a tree; click + to see its tables.
  • The tabs along the top change with what you selected: the server (Databases, SQL, Status, User accounts, Export, Import, Variables...), a database (Structure, SQL, Search, Query, Export, Import, Operations...), or a table (Browse, Structure, SQL, Search, Insert, Export, Import...).
  • The home page shows the server version (look for "Server version: 9.7.2 - MySQL Community Server - GPL") and phpMyAdmin's own version.

Browse and Structure

  1. In the navigation panel, expand mysql and click the user table.
  2. The Browse tab opens: the rows in a grid, the same data as SELECT * FROM user;. Above the grid, phpMyAdmin shows the SQL it ran (something like SELECT * FROM `user` LIMIT 0, 25). Reading that SQL is a great way to learn.
  3. Click Structure: the column list, the visual version of DESCRIBE user;.

The SQL tab

  1. With the mysql database selected, click SQL.
  2. Type SELECT User, Host FROM user ORDER BY User, Host;
  3. Click Go (or press Ctrl+Enter). The result appears as a table under the query.

Several statements in one go are fine; each result gets its own box. Client commands such as \G, SOURCE and help do not work here, because there is no mysql client involved.

Import and Export

Import runs a .sql file you upload (choose the file, scroll down, click Import), the browser version of SOURCE; it is limited by the upload size the server allows. Export saves a database or table as a .sql file (or CSV and other formats), the browser version of the mysqldump tool you will use in Lesson 8.1.

🛑 Careful with the red buttons

phpMyAdmin makes destructive actions one click away: Drop deletes a table or database, Empty deletes every row. It asks for confirmation, but there is no undo. On a server holding real data, read the confirmation text every time.

⚠️ Common Mistakes

1. Forgetting the semicolon

Output (a session transcript)

mysql> SHOW DATABASES
    ->
    ->

What it means: nothing is wrong; the client is waiting for the end of the statement. Fix: type ; and press Enter. If the prompt is '>, close the quote first.

2. Using a database that does not exist (yet)

USE bookstore;

Error

ERROR 1049 (42000): Unknown database 'bookstore'

What it means: there is no database by that name on this server: a typo, the wrong server, or (here) a database you have not created yet. You create bookstore in Lesson 2.1. Fix: SHOW DATABASES; and copy the exact name. On Linux servers database and table names are case-sensitive, so Bookstore and bookstore differ.

3. Looking for a table in the wrong database

DESCRIBE customers;

Error

ERROR 1146 (42S02): Table 'mysql.customers' doesn't exist

What it means: the message names the database it looked in: mysql, because that is where the last USE left you. Fix: SELECT DATABASE(); to check, then USE the right database, or write the full name database.table.

4. Using a reserved word as a name

SELECT NOW() AS current_time;

Error

ERROR 1064 (42000): You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version for the right syntax to use near 'current_time' at line 1

What it means: CURRENT_TIME is a built-in SQL function, so MySQL reads the alias as the start of something else and gets lost; 1064 is the general "I could not read this statement" error, and near '...' points at the spot. Other common traps are order, rank, key and group. Fix: pick another name, or wrap it in backticks.

SELECT NOW() AS now_time, NOW() AS `current_time`;

Output (your time differs)

+---------------------+---------------------+
| now_time            | current_time        |
+---------------------+---------------------+
| 2026-03-02 14:07:45 | 2026-03-02 14:07:45 |
+---------------------+---------------------+

5. Client commands in a redirected script (MySQL 9.x)

You save a query ending in \G in roots.sql, and it worked at the prompt. Run from the shell, it stops at once:

mysql -u root -p < roots.sql

Error (the line number depends on your file)

ERROR at line 1: Unknown command '\G'.

What it means: MySQL 9.x's client switches off its own commands in batch mode (see the version note above). Fix: end statements in scripts with ;, or run mysql --commands -u root -p < roots.sql. The same file run with SOURCE from the prompt works either way.

🛠️ Project: A Server Report Script

You will write explore.sql, a short script that describes your server, and run it three ways: statement by statement, with SOURCE, and from the shell. It is your first reusable script, and the habit (save your SQL in files) will carry you through the course. Allow about 30 minutes.

🛠️ Step 1: Where am I? (5 min)

Log in and run the orientation query. USER() is who you said you are; CURRENT_USER() is the account MySQL matched you to.

SELECT USER() AS you_said, CURRENT_USER() AS account, DATABASE() AS current_db;

Output

+----------------+----------------+------------+
| you_said       | account        | current_db |
+----------------+----------------+------------+
| root@localhost | root@localhost | mysql      |
+----------------+----------------+------------+

If you are still in mysql from earlier, current_db says so; in a fresh session it is NULL.

🛠️ Step 2: Count the tables in the system databases (5 min)

information_schema.TABLES has one row per table on the server. This query counts them per database. (GROUP BY and COUNT get a full lesson in Module 3; for now, read it as "count the rows for each database".)

SELECT TABLE_SCHEMA AS db, COUNT(*) AS tables
FROM information_schema.TABLES
GROUP BY TABLE_SCHEMA
ORDER BY TABLE_SCHEMA;

Output

+--------------------+--------+
| db                 | tables |
+--------------------+--------+
| information_schema |     84 |
| mysql              |     38 |
| performance_schema |    117 |
| sys                |    101 |
+--------------------+--------+

The exact counts depend on the server version: MySQL 8.4's information_schema has 78 tables, for example, and MariaDB's system databases are laid out differently. What matters is the habit: information_schema can answer questions about every table on the server.

🛠️ Step 3: Save it as explore.sql (10 min)

In your mysql-course folder, create explore.sql with a header comment and the queries below (the first is the step 2 query). Every statement ends with a semicolon, no \G, so the file runs in any mode.

-- explore.sql: a quick report on this MySQL server
SELECT VERSION() AS version, CURRENT_USER() AS account;

SELECT TABLE_SCHEMA AS db, COUNT(*) AS tables
FROM information_schema.TABLES
GROUP BY TABLE_SCHEMA
ORDER BY TABLE_SCHEMA;

SELECT User, Host, plugin
FROM mysql.user
ORDER BY User, Host;

Output (your version can differ)

+---------+----------------+
| version | account        |
+---------+----------------+
| 9.7.2   | root@localhost |
+---------+----------------+
...
+------------------+-----------+-----------------------+
| User             | Host      | plugin                |
+------------------+-----------+-----------------------+
| mysql.infoschema | localhost | caching_sha2_password |
| mysql.session    | localhost | caching_sha2_password |
| mysql.sys        | localhost | caching_sha2_password |
| root             | localhost | caching_sha2_password |
+------------------+-----------+-----------------------+

🛠️ Step 4: Run it with SOURCE and from the shell (5 min)

At the prompt: SOURCE ~/mysql-course/explore.sql (Windows: SOURCE C:/Users/you/mysql-course/explore.sql). Then exit and run it from the shell, once plain and once with -t:

mysql -u root -p < ~/mysql-course/explore.sql
mysql -t -u root -p < ~/mysql-course/explore.sql

Compare the three outputs: same data, boxed at the prompt and with -t, tab-separated without it. (PowerShell: wrap the line in cmd /c "...".)

🛠️ Step 5: Same query, phpMyAdmin (5 min)

If you have phpMyAdmin, open its SQL tab (server level, no database selected), paste the whole file and click Go. Then find mysql > user in the navigation panel and compare the Structure tab with DESCRIBE mysql.user;. No phpMyAdmin? Run DESCRIBE mysql.user; and SHOW TABLES FROM mysql; in the client instead.

✅ Project Completion Checklist

  • explore.sql exists in your course folder, starts with a comment and ends every statement with ;
  • It runs without errors with SOURCE at the prompt
  • It runs from the shell with mysql -u root -p < explore.sql, and you can explain why that output has no boxes
  • You can say how many tables the mysql database has, and which accounts exist on your server
  • You ran at least one query in phpMyAdmin (or DESCRIBE in the client if you have no phpMyAdmin)

🏋️ Hands-on Exercises

🏋️ Exercise 1: Find the Privilege Tables

Without switching databases, list only the tables of the mysql database whose names contain priv.

💡 Hint

SHOW TABLES accepts FROM database and a LIKE 'pattern', where % means "any characters".

✅ Solution 
SHOW TABLES FROM mysql LIKE '%priv%';

Output

+--------------------------+
| Tables_in_mysql (%priv%) |
+--------------------------+
| columns_priv             |
| procs_priv               |
| proxies_priv             |
| tables_priv              |
+--------------------------+

These tables store who may do what on which column, procedure, proxy and table. Lesson 7.4's GRANT statements write into them for you.

🏋️ Exercise 2: One Column's Details

What data type is the User column of mysql.user? Show just that column's line of the table description.

💡 Hint

SHOW COLUMNS FROM table LIKE 'name' is DESCRIBE with a filter.

✅ Solution 
SHOW COLUMNS FROM mysql.user LIKE 'User';

Output

+-------+----------+------+-----+---------+-------+
| Field | Type     | Null | Key | Default | Extra |
+-------+----------+------+-----+---------+-------+
| User  | char(32) | NO   | PRI |         |       |
+-------+----------+------+-----+---------+-------+

char(32): a MySQL user name can be at most 32 characters.

🏋️ Exercise 3: Vertical Status

Show the name, host and lock status of every account on the server, vertically. Then type status (or \s) and find the server version, your current database and the connection type in its output.

💡 Hint

End the SELECT with \G instead of a semicolon. status is a client command and needs no semicolon.

✅ Solution 
SELECT User, Host, account_locked
FROM mysql.user
ORDER BY User, Host\G

Output

*************************** 1. row ***************************
          User: mysql.infoschema
          Host: localhost
account_locked: Y
*************************** 2. row ***************************
          User: mysql.session
          Host: localhost
account_locked: Y
*************************** 3. row ***************************
          User: mysql.sys
          Host: localhost
account_locked: Y
*************************** 4. row ***************************
          User: root
          Host: localhost
account_locked: N

Only root is unlocked. In the status output, look for "Server version", "Current database" and "Connection" ("Localhost via UNIX socket" on macOS and Linux, "TCP/IP" or "Named pipe" on Windows and through Docker's port).

🏋️ Exercise 4 (Stretch): A Script That Uses \G

Write roots_vertical.sql holding the Exercise 3 query (ending in \G). Make it run from the shell on MySQL 9.7 without changing the file, and explain why the plain redirect fails.

💡 Hint

The fix is an option for the mysql command, not a change to the SQL.

✅ Solution 
mysql -u root -p < roots_vertical.sql              # ERROR at line 1: Unknown command '\G'.
mysql --commands -u root -p < roots_vertical.sql   # works: client commands enabled

In batch mode, the MySQL 9.x client does not process its own commands unless you pass --commands. Running the file with SOURCE from the prompt also works. The most portable fix is to end the statement with ; and add -E (--vertical) to the command line when you want vertical output: mysql -E -u root -p < roots.sql.

❓ Common Questions at This Stage

Do I have to write SQL keywords in capitals?

No. select user from mysql.user; works. Capital keywords are a convention that makes it easy to see which words are SQL and which are your names. Table and database names are a different story: on Linux they are case-sensitive by default, on Windows and macOS not. Use lowercase names and you never have to think about it.

How do I clear the screen in the mysql client?

On macOS and Linux, press Ctrl+L. The old trick \! clear runs a shell command, and MySQL 9.x's client disables shell commands unless it is started with --system-command. On Windows, the simplest way is to exit and open a new window.

Can I keep a log of everything I type and see?

Yes: tee ~/mysql-course/session.log (Windows: tee C:/Users/you/mysql-course/session.log) at the prompt starts copying the whole session into that file, and notee stops. It is a handy way to keep notes of a practice session.

MySQL Workbench or DBeaver instead of phpMyAdmin?

Both are fine desktop clients and need no web server: connect to host 127.0.0.1, port 3306, user root. Workbench is Oracle's own tool for MySQL; DBeaver works with many databases. The SQL in this course runs unchanged in either. Keep the mysql client as your main tool while learning.

📝 Lesson Summary

🎓 Key Takeaways

  • Log in with mysql -u root -p (no space, no password after -p); leave with exit, \q or Ctrl+D
  • Explore with SHOW DATABASES, USE, SELECT DATABASE(), SHOW TABLES, DESCRIBE: SQL statements that work in every client
  • Nothing runs until the semicolon; -> means "waiting", '> means "open quote", \c abandons a statement
  • \G, \c, status, source, help are client commands, unknown to phpMyAdmin
  • Run files with SOURCE path at the prompt or mysql -u root -p < file.sql from the shell; MySQL 9.x needs --commands for client commands in redirected files
  • phpMyAdmin: navigation panel, Browse, Structure, SQL, Import, Export; same server, same SQL
  • Avoid reserved words such as current_time as names (error 1064)
