✅ Best Practices Worth Keeping

Not rules for their own sake: each of these prevents a problem you met somewhere in this course.

Design

  • Every table gets a primary key. InnoDB stores rows in primary-key order; without one it invents a hidden key, and replication and many tools work badly.
  • Normalize first (3NF), denormalize only with a measured reason. Store each fact once and derive the rest (Lesson 6.3, and "available" in the final project).
  • Pick exact types: DECIMAL for money, DATE/DATETIME for time, utf8mb4 for text. Never FLOAT for money (see Common Mistakes).
  • Let the database enforce what it can: NOT NULL, UNIQUE, CHECK, foreign keys. Application code changes and has bugs; constraints catch them.
  • Name things consistently: snake_case, plural table names, <table>_id for foreign keys, named constraints (fk_books_author), and no reserved words.

Queries

  • List the columns you need in application code rather than SELECT *: the query keeps working when someone adds a column, and an index can sometimes answer it alone.
  • Always ORDER BY when order matters, because nothing else guarantees it.
  • Preview with SELECT before an UPDATE or DELETE, using the same WHERE; wrap risky changes in a transaction.
  • Never turn off ONLY_FULL_GROUP_BY or strict mode to make an error go away; fix the query.
  • Measure before tuning: EXPLAIN (or EXPLAIN ANALYZE) first, an index second, and only for queries that are actually slow. For deep pagination, "the next 20 after id 5000" (WHERE id > 5000 ORDER BY id LIMIT 20) beats a large OFFSET.

Security

  • Parameterized queries, always: never build SQL by gluing user input into a string.
  • One account per application, with least privilege; root only for administration, and never over the network.
  • Secrets outside the code: environment variables, a secrets manager, or an option file only your user can read. Never commit passwords.
  • Modern authentication: caching_sha2_password is the default and modern drivers support it. Advice to switch accounts to mysql_native_password is outdated; MySQL 9.x no longer has that plugin.
  • Stay on a supported release and apply updates.

Operations

  • Back up automatically and test the restore on a schedule (Lesson 8.1). Keep a copy off the machine.
  • Keep the schema in version-controlled scripts, as in the final project, so any database can be rebuilt from files. Teams use migration tools (Flyway, Liquibase, or the one built into their framework) for this.
  • Watch the slow query log (slow_query_log, long_query_time) to find the queries worth tuning.
  • Plan upgrades around LTS releases. MySQL has Long-Term Support releases (8.4, 9.7) that receive fixes for years, and Innovation releases in between that add features quickly but are supported only until the next one. Production systems usually stay on an LTS. After 9.7, Innovation releases use calendar-style version numbers (26.x), so "the latest" from brew install mysql or the Docker tag mysql:latest is an Innovation release, not 9.7: ask for the LTS by name (mysql@9.7, mysql:9.7) as Lesson 1.2 did. MySQL 8.0 has reached its end of life.

🩺 Checking a Database with information_schema

Every MySQL server describes itself in the read-only information_schema database: one row per table in TABLES, one per column in COLUMNS, one per constraint in TABLE_CONSTRAINTS, and so on. Because it is just tables, you can query it to check a design automatically instead of by eye.

To see the checks find something, create a deliberately flawed table, the kind that turns up in old projects:

CREATE TABLE hc_demo_payments (
    paid_on DATE,
    amount  FLOAT,
    note    VARCHAR(100) CHARACTER SET latin1
);

Check 1: tables without a primary key

SELECT t.TABLE_NAME AS table_without_pk
FROM information_schema.TABLES AS t
LEFT JOIN information_schema.TABLE_CONSTRAINTS AS c
       ON c.TABLE_SCHEMA = t.TABLE_SCHEMA
      AND c.TABLE_NAME = t.TABLE_NAME
      AND c.CONSTRAINT_TYPE = 'PRIMARY KEY'
WHERE t.TABLE_SCHEMA = 'bookstore'
  AND t.TABLE_TYPE = 'BASE TABLE'
  AND c.CONSTRAINT_NAME IS NULL
ORDER BY t.TABLE_NAME;

Output

+------------------+
| table_without_pk |
+------------------+
| hc_demo_payments |
+------------------+

The pattern is the "find what is missing" LEFT JOIN ... IS NULL from Lesson 4.3, pointed at the catalog. The condition on CONSTRAINT_TYPE sits in ON, not WHERE, for the reason you saw in the final project's Common Mistakes.

Check 2: risky column types and old character sets

SELECT TABLE_NAME, COLUMN_NAME, COLUMN_TYPE, CHARACTER_SET_NAME
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'bookstore'
  AND (DATA_TYPE IN ('float', 'double')
       OR CHARACTER_SET_NAME NOT IN ('utf8mb4', 'binary'))
ORDER BY TABLE_NAME, ORDINAL_POSITION;

Output

+------------------+-------------+--------------+--------------------+
| TABLE_NAME       | COLUMN_NAME | COLUMN_TYPE  | CHARACTER_SET_NAME |
+------------------+-------------+--------------+--------------------+
| hc_demo_payments | amount      | float        | NULL               |
| hc_demo_payments | note        | varchar(100) | latin1             |
+------------------+-------------+--------------+--------------------+

Only the demo table is flagged: every text column in the bookstore is utf8mb4 and all money is DECIMAL. (Number and date columns have no character set, so CHARACTER_SET_NAME is NULL for them and the NOT IN test is not true for them.)

Check 3: foreign keys and what they do on delete

SELECT TABLE_NAME, CONSTRAINT_NAME, REFERENCED_TABLE_NAME, DELETE_RULE
FROM information_schema.REFERENTIAL_CONSTRAINTS
WHERE CONSTRAINT_SCHEMA = 'bookstore'
ORDER BY TABLE_NAME, CONSTRAINT_NAME;

Output

+-----------------+----------------------+-----------------------+-------------+
| TABLE_NAME      | CONSTRAINT_NAME      | REFERENCED_TABLE_NAME | DELETE_RULE |
+-----------------+----------------------+-----------------------+-------------+
| book_categories | fk_bc_book           | books                 | CASCADE     |
| book_categories | fk_bc_category       | categories            | CASCADE     |
| books           | fk_books_author      | authors               | RESTRICT    |
| employees       | fk_employees_manager | employees             | SET NULL    |
| order_items     | fk_items_book        | books                 | RESTRICT    |
| order_items     | fk_items_order       | orders                | CASCADE     |
| orders          | fk_orders_customer   | customers             | RESTRICT    |
+-----------------+----------------------+-----------------------+-------------+

One glance shows every relationship and its delete rule. Deleting an order removes its items (CASCADE), deleting a customer with orders is refused (RESTRICT), and deleting a manager leaves the staff without one (SET NULL). If any line surprises you, that is a design discussion to have now rather than after a bad delete.

DROP TABLE hc_demo_payments;

🔌 Connecting from Application Code

Real users never see a mysql> prompt. A web or desktop application connects through a driver (also called a connector) for its language, and sends SQL with the user's input as parameters, separate from the SQL text. The pattern is the same everywhere:

graph TD A["connect with an app account"] --> B["SQL with placeholders"] B --> C["execute with the values"] C --> D["read the rows"] D --> E["close or return to the pool"]

Each example below reads the password from an environment variable and asks for the books under a price the user chose. The account is a least-privilege one like those from Lesson 7.4, never root.

PHP (PDO)

<?php
$pdo = new PDO(
    'mysql:host=localhost;dbname=bookstore;charset=utf8mb4',
    'bookstore_app',
    getenv('DB_PASSWORD'),
    [PDO::ATTR_EMULATE_PREPARES => false]
);   // since PHP 8, PDO throws exceptions on errors by default

$stmt = $pdo->prepare('SELECT title, price FROM books WHERE price < :max_price ORDER BY price');
$stmt->execute(['max_price' => $_GET['max_price'] ?? 10]);

foreach ($stmt as $row) {
    echo $row['title'], ' - $', $row['price'], "\n";
}

Python (mysql-connector-python)

import os
import mysql.connector

conn = mysql.connector.connect(
    host="localhost", database="bookstore",
    user="bookstore_app", password=os.environ["DB_PASSWORD"],
)
with conn.cursor(dictionary=True) as cur:
    cur.execute(
        "SELECT title, price FROM books WHERE price < %s ORDER BY price",
        (max_price,),
    )
    for row in cur:
        print(f"{row['title']} - ${row['price']}")
conn.close()

JavaScript / Node.js (mysql2)

import mysql from 'mysql2/promise';

const conn = await mysql.createConnection({
  host: 'localhost', database: 'bookstore',
  user: 'bookstore_app', password: process.env.DB_PASSWORD,
});
const [rows] = await conn.execute(
  'SELECT title, price FROM books WHERE price < ? ORDER BY price',
  [maxPrice],
);
for (const row of rows) console.log(`${row.title} - $${row.price}`);
await conn.end();

C# (.NET, MySqlConnector)

using MySqlConnector;

var connStr = "Server=localhost;Database=bookstore;User ID=bookstore_app;Password="
            + Environment.GetEnvironmentVariable("DB_PASSWORD");
await using var conn = new MySqlConnection(connStr);
await conn.OpenAsync();

await using var cmd = new MySqlCommand(
    "SELECT title, price FROM books WHERE price < @max_price ORDER BY price", conn);
cmd.Parameters.AddWithValue("@max_price", maxPrice);

await using var reader = await cmd.ExecuteReaderAsync();
while (await reader.ReadAsync())
    Console.WriteLine($"{reader.GetString(0)} - ${reader.GetDecimal(1)}");

Four languages, one idea: the placeholder (:max_price, %s, ?, @max_price) marks where a value goes, and the driver sends the value separately, so it can never change the meaning of the SQL. You can do exactly the same at the mysql> prompt with PREPARE and EXECUTE ... USING; the Common Mistakes section shows why it matters.

ORMs: the next layer up

An ORM (object-relational mapper) lets you work with classes and objects and writes the SQL for you, parameterized. Popular choices: Eloquent (Laravel) and Doctrine for PHP; SQLAlchemy and the Django ORM for Python; Prisma, Drizzle, Sequelize and TypeORM for JavaScript and TypeScript; Entity Framework Core (and the lighter Dapper) for C#. Here is the same query in SQLAlchemy 2:

import os
from decimal import Decimal
from sqlalchemy import create_engine, select, String, Numeric
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, Session

class Base(DeclarativeBase):
    pass

class Book(Base):
    __tablename__ = "books"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(200))
    price: Mapped[Decimal] = mapped_column(Numeric(8, 2))

engine = create_engine(
    f"mysql+mysqlconnector://bookstore_app:{os.environ['DB_PASSWORD']}@localhost/bookstore")
with Session(engine) as session:
    for book in session.scalars(select(Book).where(Book.price < 10).order_by(Book.price)):
        print(book.title, book.price)

✅ You learned it in the right order

ORMs save a lot of typing for everyday reads and writes, but they generate SQL, and sometimes slow SQL. Because you know what a join, an index and a transaction are, you can turn on the ORM's query logging, read what it sends, run EXPLAIN on it, and drop down to plain SQL for the reports and bulk jobs ORMs handle poorly.

⚠️ Common Mistakes

1. Building SQL from user input (silent, and dangerous)

An application looks up a customer by the email typed into a form. Here is what string-building does when the "email" is crafted by an attacker. PREPARE and EXECUTE let you see it at the prompt:

SET @input = 'nobody@example.com'' OR ''1''=''1';

SET @sql = CONCAT('SELECT first_name, email FROM customers WHERE email = ''', @input, '''');
SELECT @sql AS query_sent;

PREPARE lookup FROM @sql;
EXECUTE lookup;
DEALLOCATE PREPARE lookup;

Output

+---------------------------------------------------------------------------------------+
| query_sent                                                                            |
+---------------------------------------------------------------------------------------+
| SELECT first_name, email FROM customers WHERE email = 'nobody@example.com' OR '1'='1' |
+---------------------------------------------------------------------------------------+
Statement prepared
+------------+-------------------+
| first_name | email             |
+------------+-------------------+
| Alice      | alice@example.com |
| Bob        | bob@example.com   |
| Carol      | carol@example.com |
| Dave       | dave@example.com  |
| Eve        | eve@example.com   |
| Frank      | frank@example.com |
| Grace      | grace@example.com |
| Hank       | hank@example.com  |
+------------+-------------------+

What it means: the quote inside the input closed the string early, and OR '1'='1' became part of the SQL. The query is true for every row, so every customer's email leaks, with no error at all. Variations of this delete tables or bypass logins. Fix: a placeholder. The value is sent separately and is only ever a value:

PREPARE lookup FROM 'SELECT first_name, email FROM customers WHERE email = ?';
EXECUTE lookup USING @input;
DEALLOCATE PREPARE lookup;

Output

Statement prepared
Empty set

No customer has that strange email address, so nothing comes back. This is exactly what the drivers in the previous section do. Escaping quotes by hand is not a substitute: it is easy to get wrong, and placeholders cost nothing.

2. An UPDATE without a usable WHERE

The mysql client's --safe-updates option (also SET SQL_SAFE_UPDATES = 1) refuses an UPDATE or DELETE that does not filter on a key. It is a good habit on any server holding real data:

SET SQL_SAFE_UPDATES = 1;

UPDATE books SET price = price * 1.10;

Error

ERROR 1175 (HY000): You are using safe update mode and you tried to update a table without a WHERE that uses a KEY column.

What it means: the statement would change every row, which is usually a forgotten WHERE. Fix: add the WHERE you meant (WHERE id = 3). If you really mean every row, add a key condition such as WHERE id > 0 on purpose, or switch the setting off for that one statement.

SET SQL_SAFE_UPDATES = 0;

3. Following old advice about mysql_native_password

CREATE USER 'legacy_app'@'localhost'
    IDENTIFIED WITH mysql_native_password BY 'Change-Me-Legacy-2026';

Error

ERROR 1524 (HY000): Plugin 'mysql_native_password' is not loaded

What it means: the old authentication plugin is gone in MySQL 9.x (and disabled by default in 8.4). Old tutorials suggest it to work around drivers that could not handle the newer method. Fix: create the account normally (IDENTIFIED BY ... uses caching_sha2_password) and update the driver; every maintained driver supports it.

4. FLOAT for money (silent)

CREATE TEMPORARY TABLE till (amount_float FLOAT, amount_decimal DECIMAL(8, 2));
INSERT INTO till VALUES (0.10, 0.10), (0.20, 0.20), (19.99, 19.99);

SELECT SUM(amount_float) AS total_float, SUM(amount_decimal) AS total_decimal
FROM till;

DROP TEMPORARY TABLE till;

Output

+--------------------+---------------+
| total_float        | total_decimal |
+--------------------+---------------+
| 20.289999775588512 |         20.29 |
+--------------------+---------------+

What it means: FLOAT stores binary approximations, so cents drift: the "total" is not 20.29. Across thousands of rows and some rounding, accounts stop balancing. Fix: DECIMAL(p, 2) for anything counted in cents. Health check 2 finds FLOAT and DOUBLE columns for you.

🛠️ Project: Health Check and Learning Plan

Turn this lesson's checks into a script you can point at any database you meet in the future (your final project, a client's database, a job's), and finish the course with a written plan. Allow about 25 minutes.

🛠️ Step 1: Make the script work for any database (5 min)

Create health_check.sql. Instead of writing 'bookstore' into every query, set the database name once in a variable:

SET @db = 'bookstore';

SELECT @db AS checking, COUNT(*) AS tables_found
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = @db AND TABLE_TYPE = 'BASE TABLE';

Output

+-----------+--------------+
| checking  | tables_found |
+-----------+--------------+
| bookstore |            8 |
+-----------+--------------+

🛠️ Step 2: Add the three checks (5 min)

Paste in checks 1 to 3 from this lesson, replacing 'bookstore' with @db. Run the file with SOURCE health_check.sql; on the bookstore, checks 1 and 2 print Empty set, which is the result you want.

🛠️ Step 3: Find foreign keys without their own index (5 min)

InnoDB creates an index for every foreign key automatically if none exists, so this is mostly a check for other engines and hand-made schemas. Still, it is a good example of a check that joins two catalog tables. Add it to the file:

SELECT k.TABLE_NAME, k.COLUMN_NAME, k.CONSTRAINT_NAME
FROM information_schema.KEY_COLUMN_USAGE AS k
LEFT JOIN information_schema.STATISTICS AS s
       ON s.TABLE_SCHEMA = k.TABLE_SCHEMA
      AND s.TABLE_NAME = k.TABLE_NAME
      AND s.COLUMN_NAME = k.COLUMN_NAME
      AND s.SEQ_IN_INDEX = 1
WHERE k.TABLE_SCHEMA = @db
  AND k.REFERENCED_TABLE_NAME IS NOT NULL
  AND s.INDEX_NAME IS NULL
ORDER BY k.TABLE_NAME, k.COLUMN_NAME;

Output

Empty set

Every foreign-key column in the bookstore leads an index, so nothing is reported. SEQ_IN_INDEX = 1 matters: a column that is only the second part of an index does not help lookups on it alone.

🛠️ Step 4: Run it on your final project (5 min)

Change the first line to SET @db = 'tool_library'; (or whatever you named your project database), run the file again, and fix anything it reports. Add a comment at the top of the file saying what each check means, so the script explains itself in a year.

🛠️ Step 5: Write your learning plan (5 min)

In learning_plan.md, answer: Which path from "Choose a path by goal" fits you? Which one topic from "Topics this course did not cover" will you learn first, and with what small project? What will you build in the next month? Put a date next to each answer.

🏋️ Hands-on Exercises

🏋️ Exercise 1: A Safe Search

Write a prepared statement that lists the titles and prices of books under a maximum price written by a given author, both supplied as parameters. Run it for George Orwell with a maximum of 9.00, then for the "author" x' OR 'x'='x.

💡 Hint

Two ? placeholders, and EXECUTE ... USING @a, @b in the same order. Join books to authors on author_id.

✅ Solution 
PREPARE by_author FROM
    'SELECT b.title, b.price
     FROM books AS b
     JOIN authors AS a ON a.id = b.author_id
     WHERE a.name = ? AND b.price < ?
     ORDER BY b.price';

SET @author = 'George Orwell', @max_price = 9.00;
EXECUTE by_author USING @author, @max_price;

SET @author = 'x'' OR ''x''=''x';
EXECUTE by_author USING @author, @max_price;

DEALLOCATE PREPARE by_author;

Output

Statement prepared
+-------------+-------+
| title       | price |
+-------------+-------+
| Animal Farm |  8.49 |
+-------------+-------+
Empty set

Orwell has one book under 9.00, Animal Farm (1984 costs 9.99). The injection attempt finds no author with that odd name and returns nothing.

🏋️ Exercise 2: Where Can NULL Hide?

List every column in bookstore that allows NULL, with its table and type. For each one, decide whether NULL has a clear meaning there.

💡 Hint

information_schema.COLUMNS has an IS_NULLABLE column holding 'YES' or 'NO'.

✅ Solution 
SELECT TABLE_NAME, COLUMN_NAME, COLUMN_TYPE
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'bookstore' AND IS_NULLABLE = 'YES'
ORDER BY TABLE_NAME, ORDINAL_POSITION;

Output

+------------+-------------+--------------------------------------------------+
| TABLE_NAME | COLUMN_NAME | COLUMN_TYPE                                      |
+------------+-------------+--------------------------------------------------+
| authors    | birth_year  | int                                              |
| books      | pages       | int                                              |
| books      | published   | date                                             |
| books      | in_stock    | tinyint(1)                                       |
| categories | description | varchar(255)                                     |
| customers  | city        | varchar(50)                                      |
| customers  | created_at  | datetime                                         |
| employees  | department  | enum('sales','inventory','management','support') |
| employees  | manager_id  | int                                              |
| employees  | is_active   | tinyint(1)                                       |
+------------+-------------+--------------------------------------------------+

Most have a clear meaning: an unknown birth year or city, no manager (Maria, at the top), no description yet. Some are worth a second look: should in_stock or is_active ever be unknown? A NOT NULL with a default would rule that out.

🏋️ Exercise 3 (Stretch): A One-Line Summary per Table

For each table in bookstore, show the number of columns, the number of indexes and the number of foreign keys it declares, in one query.

💡 Hint

Start from information_schema.TABLES and use three correlated subqueries (Lesson 3.4) against COLUMNS, STATISTICS (count DISTINCT INDEX_NAME) and REFERENTIAL_CONSTRAINTS.

✅ Solution 
SELECT t.TABLE_NAME,
       (SELECT COUNT(*) FROM information_schema.COLUMNS AS c
         WHERE c.TABLE_SCHEMA = t.TABLE_SCHEMA AND c.TABLE_NAME = t.TABLE_NAME) AS columns_count,
       (SELECT COUNT(DISTINCT s.INDEX_NAME) FROM information_schema.STATISTICS AS s
         WHERE s.TABLE_SCHEMA = t.TABLE_SCHEMA AND s.TABLE_NAME = t.TABLE_NAME) AS indexes,
       (SELECT COUNT(*) FROM information_schema.REFERENTIAL_CONSTRAINTS AS r
         WHERE r.CONSTRAINT_SCHEMA = t.TABLE_SCHEMA AND r.TABLE_NAME = t.TABLE_NAME) AS foreign_keys
FROM information_schema.TABLES AS t
WHERE t.TABLE_SCHEMA = 'bookstore' AND t.TABLE_TYPE = 'BASE TABLE'
ORDER BY t.TABLE_NAME;

Output

+-----------------+---------------+---------+--------------+
| TABLE_NAME      | columns_count | indexes | foreign_keys |
+-----------------+---------------+---------+--------------+
| authors         |             3 |       1 |            0 |
| book_categories |             2 |       2 |            2 |
| books           |             7 |       2 |            1 |
| categories      |             3 |       2 |            0 |
| customers       |             6 |       2 |            0 |
| employees       |             9 |       3 |            1 |
| order_items     |             5 |       3 |            2 |
| orders          |             3 |       2 |            1 |
+-----------------+---------------+---------+--------------+

A quick portrait of a schema you have never seen: the junction table book_categories is nothing but two columns and two foreign keys, order_items also links two tables, and the lookup tables (authors, categories, customers) point at nothing.

❓ Common Questions at This Stage

Is this course enough to get a job?

It is the database half of many entry-level developer and data roles: designing tables, writing joins and aggregates, using transactions and accounts. Pair it with one programming language and two or three finished projects (your final project is one), and be ready to write queries live, which is what most interviews test.

Should I learn PostgreSQL too?

Eventually, it is worth it: many companies use it. About 90% of what you learned transfers directly (SELECT, joins, GROUP BY, CTEs, window functions, transactions). The differences are in types, functions, auto-increment syntax and administration. Learn it when a project or job calls for it.

Do I still need SQL if I use an ORM or an AI assistant?

Yes. Both produce SQL that you are responsible for. You need to read it, judge whether it is correct and efficient, and fix it when it is not, especially for reports, migrations and anything involving money or permissions.

How do I keep my skills from fading?

Use them on something you care about every week or two, even briefly. Add a feature to your final project, answer a question on a forum, or redo an exercise from memory. Revisit the cheat sheet before a project starts.

🎓 Key Takeaways

  • Good habits are cheap insurance: primary keys, exact types, constraints, ORDER BY, previews before changes, and backups you have restored

  • Application code sends values as parameters, never glued into SQL; PREPARE ... EXECUTE ... USING does the same at the prompt
