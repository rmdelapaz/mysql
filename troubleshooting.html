🔧 Troubleshooting Guide

Step-by-step fixes for the problems learners hit most often in this course: installing MySQL 9.7, starting the server, connecting, phpMyAdmin, puzzling query results, slow queries and garbled text. For a specific error number, see Common MySQL Errors.

💡 First, three questions

Most problems are answered by: Is the server running? (see Service Problems) Which server am I talking to? (SELECT VERSION();: anything other than 9.7.x, such as 8.0, 26.x or a version containing MariaDB, means a different server than the course uses) Who am I, and where? (SELECT CURRENT_USER(), DATABASE();). The SQL examples on this page assume the course database from bookstore.sql.

📥 Installation & Setup Issues

The installation steps for every platform are in Lesson 1.2: Installing MySQL.

🔹 "I installed MySQL, but I got an older version (or MariaDB)"

Symptom: mysql --version or SELECT VERSION(); shows 8.0.x, 8.4.x, 26.x, or a version containing MariaDB.

Why: "latest" is usually not 9.7. brew install mysql and Docker's mysql:latest give the newest innovation release (calendar-numbered, like 26.x); the LTS series is mysql@9.7 / mysql:9.7. Linux distributions package their own version: Ubuntu's mysql-server is 8.0 on 22.04 and 24.04 and 8.4 on 26.04, and Debian's default-mysql-server is MariaDB. XAMPP ships MariaDB (its button still says "MySQL"); MAMP ships an older MySQL. Fix: for MySQL 9.7 on Ubuntu/Debian, add Oracle's MySQL APT repository (Lesson 1.2), or use Docker (mysql:9.7). Everything in this course also works on MySQL 8.4 LTS; on MariaDB almost everything does, and the lessons point out the differences.

mysql --version          # the client
mysql -u root -p -e "SELECT VERSION();"   # the server (can differ from the client!)

🔹 "mysql: command not found" / "'mysql' is not recognized"

Why: the client is installed, but its folder is not on your PATH. Fix: add the server's bin folder to the PATH, then open a new terminal.

Windows (PowerShell)

# Find the folder (the version number in the path depends on what you installed)
Get-ChildItem "C:\Program Files\MySQL" -Directory

# Then: Settings, search "environment variables", Edit the user Path, add for example
#   C:\Program Files\MySQL\MySQL Server 9.7\bin
# and open a NEW PowerShell window
mysql --version

macOS (zsh)

# Homebrew: mysql@9.7 is "keg-only", so its commands are not on the PATH by default
echo 'export PATH="$(brew --prefix)/opt/mysql@9.7/bin:$PATH"' >> ~/.zshrc
# DMG package instead:
echo 'export PATH="/usr/local/mysql/bin:$PATH"' >> ~/.zshrc

source ~/.zshrc
mysql --version

🔹 "E: Unable to locate package mysql-server" (Ubuntu/Debian)

Fix: refresh the package lists first. After adding the MySQL APT repository, the package names stay the same (mysql-server), but the version comes from Oracle's repository.

sudo apt update
sudo apt install mysql-server
apt policy mysql-server        # which version will be (or was) installed, and from where

🔹 Ubuntu never asked for a root password; now I can't log in

Why: Ubuntu's own mysql-server package sets root to log in through the operating system (the auth_socket plugin): sudo mysql works, mysql -u root -p does not. Fix: leave root as it is and create your own administrator account with a password:

sudo mysql
CREATE USER 'ray'@'localhost' IDENTIFIED BY 'Replace-With-Your-Own-Passphrase-1';
GRANT ALL PRIVILEGES ON *.* TO 'ray'@'localhost' WITH GRANT OPTION;
SHOW GRANTS FOR 'ray'@'localhost';

Use your own name and a real passphrase, then log in with mysql -u ray -p. This account is for you, at your own computer; applications get their own least-privilege accounts (Lesson 7.4: User Management & Permissions). If you prefer to give root a password instead, run this inside sudo mysql (it uses the default caching_sha2_password; do not switch to mysql_native_password, which MySQL 9.x no longer has):

ALTER USER 'root'@'localhost' IDENTIFIED WITH caching_sha2_password BY 'Replace-With-Your-Own-Passphrase-2';

🔹 Red Hat, Fedora, Oracle Linux: "what is the root password?"

Why: MySQL's Yum repository packages create a random temporary root password on the first start and write it to the log. Fix: read it, log in, and change it right away (until you do, every other statement fails with error 1820):

sudo grep 'temporary password' /var/log/mysqld.log
mysql -u root -p                # paste the temporary password
ALTER USER 'root'@'localhost' IDENTIFIED BY 'Replace-With-Your-Own-Passphrase-2';

These packages also install the password-strength component, so a weak password fails with ERROR 1819.

🔹 Port 3306 is already in use

Symptom: the server will not start, or Docker says Bind for 0.0.0.0:3306 failed: port is already allocated. Why: another MySQL or MariaDB (often XAMPP's, or a second installation, or a container you forgot) is listening. Fix: find it and stop it, or run the new server on another port (Docker: -p 3307:3306, then connect with -P 3307).

macOS / Linux / WSL

sudo lsof -i :3306
docker ps                       # a container already publishing 3306?

Windows (PowerShell)

Get-NetTCPConnection -LocalPort 3306 | Select-Object LocalAddress, OwningProcess
Get-Process -Id <OwningProcess>

🔹 Docker: the container stops right after it starts

Fix: read its log. The most common message says the database is uninitialized and no password option was given: the first start of an empty data volume needs MYSQL_ROOT_PASSWORD (or MYSQL_RANDOM_ROOT_PASSWORD=yes).

docker ps -a                    # is it "Exited"?
docker logs mysql97             # use your container's name
docker rm mysql97
docker run --name mysql97 -e MYSQL_ROOT_PASSWORD='Replace-With-A-Passphrase' \
    -p 3306:3306 -v mysql97-data:/var/lib/mysql -d mysql:9.7

⚠️ Changing MYSQL_ROOT_PASSWORD later does nothing

The variable is read only when the data volume is empty. With an existing volume, the old password stays; change it with ALTER USER instead.

⚙️ MySQL Service Problems

🔹 Is the server running? Start, stop, restart

Linux (systemd, including WSL with systemd)

sudo systemctl status mysql     # the service is "mysqld" on Red Hat-family systems
sudo systemctl start mysql
sudo systemctl restart mysql
sudo systemctl enable mysql     # start automatically at boot

macOS

brew services list              # Homebrew installs
brew services start mysql@9.7
# DMG installs: System Settings, MySQL (bottom of the list), Start MySQL Server

Windows (PowerShell as Administrator)

Get-Service *mysql*             # shows the service name and status
Start-Service -Name MySQL97     # use the name Get-Service printed

Docker

docker ps -a
docker start mysql97

🔹 The server will not start, or stops by itself

Fix: the error log almost always names the reason. Look at its last lines.

# Linux packages
sudo tail -50 /var/log/mysql/error.log      # Debian/Ubuntu
sudo tail -50 /var/log/mysqld.log           # Red Hat family
sudo journalctl -u mysql -n 50

# Homebrew
tail -50 "$(brew --prefix)"/var/mysql/*.err

# Docker
docker logs --tail 50 mysql97

# Windows: the .err file in the data folder, typically
#   C:\ProgramData\MySQL\MySQL Server 9.7\Data\<computer-name>.err

Common causes in the log: port 3306 in use (see above), a typo in a configuration file you edited (unknown variable), a full disk (df -h), wrong ownership of the data directory (Linux: sudo chown -R mysql:mysql /var/lib/mysql), or not enough memory (on Linux: sudo dmesg | grep -i -E 'killed process|out of memory').

🔌 Connection Issues

🔹 "Access denied" with the right password

Possible causes (ERROR 1045):

  • The account exists for a different host: 'app'@'%' and 'app'@'localhost' are separate accounts with separate passwords.
  • Root uses auth_socket (Ubuntu's package): use sudo mysql, then see the Ubuntu root fix.
  • The shell changed your password: characters like !, $ or & on the command line. Use -p alone and type the password at the prompt.
  • You are talking to a different server than you think (a Docker container and a local installation both on port 3306).

As an administrator, see which accounts exist, which host each allows, and which plugin it uses:

SELECT user, host, plugin, account_locked FROM mysql.user ORDER BY user, host;

🔹 "Can't connect to local MySQL server through socket"

This is ERROR 2002: on Linux and macOS, localhost uses a socket file, and it is missing because the server is not running. Fix: start the server (above). If it is running and the error persists, the client and server disagree about the socket path; connect over TCP instead:

mysql -h 127.0.0.1 -P 3306 -u root -p
mysqladmin -u root -p variables | grep socket     # where the server put its socket

🔹 Old tool: "Authentication plugin 'caching_sha2_password' cannot be loaded"

Why: a client or library from the MySQL 5.7 era (or PHP before 7.4) does not know the default authentication plugin. Fix: upgrade the client, connector or PHP. Do not switch the account to mysql_native_password: MySQL 9.x removed it (ERROR 1524).

🔹 Connecting from another computer

By default the server may listen only on 127.0.0.1, and accounts are usually @'localhost'. Three things must line up:

  1. Listen: set bind-address in the server configuration (Ubuntu: /etc/mysql/mysql.conf.d/mysqld.cnf) to the server's address, or 0.0.0.0 for all, then restart.
  2. An account for that host: as narrow as possible, with only the privileges needed (example below).
  3. Firewall: allow port 3306 only from where you need it (Ubuntu: sudo ufw allow from 192.168.1.0/24 to any port 3306).
CREATE USER 'report_user'@'192.168.1.%' IDENTIFIED BY 'Replace-With-A-Long-Passphrase-3';
GRANT SELECT ON bookstore.* TO 'report_user'@'192.168.1.%';
SHOW GRANTS FOR 'report_user'@'192.168.1.%';

🛑 Never open root to the network

Do not create 'root'@'%' or grant ALL PRIVILEGES to a remote account. Remote access is for specific accounts with specific privileges; for administration, connect over SSH and use the server locally.

🌐 phpMyAdmin Issues

phpMyAdmin is introduced in Lesson 1.3: MySQL CLI & phpMyAdmin. It is a PHP web application, so it needs a web server with PHP in front of your MySQL server (XAMPP and MAMP bundle that, with their own database server; with your own MySQL, Docker's phpmyadmin image is the easiest route, see Lesson 1.2: Installing MySQL).

🔹 http://localhost/phpmyadmin shows "Not Found"

Fix (Ubuntu with Apache): the package installs a configuration snippet that must be enabled.

dpkg -l | grep phpmyadmin                     # installed at all?
sudo apt install phpmyadmin                   # pick "apache2" when asked
sudo ln -s /etc/phpmyadmin/apache.conf /etc/apache2/conf-available/phpmyadmin.conf
sudo a2enconf phpmyadmin
sudo systemctl reload apache2

🔹 The login page rejects root

Why: on Ubuntu's package, root has no password (it uses auth_socket), and a web application cannot log in that way. Fix: log in to phpMyAdmin with your own administrator account (created above), not root.

If phpMyAdmin instead says The server requested authentication method unknown to the client [caching_sha2_password], its PHP is older than 7.4: upgrade PHP (and phpMyAdmin), not the account's plugin.

🔹 Import fails: "file exceeds the maximum upload size"

Fix: raise PHP's limits, or skip the browser for big files and use the client: mysql -u root -p bookstore < big_file.sql.

php --ini | grep "Loaded Configuration"        # which php.ini? (Apache may use a different one)
# In that php.ini set, for example:
#   upload_max_filesize = 64M
#   post_max_size = 64M
#   max_execution_time = 300
sudo systemctl restart apache2

🔍 Query Problems

🔹 A script works at the prompt but fails from a file: "Unknown command '\G'"

Why: since MySQL 9, the mysql client ignores its own backslash commands such as \G, and SOURCE, in batch mode (DELIMITER still works), that is when you redirect a file into it (mysql ... < file.sql) or use -e. \G then stops the script with ERROR at line 1: Unknown command '\G'., and a SOURCE line reaches the server as a syntax error (1064). Fix: end statements in script files with ;, or allow client commands explicitly (Lesson 1.3):

mysql --commands -u root -p bookstore < report.sql

Likewise \! (run a shell command) is off by default in MySQL 9.x; start the client with --system-command if you need it.

🔹 The query returns nothing (but it should)

Check: the right database (SELECT DATABASE();), the table has rows (SELECT COUNT(*) FROM customers;), the WHERE is not too strict, and above all: NULL. Nothing is ever equal to NULL, not even NULL, so = NULL matches no rows and raises no error:

SELECT first_name, last_name FROM customers WHERE city = NULL;

Output

Empty set
SELECT first_name, last_name FROM customers WHERE city IS NULL;

Output

+------------+-----------+
| first_name | last_name |
+------------+-----------+
| Eve        | Davis     |
| Hank       | Taylor    |
+------------+-----------+

The same trap hides in NOT IN: if the list (or subquery) contains a NULL, NOT IN returns no rows. Use NOT EXISTS or filter the NULLs out.

🔹 A JOIN returns duplicate rows

Why: you joined to the "many" side of a relationship: 1984 is in three categories, so it appears three times. That is correct SQL; the question is what you wanted. DISTINCT hides the symptom; better, decide whether you need the extra table at all, or collapse it on purpose:

SELECT b.title, a.name
FROM books b
JOIN authors a ON a.id = b.author_id
JOIN book_categories bc ON bc.book_id = b.id
WHERE a.name = 'George Orwell'
ORDER BY b.title;

Output

+-------------+---------------+
| title       | name          |
+-------------+---------------+
| 1984        | George Orwell |
| 1984        | George Orwell |
| 1984        | George Orwell |
| Animal Farm | George Orwell |
| Animal Farm | George Orwell |
+-------------+---------------+
SELECT b.title, a.name, GROUP_CONCAT(c.name ORDER BY c.name SEPARATOR ', ') AS categories
FROM books b
JOIN authors a ON a.id = b.author_id
JOIN book_categories bc ON bc.book_id = b.id
JOIN categories c ON c.id = bc.category_id
WHERE a.name = 'George Orwell'
GROUP BY b.id, b.title, a.name
ORDER BY b.title;

Output

+-------------+---------------+-----------------------------+
| title       | name          | categories                  |
+-------------+---------------+-----------------------------+
| 1984        | George Orwell | Classic, Dystopian, Fiction |
| Animal Farm | George Orwell | Classic, Fiction            |
+-------------+---------------+-----------------------------+

🔹 The rows come back in a different order than in the lesson

Why: without ORDER BY, SQL promises no order at all, and since MySQL 8.0 GROUP BY no longer sorts its groups either (MariaDB still does). Fix: whenever order matters, say so: ORDER BY, with a tiebreaker such as id when values repeat.

🔹 "dune" matches "Dune": comparisons ignore case

Why: the course database uses a case-insensitive collation (_ci), so = and LIKE ignore case. Usually that is what you want. For an exact, case-sensitive match, compare with a binary collation (the older BINARY 'dune' form is deprecated):

SELECT title FROM books WHERE title = 'dune';
SELECT title FROM books WHERE title = 'dune' COLLATE utf8mb4_bin;

Output

+-------+
| title |
+-------+
| Dune  |
+-------+
Empty set

🔹 "Rows matched: 1 Changed: 0"

Why: the WHERE found the row, but it already had that value, so nothing changed. Not an error; it often means an earlier statement already did the work, or the SET is not what you meant.

UPDATE books SET price = 14.99 WHERE id = 1;   -- Dune already costs 14.99

Output

Query OK, 0 rows affected
Rows matched: 1  Changed: 0  Warnings: 0

🔹 Money adds up to 0.30000000000000004

Why: FLOAT and DOUBLE are binary approximations. DECIMAL (and plain literals like 0.1) are exact. Fix: store money as DECIMAL(8, 2), as the course tables do.

SELECT 0.1e0 + 0.2e0 AS double_math, 0.1 + 0.2 AS decimal_math;

Output

+---------------------+--------------+
| double_math         | decimal_math |
+---------------------+--------------+
| 0.30000000000000004 |          0.3 |
+---------------------+--------------+

🔹 A query hangs

Why: usually it is waiting for a lock held by an open transaction in another window (it gives up after 50 seconds with ERROR 1205), or it is genuinely slow. Fix: press Ctrl+C to cancel it, then look at what is running, from another session:

SELECT id, user, db, command, time, state, info
FROM performance_schema.processlist
WHERE command <> 'Daemon';

(SHOW PROCESSLIST; shows the same list, but on MySQL 9.7 it adds a deprecation warning pointing to this table.)

Find the stuck statement's Id and stop it (12345 is a placeholder: use the real Id). KILL QUERY cancels the statement; KILL closes the whole connection and rolls back its open transaction:

KILL QUERY 12345;

⚡ Performance Issues

Background: Lesson 6.1: Indexes & Query Optimization.

🔹 Quick checklist

  1. EXPLAIN the query: type: ALL means a full table scan; the key column shows which index is used.
  2. Index the columns you filter, join and sort on. InnoDB indexes foreign key columns automatically.
  3. Keep columns bare in WHERE: WHERE YEAR(published) = 1949 cannot use an index on published; WHERE published >= '1949-01-01' AND published < '1950-01-01' can.
  4. Ask for less: only the columns you need (no SELECT * in applications), and LIMIT lists.
  5. Measure: EXPLAIN ANALYZE runs the query and reports real times (MySQL only).
CREATE INDEX idx_books_published ON books (published);

EXPLAIN SELECT title FROM books WHERE YEAR(published) = 1949;
EXPLAIN SELECT title FROM books WHERE published >= '1949-01-01' AND published < '1950-01-01';

DROP INDEX idx_books_published ON books;

On a table this small, MySQL may still choose a full scan; the difference shows on thousands of rows.

🔹 Find slow queries with the slow query log

As an administrator, switch it on, reproduce the slowness, read the file, and switch it off again (SET GLOBAL lasts until the server restarts):

SHOW VARIABLES LIKE 'slow_query_log%';
SET GLOBAL long_query_time = 1;        -- log statements slower than 1 second
SET GLOBAL slow_query_log = ON;
sudo tail -50 /var/lib/mysql/$(hostname)-slow.log     # the file named by slow_query_log_file
mysqldumpslow -s t /var/lib/mysql/$(hostname)-slow.log  # summary, slowest first
SET GLOBAL slow_query_log = OFF;
SET GLOBAL long_query_time = DEFAULT;

🔤 Character Encoding Issues

🔹 Garbled characters (é shows as Ã©) or emoji become ????

Why: somewhere between your keyboard and the table, one link is not utf8mb4: the connection, the table or column, or the terminal. Plain utf8 in MySQL is the old 3-byte utf8mb3, which cannot store emoji, and is deprecated. Fix: check each link.

-- The connection
SHOW VARIABLES LIKE 'character_set_c%';
SET NAMES utf8mb4;

-- The database
SELECT default_character_set_name, default_collation_name
FROM information_schema.schemata
WHERE schema_name = 'bookstore';

-- Any text columns that are NOT utf8mb4?
SELECT table_name, column_name, character_set_name
FROM information_schema.columns
WHERE table_schema = 'bookstore'
  AND character_set_name IS NOT NULL
  AND character_set_name <> 'utf8mb4';

To convert a table that is not utf8mb4 (this rewrites the table; back up first):

ALTER TABLE customers CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

For the client, start it with mysql --default-character-set=utf8mb4 -u root -p. In the Windows console, also switch it to UTF-8 with chcp 65001 (Windows Terminal handles this better than the old console).

🐧 WSL-Specific Issues

🔹 MySQL does not start automatically in WSL

Why: current Ubuntu images for WSL run systemd, so sudo systemctl enable mysql works. Older setups have no systemd: systemctl answers "System has not been booted with systemd". Fix: enable systemd, or start the service by hand each session.

# Option 1: enable systemd (then run "wsl --shutdown" in PowerShell and reopen Ubuntu)
printf '[boot]\nsystemd=true\n' | sudo tee /etc/wsl.conf

# Option 2: start it yourself
sudo service mysql start

🔹 Windows programs can't reach MySQL (or phpMyAdmin) in WSL

Fix: WSL 2 normally forwards localhost to Windows. If it does not, use the WSL address, or restart WSL. Also make sure a MySQL installed on Windows itself is not holding port 3306 at the same time.

hostname -I            # the WSL address; try http://THAT-ADDRESS/phpmyadmin
# In PowerShell:  wsl --shutdown   then reopen the Ubuntu terminal

🔑 Resetting the Root Password

If you lost root's password (and have no other administrator account), restart the server once with the privilege checks switched off, set a new password, and restart normally. The server must be yours: on a shared or hosted server, ask its administrator.

🛑 While the checks are off, anyone can log in

--skip-grant-tables lets every connection in as any user. MySQL automatically disables network connections in this mode (--skip-networking), but finish quickly and restart normally right after.

Linux (and WSL)

sudo systemctl stop mysql
sudo mkdir -p /var/run/mysqld && sudo chown mysql:mysql /var/run/mysqld
sudo mysqld --user=mysql --skip-grant-tables --skip-networking &
mysql -u root                  # no password needed right now

Inside the client: load the privilege tables first (in this mode they are not loaded, so ALTER USER would fail), then set the password. FLUSH PRIVILEGES is deprecated in MySQL 9.x and prints a warning; this special mode is the one place you still need it:

FLUSH PRIVILEGES;
ALTER USER 'root'@'localhost' IDENTIFIED BY 'Replace-With-Your-New-Passphrase';
EXIT
sudo mysqladmin -u root -p shutdown     # stop the temporary server (use the NEW password)
sudo systemctl start mysql
mysql -u root -p                        # test it

Windows

  1. Create a text file, for example C:\mysql-init.txt, holding the one line ALTER USER 'root'@'localhost' IDENTIFIED BY 'Replace-With-Your-New-Passphrase';
  2. Stop the MySQL service (Stop-Service -Name MySQL97, with your service's name).
  3. In an Administrator PowerShell, start the server once with that file (adjust the version in the paths):
cd "C:\Program Files\MySQL\MySQL Server 9.7\bin"
.\mysqld.exe --defaults-file="C:\ProgramData\MySQL\MySQL Server 9.7\my.ini" --init-file=C:\mysql-init.txt --console
  1. When the console says the server is ready for connections, press Ctrl+C, start the service normally, and log in with the new password.
  2. Delete C:\mysql-init.txt: it contains the password.

Docker

If you still know the password of any administrator account, use docker exec -it mysql97 mysql -u that_admin -p and ALTER USER. Otherwise, the simplest route for a practice container is a fresh one: export what you need first, then remove the container and its volume and start again (below).

💣 Last Resort: Reinstall MySQL

🛑 This deletes every database on the server

Back up anything you want to keep first (Lesson 8.1: Importing & Exporting Data): mysqldump -u root -p --all-databases --routines --events > everything.sql. The course database itself can always be rebuilt from bookstore.sql.

Ubuntu/Debian

sudo systemctl stop mysql
sudo apt purge 'mysql-server*' 'mysql-client*' 'mysql-community-*' mysql-common
sudo apt autoremove
sudo rm -rf /var/lib/mysql /etc/mysql /var/log/mysql
sudo apt update && sudo apt install mysql-server

macOS (Homebrew)

brew services stop mysql@9.7
brew uninstall mysql@9.7
rm -rf "$(brew --prefix)/var/mysql"
brew install mysql@9.7 && brew services start mysql@9.7

Docker

docker rm -f mysql97
docker volume rm mysql97-data
docker run --name mysql97 -e MYSQL_ROOT_PASSWORD='Replace-With-A-Passphrase' \
    -p 3306:3306 -v mysql97-data:/var/lib/mysql -d mysql:9.7

Windows

Uninstall "MySQL Server" in Settings, Apps; delete the data folder C:\ProgramData\MySQL (hidden; type the path into File Explorer); then run the installer again (Lesson 1.2).
