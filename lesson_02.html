🔧 Lesson 1.2: Installing MySQL

Time to get a real MySQL server running on your own machine. This lesson walks you through MySQL 9.7 LTS on Windows, macOS and Linux, or in a Docker container on any of them, then has you secure the root account, connect with the mysql client and prove that everything works.

🎯 Learning Objectives

By the end of this lesson, you will be able to:

  • Choose the right MySQL release (9.7 LTS) and installation method for your computer, and recognize when a package gives you something else (an older MySQL, or MariaDB)
  • Install MySQL 9.7 LTS with the Windows MSI, the macOS package or Homebrew, the MySQL APT repository, or the official Docker image
  • Start and stop the server, and set a strong root password
  • Connect with mysql -u root -p and verify the version, user and character set with SQL
  • Diagnose the four classic first-day errors: command not found, 1045, 2002 and 2003
  • ⏱️ Time 90 minutes
  • 📋 Prerequisites Lesson 1.1: What Is a Database?, administrator rights on your computer (or Docker Desktop), about 1.5 GB of free disk space
  • 🛠️ You will build A working MySQL 9.7 server and an installation health check you can rerun any time
  • 🗄️ Database None yet: a fresh server holds only its system databases

🧩 What You Are Installing

"Installing MySQL" really means installing two programs:

  • The server (mysqld, the "d" is for daemon): a program that runs in the background, owns the data files and listens for connections, by default on network port 3306.
  • A client: a program you use to send SQL to the server and see the answers. The standard one is the command-line client mysql, which every installation method below includes. Graphical clients (phpMyAdmin, MySQL Workbench, DBeaver) are optional extras.
graph TD A["You type SQL"] --> B["mysql client"] B -->|"connects on port 3306"| C["MySQL server (mysqld)"] C --> D["data directory on disk"]

The client and server can sit on different machines; on your laptop they are on the same one. You do not need Apache or PHP for this course: they are only required if you want phpMyAdmin, and even that can run in Docker (see the optional GUI section).

🧭 Choose a Version and a Path

Which version?

MySQL ships on two tracks:

  • LTS (long-term support) releases keep the same features for years and get only bug and security fixes. The current one is MySQL 9.7 LTS, and it is what this course uses. The previous one, 8.4 LTS, is still supported and runs almost everything here.
  • Innovation releases come out every few months with new features. After 9.7, MySQL switched to calendar version numbers (year.month), so innovation releases are numbered like 26.7. They are fine to experiment with, but "latest" on a download page or a package manager often means an innovation release, not 9.7.

MySQL 8.0, which many older tutorials show, has reached the end of its support life. If a package offers you 8.0, look for a newer path.

⚠️ One server per port

If you already have MySQL, MariaDB, XAMPP or MAMP installed and running, a second server cannot also listen on port 3306. Stop the old one first, or give the new one another port (the Docker section shows how).

🪟 Windows: MSI Installer

On Windows, MySQL 9.7 is installed with an MSI package, then configured with MySQL Configurator, a setup wizard that the MSI installs and launches for you. (The older all-in-one "MySQL Installer" belongs to the 8.0 era; you do not need it.)

Step 1: Download

  1. Go to dev.mysql.com/downloads/mysql (MySQL Community Server).
  2. In the version list, choose 9.7.x LTS (not the newest innovation release) and the operating system Microsoft Windows.
  3. Download the Windows (x86, 64-bit), MSI Installer. You can skip the Oracle account sign-up with the "No thanks, just start my download" link.

MySQL 9.7 needs 64-bit Windows and the Microsoft Visual C++ Redistributable; if the installer complains about it, install the current "Visual C++ Redistributable for Visual Studio" (x64) from Microsoft and run the MSI again.

Step 2: Install

Double-click the .msi, accept the license, choose the Typical setup and confirm the administrator prompt. The files go to C:\Program Files\MySQL\MySQL Server 9.7\. At the end, leave the option to run MySQL Configurator checked. The server does not start until it has been configured.

Step 3: Configure with MySQL Configurator

The Configurator walks through a series of pages. For a learning machine:

PageChoose
Type and NetworkingConfig type Development (uses the least memory); TCP/IP on port 3306; X Protocol port 33060 can stay as is
Accounts and RolesType a strong root password twice and store it in your password manager. No extra accounts needed now
Windows ServiceKeep "Configure MySQL Server as a Windows Service" and "Start the MySQL Server at System Startup" checked; note the service name it suggests (something like MySQL97)
Server File PermissionsKeep the default (only the service account and Administrators can read the data folder)
Sample DatabasesOptional. The course builds its own bookstore database, so you can skip sakila and world
Apply ConfigurationClick Execute and wait until every step shows a green check, then Finish

Step 4: Put the client on your PATH

The MSI does not add mysql.exe to your PATH, so typing mysql in a terminal fails until you do. Open Start, search for Edit the system environment variables, click Environment Variables..., select Path under your user variables, click Edit, then New, and add:

C:\Program Files\MySQL\MySQL Server 9.7\bin

Click OK three times and open a new PowerShell window (old windows keep the old PATH). Check:

mysql --version

Output (your exact version can differ)

C:\Program Files\MySQL\MySQL Server 9.7\bin\mysql.exe  Ver 9.7.2 for Win64 on x86_64 (MySQL Community Server - GPL)

Starting and stopping on Windows

The service starts with Windows. To control it, open the Services app and find the MySQL service, or use an administrator PowerShell (use the service name you noted in step 3):

Get-Service MySQL*      # is it Running?
Stop-Service MySQL97
Start-Service MySQL97

💡 Prefer Linux tools? Use WSL

If you develop inside WSL (Windows Subsystem for Linux), install MySQL inside your Ubuntu distribution with the Linux steps instead. Pick one: a Windows MySQL and a WSL MySQL both want port 3306.

Done? Skip to Securing the Root Account.

🍎 macOS: Package or Homebrew

Two good options. Homebrew is easiest to update and remove if you already use it; the DMG package is a classic point-and-click installer.

Option A: Homebrew

If you do not have Homebrew yet, install it with the one-line command on its home page and follow the instructions it prints at the end. Then ask for the 9.7 series by name:

brew install mysql@9.7

⚠️ brew install mysql is not 9.7

The plain mysql formula follows the newest innovation release. The versioned formula mysql@9.7 stays on the LTS series. Run brew info mysql@9.7 to see exactly which version it installs.

Versioned formulae are "keg-only": Homebrew does not put their commands on your PATH. Add the folder to your shell profile, then open a new Terminal window:

echo 'export PATH="$(brew --prefix)/opt/mysql@9.7/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
mysql --version

Start the server now and at every login, and check its status:

brew services start mysql@9.7
brew services list

The list shows mysql@9.7 with the status started. Homebrew creates the root account without a password, accepting connections from your Mac only. You will fix that in Securing the Root Account with mysql_secure_installation. To stop the server: brew services stop mysql@9.7.

Option B: The DMG package

  1. On dev.mysql.com/downloads/mysql, select 9.7.x LTS and macOS, then the DMG Archive for your processor: ARM, 64-bit for Apple silicon (M-series), x86, 64-bit for Intel Macs (Apple menu, About This Mac, tells you which).
  2. Open the DMG and run the .pkg installer. Near the end it asks you to set the root password; choose a strong one and store it.
  3. The installer registers MySQL to start automatically and adds a MySQL pane to System Settings, where you can start and stop the server.
  4. The programs live in /usr/local/mysql/bin, which is not on your PATH. Add it, then open a new Terminal window:
echo 'export PATH="/usr/local/mysql/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
mysql --version

Done? Continue with Securing the Root Account.

🐧 Linux: APT and Yum Repositories

Your distribution's own package is usually not MySQL 9.7:

Distribution packageWhat you get
mysql-server on Ubuntu 22.04 and 24.04MySQL 8.0 (past its end of life)
mysql-server on Ubuntu 26.04MySQL 8.4 LTS
default-mysql-server on DebianMariaDB, not MySQL
MySQL's own APT or Yum repositoryThe series you pick: 9.7 LTS

Run apt policy mysql-server to see which version your system would install. For this course, add MySQL's repository.

Ubuntu and Debian: the MySQL APT repository

  1. Download the repository setup package (mysql-apt-config_..._all.deb) from dev.mysql.com/downloads/repo/apt.
  2. Install it. A text menu opens: under the server entry, choose the 9.7 LTS series, then select Ok.
sudo dpkg -i ~/Downloads/mysql-apt-config_*_all.deb
  1. Refresh the package lists and install the server (the client comes with it):
sudo apt update
sudo apt install mysql-server
  1. During the install you are asked for a root password. Set a strong one. (If you leave it empty, root can only log in through sudo mysql; see the next section.)
  2. The server starts automatically and at every boot. Check it, and learn the controls:
systemctl status mysql          # look for "active (running)"
sudo systemctl stop mysql
sudo systemctl start mysql

To change series later, run sudo dpkg-reconfigure mysql-apt-config, then sudo apt update.

Fedora, RHEL, Rocky and AlmaLinux: the MySQL Yum repository

Download the repository package for your release from dev.mysql.com/downloads/repo/yum, install it with sudo dnf install ./mysql*-community-release-*.rpm, make sure the 9.7 LTS series is the enabled one (the repository's documentation lists the repo names), then:

sudo dnf install mysql-community-server
sudo systemctl enable --now mysqld
sudo grep 'temporary password' /var/log/mysqld.log

On these systems the service is called mysqld, and the first start creates a random temporary root password in the log file. Log in with it and change it right away (next section).

💡 WSL notes

In WSL, follow the Ubuntu steps inside your Linux terminal. Current WSL versions run systemd, so systemctl works; on an older setup without systemd, use sudo service mysql start instead.

🐳 Docker: Any Operating System

If you have Docker Desktop (Windows, macOS) or Docker Engine (Linux), the official image is the quickest clean install, and removing it later leaves nothing behind. Every command in this section was run as written.

Start a MySQL 9.7 container

docker run --name mysql97 \
  -e MYSQL_ROOT_PASSWORD='choose-a-strong-password' \
  -p 3306:3306 \
  -v mysql97-data:/var/lib/mysql \
  -d mysql:9.7

On Windows PowerShell, write it on one line (or end each line with a backtick ` instead of \). What each part does:

PartMeaning
--name mysql97A name to refer to the container by
-e MYSQL_ROOT_PASSWORD=...The root password, set on the very first start only. Required: without it (or one of the alternatives) the container stops with "Database is uninitialized and password option is not specified"
-p 3306:3306Publish the container's port 3306 on your computer's port 3306. Use -p 3307:3306 if 3306 is taken
-v mysql97-data:/var/lib/mysqlKeep the data in a named volume, so it survives stopping, removing and re-creating the container
-d mysql:9.7Run in the background, from the official image, 9.7 series (the tag mysql:lts currently points to the same image; mysql:latest is the newest innovation release)

The first start takes 10 to 30 seconds while MySQL creates its system tables. Watch the log until the last line says the server is ready:

docker logs mysql97

Output (last line; timestamps differ)

... [System] [MY-010931] [Server] /usr/sbin/mysqld: ready for connections. Version: '9.7.2'  socket: '/var/run/mysqld/mysqld.sock'  port: 3306  MySQL Community Server - GPL.

The log shows "ready for connections" twice: the first time is a temporary server used for setup (it says port: 0). Wait for the one with port: 3306.

Connect

The image contains the mysql client, so you do not need to install anything else. Open it inside the container:

docker exec -it mysql97 mysql -u root -p

If you also have a mysql client installed on your computer, connect through the published port. Use the address 127.0.0.1, not localhost: on macOS and Linux, the client treats localhost as "use the local socket file" and ignores the port, which fails with error 2002.

mysql -h 127.0.0.1 -P 3306 -u root -p

Stop, start, remove

docker stop mysql97        # stop the server; data is kept
docker start mysql97       # start it again, same data and password
docker rm -f mysql97       # delete the container; the mysql97-data volume (your data) stays
docker volume rm mysql97-data   # only when you really want to erase every database

💡 Docker Desktop starts on demand

Containers only run while Docker Desktop is running. After a reboot, open Docker Desktop and run docker start mysql97 (or click its start button in the Containers list). Add --restart unless-stopped to the docker run command if you want it to come back by itself.

📦 XAMPP, MAMP and MariaDB

Bundles such as XAMPP install Apache, PHP, phpMyAdmin and a database in one go, and many classrooms use them. Know what you are getting:

  • XAMPP ships MariaDB, not MySQL, even though its control panel labels the button "MySQL".
  • MAMP ships MySQL, usually an older series than 9.7.
  • Many shared web hosts and Linux distributions also hand you MariaDB under the name "MySQL".

The basic SQL of this course works on all of them, but you will see differences: some newer MySQL features fail, a few error messages read differently, and grouped results come back sorted. The quickest way to find out what you are talking to is to ask the server. Here is the same statement on MariaDB:

SELECT VERSION();

Output on MariaDB (your version number will differ)

+------------------------+
| VERSION()              |
+------------------------+
| 12.3.3-MariaDB-ubu2404 |
+------------------------+

The word MariaDB in the version is the giveaway. If you must use XAMPP, you can follow the course; read the 🐬 version notes when your output disagrees. For the smoothest ride, install MySQL 9.7 itself.

🔐 Securing the Root Account

root is MySQL's all-powerful administrator account. It should always have a strong password, and it is for administration only: from Lesson 7.4 on, applications get their own accounts with just the permissions they need.

mysql_secure_installation comes with every server package. Run it in a terminal (with sudo on Linux):

Setting the root password by hand

For the Yum temporary password, or Ubuntu's own package where root logs in with sudo mysql, open the client as described in the table and run one statement. Replace the placeholder with your own password, and keep the quotes:

ALTER USER 'root'@'localhost'
    IDENTIFIED WITH caching_sha2_password BY 'your-strong-password-here';

caching_sha2_password is MySQL's default and secure login method. From then on, log in with mysql -u root -p (no sudo).

🛑 Never "fix" logins with mysql_native_password

Old tutorials and answers tell you to switch root to mysql_native_password so that phpMyAdmin or an old library can connect. That plugin is removed in MySQL 9.x (and disabled by default in 8.4), so the advice fails with error 1524, and it was the weaker method anyway. Current clients, phpMyAdmin 5.2 and PHP's mysqli/PDO all support caching_sha2_password. Update the client instead of weakening the server.

✅ Connect and Verify

Open a terminal and log in (Docker: docker exec -it mysql97 mysql -u root -p):

mysql -u root -p

-u root is the user name, -p means "ask me for the password". Type it at the Enter password: prompt (nothing appears while you type, that is normal) and you see a welcome message and the mysql> prompt. Everything you type there goes to the server. End each statement with a semicolon. Try these three:

SELECT VERSION();

Output (your exact version can differ)

+-----------+
| VERSION() |
+-----------+
| 9.7.2     |
+-----------+

Any 9.7.x is right. If you see 8.0, 8.4, 26.x or a version containing "MariaDB", you are talking to a different server than you meant to (see Common Mistakes).

SHOW DATABASES;

Output

+--------------------+
| Database           |
+--------------------+
| information_schema |
| mysql              |
| performance_schema |
| sys                |
+--------------------+

A fresh server holds four system databases. MySQL keeps its accounts, settings and statistics in them; you will look inside in the next lesson, but never store your own tables there. If you installed sample databases or ran another course before, you see those too.

SELECT CURRENT_USER();

Output

+----------------+
| CURRENT_USER() |
+----------------+
| root@localhost |
+----------------+

You are root, connected from this computer (localhost). Through Docker's published port with -h 127.0.0.1 you would see root@% instead, the container's "root from any host" account. To leave the client, type exit (or press Ctrl+D on macOS and Linux).

🖥️ Optional: phpMyAdmin and Other GUIs

Lesson 1.3 tours phpMyAdmin, a browser-based tool written in PHP. You do not need it to finish the course; the command-line client does everything. If you want it, the least fiddly route is a second container next to your MySQL container:

docker network create mysql-net
docker network connect mysql-net mysql97
docker run --name phpmyadmin --network mysql-net \
  -e PMA_HOST=mysql97 -p 8080:80 -d phpmyadmin:5.2

Then open http://localhost:8080 and log in as root with your password. (Tested: phpMyAdmin 5.2 logs in to MySQL 9.7 with its default caching_sha2_password accounts.) Without Docker:

  • Ubuntu/Debian: sudo apt install phpmyadmin pulls in Apache and PHP; choose apache2 when asked, then browse to http://localhost/phpmyadmin.
  • XAMPP: phpMyAdmin is built in, at http://localhost/phpmyadmin, but it talks to XAMPP's MariaDB, not to the MySQL 9.7 you just installed.
  • Desktop tools: MySQL Workbench (Oracle's free GUI) and DBeaver (free, works with many databases) are installed like any app and connect with host 127.0.0.1, port 3306, user root.

⚠️ Common Mistakes

Most first-day problems are connection problems. The error number tells you which one you have.

1. "mysql: command not found" or "not recognized"

mysql -u root -p

Error (macOS zsh; Windows says "The term 'mysql' is not recognized...")

zsh: command not found: mysql

What it means: the server may be fine; your shell just cannot find the client program. Fix: add the bin folder to your PATH (Windows step 4, the macOS export PATH line), then open a new terminal. With Docker, use docker exec -it mysql97 mysql -u root -p.

2. ERROR 1045: Access denied

mysql -h 127.0.0.1 -P 3306 -u root -p

Error (the host part differs by setup)

ERROR 1045 (28000): Access denied for user 'root'@'172.17.0.1' (using password: YES)

What it means: the server is running and answered, but the user name and password did not match an account (here: a Docker container, reached through its port, with a mistyped password). using password: NO means you forgot -p. Fix: retype the password carefully (it is case-sensitive). On Ubuntu's own package, root may only work through sudo mysql until you set a password. For Docker, remember that MYSQL_ROOT_PASSWORD only counts on the very first start: changing it later in docker run does nothing while the old volume still exists.

3. ERROR 2002 or 2003: Can't connect

mysql -u root -p
mysql -h 127.0.0.1 -P 3306 -u root -p

Error (paths and ports differ)

ERROR 2002 (HY000): Can't connect to local MySQL server through socket '/tmp/mysql.sock' (2)
ERROR 2003 (HY000): Can't connect to MySQL server on '127.0.0.1:3306' (111)

What it means: nothing answered. 2002 is the local socket file (macOS and Linux), 2003 a network address and port. Usually the server is stopped; sometimes it listens elsewhere (Docker published on 3307, or a container only reachable through 127.0.0.1, not localhost). Fix: start the server (Start-Service, brew services start mysql@9.7, sudo systemctl start mysql, docker start mysql97) and check the host and port you are using.

4. Following old advice: mysql_native_password

A tutorial says "if your app can't log in, create its user with mysql_native_password". On 9.7:

CREATE USER 'legacy_app'@'localhost'
    IDENTIFIED WITH mysql_native_password BY 'placeholder-password';

Error

ERROR 1524 (HY000): Plugin 'mysql_native_password' is not loaded

What it means: that login method no longer exists in MySQL 9.x. MySQL 8.4 still has the code but disables it by default, so it fails there the same way:

CREATE USER 'legacy_app'@'localhost'
    IDENTIFIED WITH mysql_native_password BY 'placeholder-password';

Error on MySQL 8.4

ERROR 1524 (HY000): Plugin 'mysql_native_password' is not loaded

Fix: leave out the IDENTIFIED WITH part (you get caching_sha2_password) and update the client library. The same goes for the old SELECT @@default_authentication_plugin; check, which fails with ERROR 1193 (HY000): Unknown system variable 'default_authentication_plugin' because that setting was removed too.

5. Installing a different server than you think (silent)

Everything works, the course examples mostly run, and yet some outputs differ from the lesson. The cause is a version mix-up: brew install mysql or Docker's mysql:latest gave you an innovation release, apt install mysql-server gave you 8.0, or XAMPP gave you MariaDB. Fix: run SELECT VERSION(); on day one and write the answer down. If it is not 9.7.x, either reinstall with the steps above or keep it and expect the differences the 🐬 version notes describe.

🛠️ Project: Installation Health Check

You will install MySQL with the path you chose, then write a small health check, a few queries that describe your server, and save their answers in your journal. When something breaks later in the course, rerunning the health check tells you in a minute whether the server or your SQL is the problem. Allow about 50 minutes, most of it the installation itself.

🛠️ Step 1: Install and start MySQL 9.7 (30 min)

Follow exactly one installation section above: Windows, macOS, Linux or Docker. Finish with the server running and its "start/stop" commands written in your journal.

🛠️ Step 2: Secure root and log in (5 min)

Make sure root has a strong password (see Securing the Root Account), store it in a password manager, and log in with mysql -u root -p.

🛠️ Step 3: Who and what is this server? (5 min)

Run these two queries. The @@ names read server settings; the first query's answers vary by installation, the second's should match exactly.

SELECT VERSION() AS version, @@version_comment AS edition, @@port AS port;

Output (your version and port can differ)

+---------+------------------------------+------+
| version | edition                      | port |
+---------+------------------------------+------+
| 9.7.2   | MySQL Community Server - GPL | 3306 |
+---------+------------------------------+------+
SELECT
    CURRENT_USER()         AS logged_in_as,
    @@character_set_server AS charset,
    @@collation_server     AS collation;

Output

+----------------+---------+--------------------+
| logged_in_as   | charset | collation          |
+----------------+---------+--------------------+
| root@localhost | utf8mb4 | utf8mb4_0900_ai_ci |
+----------------+---------+--------------------+

utf8mb4 is full Unicode (every language, and emoji), MySQL's default since 8.0. If you see latin1, you are on a very old server.

🛠️ Step 4: How does root log in? (5 min)

Account information lives in the mysql.user system table. Look at the root accounts:

SELECT user, host, plugin
FROM mysql.user
WHERE user = 'root'
ORDER BY host;

Output

+------+-----------+-----------------------+
| user | host      | plugin                |
+------+-----------+-----------------------+
| root | localhost | caching_sha2_password |
+------+-----------+-----------------------+

A Docker container shows a second row, root with host % (any host), which is how you reach it through the published port. Ubuntu's own package shows auth_socket until you set a password. Whatever you see, you should not see mysql_native_password.

🛠️ Step 5: Prove the server keeps running (5 min)

Type exit. Stop the server with your platform's stop command, try mysql -u root -p and read the error (2002 or 2003). Start the server again and log back in. Write the version, port, charset, root's plugin and your start/stop commands in your journal: that is your health check.

✅ Project Completion Checklist

  • SELECT VERSION(); returns 9.7.x (or you wrote down why yours differs)
  • root has a strong password stored in a password manager, and you log in with mysql -u root -p
  • The charset is utf8mb4 and root's plugin is caching_sha2_password
  • You stopped and restarted the server and saw the connection error in between
  • Your journal holds the health-check answers and your start/stop commands

🏋️ Hands-on Exercises

🏋️ Exercise 1: Client Version vs. Server Version

Run mysql --version in your terminal, then log in and run SELECT VERSION();. Do the numbers match? Which program does each one describe?

💡 Hint

One command runs before you are connected to anything.

✅ Solution

mysql --version describes the client program on your computer; it works even when no server is running. SELECT VERSION() asks the server. With a normal installation both say 9.7.x. They can differ, for example a Docker 9.7 server reached from an older client installed on your laptop. That usually still works, but it is worth knowing which is which.

🏋️ Exercise 2: Read the Settings Yourself

Write one or two queries that show the server's default SQL mode (@@sql_mode) and the folder it is allowed to read and write files in (@@secure_file_priv). You will meet both again: the SQL mode in Lesson 3.3, the file folder in Lesson 8.1.

💡 Hint

Put both @@ names in one SELECT, separated by a comma, and give each an alias with AS.

✅ Solution 
SELECT @@sql_mode AS sql_mode;
SELECT @@secure_file_priv AS file_folder;

Output (the folder differs by installation)

+-----------------------------------------------------------------------------------------------------------------------+
| sql_mode                                                                                                              |
+-----------------------------------------------------------------------------------------------------------------------+
| ONLY_FULL_GROUP_BY,STRICT_TRANS_TABLES,NO_ZERO_IN_DATE,NO_ZERO_DATE,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION |
+-----------------------------------------------------------------------------------------------------------------------+
+-----------------------+
| file_folder           |
+-----------------------+
| /var/lib/mysql-files/ |
+-----------------------+

Two separate statements keep the very wide SQL mode in its own table; one SELECT with both columns is just as correct. The SQL mode is the same on every MySQL 9.7 that nobody has reconfigured. The file folder is /var/lib/mysql-files/ on Linux packages and Docker; on Windows it is under C:\ProgramData\MySQL\MySQL Server 9.7\Uploads\, and it can be NULL (no file access) or empty (anywhere) elsewhere.

🏋️ Exercise 3: Break It on Purpose

Produce each of these errors once, on purpose, and write down the exact command that caused it: 1045 (access denied) and 2002 or 2003 (cannot connect).

💡 Hint

One needs the server running and a wrong password; the other needs the server stopped (or a wrong port).

✅ Solution
  • 1045: server running, mysql -u root -p, type a wrong password. The server answered and refused you.
  • 2002/2003: stop the server and run mysql -u root -p, or connect to a port where nothing listens (mysql -h 127.0.0.1 -P 3399 -u root -p). Nothing answered at all.

The difference is the most useful debugging fact of this lesson: 1045 means "fix your credentials", 2002/2003 means "fix the server or the address".

🏋️ Exercise 4 (Stretch): A Second Server Side by Side

With Docker, start a MySQL 8.4 LTS container next to your main server without stopping it, connect to it, and confirm with SQL which server you are on.

💡 Hint

Use a different container name, a different volume and a different host port, and connect with -h 127.0.0.1 -P and that port.

✅ Solution 
docker run --name mysql84 -e MYSQL_ROOT_PASSWORD='another-strong-password' \
  -p 3307:3306 -v mysql84-data:/var/lib/mysql -d mysql:8.4
docker exec -it mysql84 mysql -u root -p

Inside, SELECT VERSION(); shows 8.4.x. Port 3307 on your computer leads to this container while 3306 still leads to your 9.7 server. Remove it afterwards with docker rm -f mysql84 and docker volume rm mysql84-data.

❓ Common Questions at This Stage

Should I install MySQL 8.4 instead, because my school or host uses it?

Either works for this course. 8.4 is also an LTS release, and nearly every example runs identically; the version notes mention where 9.7 behaves differently. If your production server is 8.4, matching it on your laptop is a reasonable choice.

Does MySQL slow my computer down when I'm not using it?

An idle server uses some memory (a few hundred MB) and almost no CPU. If that bothers you, turn off automatic start (Windows Services, brew services stop, sudo systemctl disable mysql, or just do not start the container) and start it when you study.

I forgot the root password. Do I have to reinstall?

No. MySQL's manual has a "How to Reset the Root Password" procedure: you restart the server with a special option that skips password checks, set a new password, and restart normally. With Docker on a learning machine, removing the container and its volume and starting fresh is often quicker, since there is no data to lose yet.

Is it safe to keep root without a password since it's only my laptop?

No. Any program on your computer, including a malicious browser extension or package, could connect to an unprotected server. A strong password costs you nothing, and building the habit now matters when you deploy real systems.

Find the server's data directory with SELECT @@datadir; and look at it with your file manager (on Linux you need sudo; in Docker, docker exec mysql97 ls /var/lib/mysql). Then find the server's error log (SELECT @@log_error;, or docker logs mysql97) and read the lines from your last start.
